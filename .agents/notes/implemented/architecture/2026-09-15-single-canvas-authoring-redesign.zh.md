## 当前实现比交接摘要多出的信息

### 1. 正常入口已退役，旧实现尚未完全退出包

[validate.ts](../../../../packages/design-authoring/src/validate.ts) 的 `finishValidation` 已无条件走 YAML 投影验证，但该文件仍有 2200 行，保留 v2 主题、HTML、表格和图表校验函数。不能把全部行数视为可删数量：YAML 解析、公开导出和现行错误处理仍需逐项确认。

import.ts (`06aa8ba:packages/design-authoring/src/import.ts`) 仍有 846 行，`importPptd` 先处理 YAML，但另有完整 `importV2` 分支；[index.ts](../../../../packages/design-authoring/src/index.ts) 仍公开导出它。正常文件 intake 的 v2 校验不通过，不等于旧低层导入代码已经删除。该区别也不能直接推导为产品入口绕过。

richtext.ts (`06aa8ba:packages/design-authoring/src/richtext.ts`) 的 HTML 解析、[semantic-assets.ts](../../../../packages/design-authoring/src/semantic-assets.ts) 的旧元素枚举，以及 [contracts.ts](../../../../packages/design-authoring/src/contracts.ts) 的旧类型联合仍连接这些分支。现行投影的主要实现集中于 426 行的 pptd-v3.ts (`06aa8ba:packages/design-authoring/src/pptd-v3.ts`)，并已通过 kernel replay 验证结构。

建议按当前消费者清理旧分支和旧导出；合法 YAML 仍走既有结构校验和素材检查。保留拒收旧输入的负例与边界，不为消除字样而让 `.pptd` 或旧字段重新成为合法输入。旧文档加载器 [migrate.ts](../../../../packages/design-authoring/src/migrate.ts) 服务已保存 BentoDoc，不能与旧 PPTD 导入一起删除。

### 2. 能力说明存在过时映射

[projection-capabilities.ts](../../../../packages/design-authoring/src/projection-capabilities.ts) 仍写 `projectionVersion: 'v3'`、`id/kind use elementId/elementType`，并以 v2 解析主题/defaults 解释部分行。当前 YAML 实际使用 `id`/`kind`，拒收那些旧构造。这是描述与当前实现的差异，不是重新启用主题继承的理由。

后续应把能力说明改为当前可编辑行为、实际投影路径与验证证据，保持已开放能力范围。冻结矩阵和 vendored 文件按既有规则处理，不能为了文案重写直接修改它们或刷新其哈希。

### 3. “Bento”需要区分上游与迁入适配

[design-bento/README.md](../../../../packages/design-bento/README.md) 明确区分 Bento 子模块和经 ALD 迁入的 contracts/kernel/editor 适配闭包；[source-manifest.json](../../../../packages/design-bento/source-manifest.json) 将 `bentodoc-v4.ts`、kernel 等列入后者。不能把所有 `vendor` 内容笼统称为 Bento 上游原生代码，再用 Bento 的许可证解释整层来源。

因此本提案能降低创作层对旧 DSL 和转换实现的依赖；若目标还包括整个 ALD 适配层的来源独立，需要另立范围，逐文件确认保留依据或替换计划。当前创作层改造不足以证明整个项目已无来源问题。真实保留代码的出处继续保留；只换路径、删 manifest 条目或改写注释不能当作实现已经独立的证据。

### 4. 历史不需要批量改写 YAML

[history.ts](../../../../apps/cli/src/design/history.ts) 读写 Git 中的 `design.json`，包含 canonical 内容及素材；当前 YAML 由 [current-projection.ts](../../../../apps/cli/src/design/current-projection.ts) 从保存内容导出。因此可保留 Git 历史字节，通过现有恢复链生成新版当前投影。旧 Agent 草稿、冻结输入、回执和普通文件仍要保留原样，不能把重建当前投影推广为迁移所有工作文件。

## 推荐改造边界

### 第一阶段审核方案

本节是用户开始实施前的审核对象。第一阶段范围为 A+B、旧 YAML 草稿的一次性转换及真实 Kimi 黄金验收驱动/执行；C 的类型区块不进入本阶段。本方案已于 2026-09-15 获用户批准，运行时实施中。

#### 1. 固定文件合同

工程文件为 `design.yaml` 和现有 `media/`。第一阶段根字段固定为：

| 字段          | 合同                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| `format`      | 必填，字面值 `geon-canvas/1`；仅为创作表示版本，不能混同 BentoDoc schemaVersion      |
| `size`        | 必填，现有 `[width, height]`，保持当前数值范围及坐标单位                             |
| `elements`    | 必填数组，保持现有七类 Bento 元素字段和结构化 text/table/chart                       |
| `background`  | 可选，显式值逐值保留；省略时沿用入口补白色 solid 的现有行为                          |
| `customFonts` | 可选，沿用当前字体登记和本地素材语义；省略与空数组保持区别                           |
| `diagnostics` | 可选，省略时沿用入口的空数组；已有 canonical 值在导出时保留                          |
| `title`       | 可选字符串，保留原有文件元数据接受行为；不新增其在 BentoDoc 中的存储或当前稿回投保证 |

`pages` 字段及独立页面文件不再是新格式依赖。未知根字段或未知 format 具名拒绝；保留旧 PPTD、HTML、主题引用和未展开 defaults 的拒收行为。页面遗留文件保留在旧草稿源目录；不作为新格式资产或额外画布采集。新格式仍只能引用现有受限 `media/` 路径。

```yaml
format: geon-canvas/1
size: [285, 2000]
background: { type: solid, color: '#FFFFFF' }
elements:
  - id: heading
    kind: text
    bounds: [12, 12, 261, 48]
    text:
      fontSize: 20
      paragraphs:
        - runs:
            - text: 'Magsafe Car Mount'
```

示例仅说明语法，不是黄金验收的预制答案或额外提示。保留元素数组顺序和显式 `zIndex`；省略的 `zIndex` 继续按现行入口规则由数组位置补齐。导出 canonical 时不删除已存在的值。`id`、`kind`、`bounds`、`groupId` 和复杂类型内部字段均不改名，不新增主题继承、布局求解或第二份权威文档。

#### 3. 存量和切换

- **当前稿**：保留 canonical 及素材，从其重建新版当前投影；发布失败保留已保存内容并阻止陈旧投影进入新回合。
- **Git 历史**：保持历史字节，加载/恢复后走同一新投影发布链。
- **旧 YAML 草稿**：交付显式调用的一次性转换入口，仅接受旧 Geon 双文件 YAML，冻结其文档/素材，将新格式写到全新目标，保留可选 title。转换前后对比完整 BentoDoc 和引用素材字节，失败不留下可被误认为成功的新稿。原草稿、未完成回合、旧回执和预期版本均不改写；转换不直接提交或自动改变基线。
- **旧 PPTD**：仍拒收，不借迁移恢复 v2/v3 创作入口。
- **升级/回退**：新进程启动时切换，不热换进行中的 Agent；两版不同时写一份工作区。回退从 canonical 重建旧版当前投影，新草稿保留，不能让旧程序误读或覆盖。

普通采集仅接受新格式；旧 YAML 读取能力限制在显式迁移入口，不建立长期双格式创作。文件摘要随格式变化而改变，不能因此自动创造一次 Agent 提交或复用旧的重提交授权。

#### 5. 执行顺序和交付

1. 本方案获批后记录对应 Spec 修订的批准及范围；先接入黄金驱动并执行当前版本基线。
2. 独立清理旧转换逻辑，跑现有行为测试；再实现单文件 codec、一次性旧 YAML 转换及完整往返。
3. 协调切换 CLI、预览/导入、skill 和示例，验证存量及所有失败路径。
4. 运行相关定向测试及 `corepack pnpm check`、`corepack pnpm format`、`corepack pnpm e2e:check`、桌面构建/smoke、`corepack pnpm run docs check`；包边界检查包含在根 check 内，相关改动需保持通过。格式化不夹带无关文件变更。
5. 构建并核验实际新版本，在隔离桌面里执行黄金复刻及保存/编辑/导出检查，交付人审材料；只有技术检查与人工高一致性均通过才标第一阶段完成。

实施交付包含可运行测试入口、用例说明、源代码与构建身份、全部检查结果和已知限制。Kimi 真实运行还需核对实际可用的模型/连接；缺失如实报告，不以模拟通过替代。原冻结 A/B/C 盲测的收口仍属后续独立证据，第一阶段不自动关闭其未达标项。

2026-09-15 后续确认：用户同意先落实旧语义清理和单文件化，类型区块重组以完整往返及 Agent 可操作性为通过条件。因此先采用 A+B、保留现有元素字段；C 仍是有条件的后续选择，不因本次确认而直接切换。用户同时指定下述真实 Kimi Code CLI 黄金复刻验收。此处记录已确认的方向，不把尚未编写完成的 Spec 修订标为 approved，也不把验收定义当作已执行结果。

推荐顺序为：**删除旧转换语义 → 单画布文件 → 有限结构重组 → 完整往返及产品验收**。前两项优先；第三项是追求更明显公开结构差异时的可选成本，必须以同一套完整编辑语义通过验收为条件。无需通过减少元素种类制造差异。

### A. 先完成创作层的语义清理

1. 把现行 YAML 解码、编码、Bento 验证和素材绑定明确分开，继续复用当前 `collectAuthoring` / `intakeAuthoring` / `exportAuthoring` 消费边界。
2. 查清所有消费者后删除 v2 导入、旧 HTML 文本解析、主题展开和 `seriesDefaults` 合并；清理旧联合类型与不再使用的导出。逐项确认 `latex.ts` 等辅助模块是否仍有当前消费者。
3. `contracts.ts` 只暴露当前需要的合同，不继续通过泛化旧 `ValidatedPptd` 表示现行文件；来自 vendored kernel 的必要类型和诊断用薄适配承接。
4. 拒收旧输入采用正向的封闭字段校验及必要入口限制，保留行为负例。旧错误码若存在持久读回消费者，保留读回映射，不整体替换历史诊断。
5. 构建和已交付 skill 内容都验证清理结果；源码删掉函数不等于安装包已不携带它。

该阶段不改变合法 YAML 的语义。具体删除数量、构建依赖和对外低层 API 的影响须经实现时核对，不能按源码行数预先承诺。

### B. 清单与画布合并

保留 `design.yaml` 作为唯一文本入口和现有 `media/` 本地素材路径，将画布尺寸、背景、字体及元素集中到一个 YAML，删除 `pages` 引用及单独页面文件。保留素材目录能复用已有 image MCP 和附件落盘，不增加一份资产 ID 清单。

理由来自当前产品：每个作品只有一个静态画布，不需要为固定的一页保留两级导航。合并减少尺寸/元素跨文本文件不一致的组合，也减少 Agent 找文件的步骤。素材仍是独立文件，**单个 YAML 不构成整份作品的原子事务**；冻结字节、检查素材、当前稿发布与最终版本检查照常保留。

保守版本仅合并外壳，元素继续采用当前 Bento 字段；这条路线的转换成本最低。不能承诺仅此即可使 C 判定为“否”。

### C. 如需更深的公开结构变化，采用可逆类型分区

以下是待验证的候选语法，当前程序不接受。它只描述已有状态，不加入新布局、样式继承或计算语言：

```yaml
format: geon-canvas/1
canvas:
  width: 1080
  height: 1440
  background: { type: solid, color: '#F4F0E8' }
layers:
  - id: headline
    box: { x: 72, y: 96, width: 936, height: 160 }
    text:
      fontFamily: Inter
      fontSize: 64
      paragraphs:
        - runs:
            - text: '城市的另一面'
  - id: cover
    box: { x: 72, y: 320, width: 936, height: 900 }
    image:
      src: media/cover.png
      fit: cover
```

语法调整均有明确职责：

| 投影表达                                      | 转入现有 BentoDoc     | 可逆性与用途                                 |
| --------------------------------------------- | --------------------- | -------------------------------------------- |
| `canvas.width/height`                         | `canvas.width/height` | 单画布直接描述，不引用页清单                 |
| `canvas.background`                           | 文档 `background`     | 仅改变容器                                   |
| 顶层可选 `fonts`、`diagnostics`               | 文档同名字段          | 保留缺省、空数组及已有值                     |
| `layers` 有序数组                             | `elements` 有序数组   | 顺序原样保留，不引入另一份 order 数组        |
| `id`                                          | `id`                  | 选区、元素引用继续稳定                       |
| `box.x/y/width/height`                        | `bounds[0..3]`        | 具名坐标方便局部编辑，不换单位、不做浮点运算 |
| 恰好一个类型区块                              | `kind` 与对应字段     | 避免标签与内容不一致；零个或多个区块报错     |
| `rotation/flip/groupId/zIndex/opacity/shadow` | 同名公共字段          | 逐值保留，不重排、不建嵌套分组               |

七个类型区块映射须写成完整的小型合同：`text` 直接容纳 canonical `text`；`shape`、`line`、`image`、`icon` 容纳各自全部种类字段；`table` / `chart` 采用 `{ content: <原 table/chart 对象>, fill?, border? }`，明确区分元素外框与内容内部样式，保留现有顶层 `fill` 的历史可投影状态。种类字段如 `shapeName`、`cropShape`、图表通道、文本 run 样式保留既有含义，不建立无当前用途的同义词词典。

不同时接受 `kind` 与类型区块，或 `bounds` 与 `box`；不给同一属性两种有效写法。所有映射只能搬字段或重组对象，不能猜类型、合并 run、展开默认样式、改坐标单位、重编号或丢弃未知字段。`format` 只标识文件表示版本，不作为 BentoDoc schemaVersion，也不在 canonical 中存第二份格式状态。

若这层结构重组明显增加 Agent 错误或维护成本，应选择 B 的原生字段版本。这里的取舍是真实成本，不能用盲测结果代替可用性判断。

## 保功能的验收定义

对当前首期已开放且可投影的文档 D、引用素材 A，要求：

```text
decode(encode(D, A)).document 与 D 深度相等
decode(encode(D, A)).assets 与 A 中被引用的素材字节相等
```

对象键顺序和 YAML 排版不作为文档语义；数组顺序、可选值是否存在、空数组、空文本 run、显式 zIndex、稳定 ID 必须保留。任意 Agent 输入不要求字节级回写相同；省略 zIndex/背景等现行入口默认行为必须单独定案并保持可预测，不能把它们偷渡成对 canonical 的归一化。

1. **结构往返**：复用 [roundtrip.test.ts](../../../../packages/design-authoring/tests/roundtrip.test.ts) 的完整字段及七类元素、13 类 chart 用例；加入新表示正反映射与歧义拒绝。不要只测示例中 text/image，也不要把新生成字段表当作独立语义证据。
2. **原生编辑**：从新表示导入后实际编辑文字/run、图形、分组、裁切、表格合并、图表数据及样式，再保存、重开并继续改；保留撤销/重做的既有边界。
3. **渲染等价**：同一 D 经新旧投影路径返回后，用同一固定字体/资源的 Bento 渲染器对比；预览与 PNG/JPEG 导出一致。像素比较辅助定位，人工仍判断视觉质量。
4. **Agent 可操作性**：同一批合成任务覆盖从零创建、只改某元素、换图、改表格/图表；记录首次合法率、返工、文本体量及成功提交。最终对产品宣称支持的各 Agent 接入完成相应端到端验证，不由单个模型通过外推全部。
5. **保存安全**：素材缺失/损坏、未知嵌套字段、重复 ID、非法图表、symlink/hardlink/逃逸、半写文件、过期当前稿版本、取消和失败均维持现有拒绝/保稿行为。相邻有效观测不当作 Agent 已完成。
6. **来源和交付物**：真实保留来源、许可证和历史；核对运行时代码、构建包及物化 skill 的依赖闭包。盲测单独按冻结仪器记录，不能因功能通过自动填写 C 为“否”。

## 不选择的路线及原因

| 路线                                 | 取舍                                                         |
| ------------------------------------ | ------------------------------------------------------------ |
| 全面同义词改名或换 YAML 后缀         | 不能删除旧转换依赖；增加映射点，没有充分功能收益             |
| 把当前稿 JSON 直接开放给 Agent       | 将保存容器、素材与版本责任暴露给创作，违反已确认入口边界     |
| 改成脚本或命令日志作为主要创作源     | 扩大执行、回放和人工编辑回投问题；当前文件表示即可满足需求   |
| 全量替换 renderer 或重写 vendor 模型 | 将来源问题扩大到编辑、布局和导出的重建；超出本提案保功能边界 |
| 把 table/chart/text 全转为路径或图片 | 不能满足当前原生编辑能力和无损往返要求                       |
| 新增主题继承、自动布局、组件实例     | 无当前需求依据，容易再次形成需要展开和反解的第二套语义       |
