# Embedded Pi 1.3.0 upgrade

Status: implemented
Date: 2026-10-17
Translation: pending

## Abstract

Molly's embedded engine moves from Pi 1.0.4 to 1.3.0 for tool-call robustness, prompt-cache and resume fixes, and MCP OAuth hardening; the owner approved it in [#158](https://github.com/LeonEthan/molly-design/issues/158). Pi 1.3.0 moves the Kimi Code preset from Anthropic Messages at `https://api.kimi.com/coding` to OpenAI Chat Completions at `https://api.kimi.com/coding/v1`, so the default endpoint, validator, key check and settings copy change with it, and saved connections on the old default migrate silently instead of showing an error. Because the bump changes the toolset, every resumed session rebuilds its saved host prompt once under the [#157 fingerprint policy](../bug-fix/2026-10-17-host-prompt-toolset-fingerprint.md). That one-time rebuild also covers two hardening changes: well-formed future snapshot versions now rebuild instead of failing, and hash inputs now sort by plain code-unit order. Live provider, resume and Kimi sign-in evidence, plus the PM's hands-on copy acceptance, are still outstanding.

## Decisions

**Kimi Code endpoint.** The [PM decision](https://github.com/LeonEthan/molly-design/issues/158#issuecomment-6244879360) sets `https://api.kimi.com/coding/v1` as the preset default shown in settings. A saved Kimi Code connection with base URL `https://api.kimi.com/coding` or `https://api.kimi.com/coding/` is rewritten to `/coding/v1` on load and still counts as the default endpoint. Users who upgrade must never see the endpoint error for an address Molly told them to use. On `api.kimi.com` the validator accepts only `/coding/v1`, with or without a trailing slash. The protocol-specific `kimi_code_requires_anthropic_base` becomes `kimi_code_requires_coding_v1_base`; the settings key `settings.models.kimiCodeEndpointRequired` and the other copy keys stay. Accepting `/coding` as a permanent alias was declined: it would keep an address the SDK no longer serves through this protocol in saved records.

**User-triggered runs only.** Pi 1.2.0 fires `before_agent_start` for idle extension `sendMessage(..., { triggerTurn: true })` runs too, as a `messageType` union. Molly dispatches only user prompts, so the host keeps returning its frozen snapshot for dispatched user runs and retires the worker for any other or undispatched run, as before.

**Snapshot forward compatibility.** Following the [CTO review of #159](https://github.com/LeonEthan/molly-design/pull/159#issuecomment-6245054413), a `molly_host_system_prompt` entry with an integer `version` above 2 and a string `systemPrompt` is treated as an unknown fingerprint and rebuilds once, like v1. Malformed entries still fail with `pi_acp_host_invalid_system_prompt_snapshot`. This prevents a future format, followed by a downgrade to this build, from bricking sessions in a released build. The alternative was to require every future format to use a new `customType`. It was declined because it relies on future discipline rather than reader tolerance.

**Locale-independent fingerprint.** `toolsetHash` sorts tools by plain code-unit comparison instead of `localeCompare`, whose order follows the ICU default locale. Plugin paths already used the default code-unit `sort()`. The hash changes once, and this upgrade already rebuilds every resumed session.

**Known non-refresh.** A Pi upgrade that changes only base-prompt wording, with an unchanged toolset, keeps the saved prompt; existing sessions are not refreshed. This follows the #155 session-stable prompt decision. Only a toolset or plugin-set change, a v1 entry or a future version triggers a rebuild.

## Reuse ladder

- Endpoint migration and validation reuse the shared `PROVIDER_PRESET_DEFAULT_BASE_URLS`, `isProviderPresetDefaultEndpoint` and `getModelConnectionConfigurationIssue` contracts, which settings, the key check and the harness already consume. The shared `ModelConnectionSchema` normalizes only the two legacy Kimi URLs after saved-record validation; vault reads, IPC snapshots and runtime schemas all consume it. `SaveModelConnectionSchema` remains separate, so typing the old URL still fails. Identity, revision, credential references and tokens are retained; the encrypted file is updated by the next normal mutation rather than a read-side write. No new settings state or migration store is added.
- Settings reuse the existing hint, endpoint-error and OAuth-hint keys with new copy, plus the existing issue-key map, renamed. No new component.
- Snapshot handling extends the existing #157 schema and selection module. No new entry type or sidecar.
- Version derivation reuses `PI_ENGINE_VERSION`, so the next bump only edits the catalog and that constant.

## Release notes

The build that first ships #159 and this upgrade must repeat these points in its GitHub Release notes, which are generated per tag rather than kept in a tracked changelog:

- Embedded Pi engine 1.0.4 → 1.3.0. Each resumed conversation rebuilds its saved system prompt once, so its first turn misses the provider prompt cache; later turns reuse the cache.
- Kimi Code now uses the OpenAI-compatible API at `https://api.kimi.com/coding/v1`. Connections saved with the old default address migrate automatically.
- A future revert of #159 must keep the v2 snapshot reader and v2 read logic; otherwise sessions holding v2 entries fail setup.
- A Pi upgrade that changes only base-prompt wording, with an unchanged toolset, does not refresh existing sessions.

## Evidence and limits

Synthetic tests on the branch cover the copy, the error-code mapping, a saved `/coding/v1` connection rendering as the default, a typed `/coding` raising the new error, `/coding/v1` and `/coding/v1/` clearing it, the OAuth hint, and future-version and malformed-entry selection. Settings tests also load raw legacy IPC snapshots and open their edit forms without an endpoint error. Synthetic encrypted-vault tests cover both old URL forms for API-key and OAuth records through snapshot, credential checks and run grants; both check paths request the new OpenAI models URL with Bearer authentication. Real-SDK model-default tests verify that migrated saved connections use the SDK endpoint without a provider override. The OAuth sign-in test pins the newly saved default. Engine fixtures derive their current version from `PI_ENGINE_VERSION`; the genuine 1.0.4-written fixture remains historical.

Executed validation for the completed branch: `MOLLY_PLATFORM=local pnpm check` passed all workspace typechecks, lint, tests, i18n and import/platform/public-boundary guards. This includes 263 harness tests, 2,971 CLI tests, 3,178 component tests and 404 Electron tests; the existing three CLI and three Loro-streams skips remain. Focused validation passed 12 shared boundary tests, 13 model-default tests, 87 vault/OAuth tests, 52 settings/capabilities tests and 99 CLI fixture tests. The three PM strings in each language were compared verbatim against the final issue comment; no unrelated locale key changed. The sealed embedded build, verifier and synthetic packaged Codemode smoke passed on Pi 1.3.0. Root formatting completed; its sole unrelated browser-account formatting change was discarded. These checks establish deterministic behavior and resource loading, not live provider or visual acceptance.

Not yet established in this note: the live Mac mini checks listed in #158 (`deepseek-flash` prompt-hash and cache-hit numbers, resume of 1.0.4- and 1.3.0-created sessions, a resume twice with MCP servers enabled, codemode/MCP/image on Flash, Kimi Code OAuth if an account is available), and the PM's hands-on acceptance of the Kimi copy in both languages. Record their results in the PR, not here, until they exist.
