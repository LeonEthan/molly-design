# 还原选定方案时提取优先于重绘

Status: implemented
Translation: current

[English](2026-10-10-extraction-over-recreation.md)

## 摘要

用户选定方案的可编辑版曾可能明显偏离选定图片——肖像被重画、分割线移位、纸
纹改变——因为还原指引只要求图像模型"匹配方案的外观"并"补全被遮挡部分"，这
可被理解为允许重新想象元素，且从未禁止从零生成图层。当前前沿图像编辑模型
的保真能力已足以让"精确提取"成为应有标准，因此 graphic-design Skill 现在要
求每个栅格图层都来自选定方案自身的像素（经 `edit`），禁止对方案已有的元素
使用 `generate`，要求模型保持未触碰像素不变，按元素在画布上的像素尺寸请求
图层，并在组装前新增逐层对比。本次仅改文字；真实模型上的保真度仍待设计评
测运行由人判断。

## 问题与依据

- 一次手绘肖像海报的还原运行返回了明显重绘的肖像、移位的分割线、变大的印
  章圆点和不同的书脊排，尽管阶段 4 已写明"还原选定方案，不重新诠释"。
- `references/layered-workflow.md` 的分离提示词只要求"匹配方案外观"并给出
  "包括被遮挡部分的完整元素"；`references/replication.md` 写的是"从参考图重
  新生成每个物体"。两处都在授权重绘而非提取。
- 对 `generate` 的禁令只存在于艺术字一节（"仅对没有方案可匹配的新艺术字使
  用 `generate`"），其他图层没有；且图层保真只在组装后检查，那里的修复手
  段仍是生成式的，只能收敛到"差不多"。
- 只有艺术字有最低像素要求；主体小尺寸重绘再放大必然发软。
- 本记录接续[由用户选择设计方案](../feature/2026-10-09-user-chosen-designs.zh.md)：
  那次修正的是"重建时重新设计"，本次修正的是其后观察到的"还原中重绘元素"。

## 决定

仅改措辞，在已获批 Spec 意图之内（Spec 第 4 步本就要求拆解选定方案）：

1. `layered-workflow.md` 的"Reproducing the chosen design"以"提取，永不重
   绘"开篇：栅格图层经 `edit` 来自选定方案自身像素且方案图为第一张输入；
   方案已有的元素禁止 `generate`；被模型重新想象的图层是失败层，需重新提
   取或如实报告。
2. 背景底板与分离提示词要求其余像素全部保持不变（光线、颜色、纹理、颗粒
   感），连接支持时对被移除区域使用 `mask`；物体按原样提取，只补全确实被
   遮挡的部分，且不少于元素在画布上占据的像素。
3. 新增逐层检查：组装前从选定方案裁出元素区域，与提取图层 `compare` 对比。
4. `SKILL.md` 阶段 4 写入同一原则；可编辑版的回复规则现在要求逐层点名可
   见偏离的栅格图层。
5. `replication.md` 以相同的提取措辞替换"重新生成每个物体"。

明确不做：不新增像素级抠图/分割脚本（生成式提取现已足够，脚本会增加依赖
与维护面）；不改 Spec——其第 4 步描述的本来就是拆解选定方案。

## 验证与局限

- 纯文档修改；`pnpm run docs check` 通过，改动文件通过 Prettier。
- 尚无设计评测运行验证新措辞；前沿连接（如 GPT Image、Nano Banana、
  Seedream 级编辑器）能否在插画与文字版式上做到近无损提取，仍须按工作流
  Spec 的验收策略在真实运行中由人判断。
