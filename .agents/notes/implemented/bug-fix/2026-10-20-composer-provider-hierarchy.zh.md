# 作曲器选择器是服务商，然后是模型，然后是推理

Status: implemented
Translation: current
Issue: [#192](https://github.com/LeonEthan/molly-design/issues/192)

[English](2026-10-20-composer-provider-hierarchy.md)

## 摘要

作曲器的模型选择器原先以 Agent 行开头，而那一行总是 Molly，首页作曲器还把同一信息做成 Agent 芯片。首页和画布内的选择器现在依次是服务商、模型和推理，每级仍是一个子菜单。模型列表只含所选服务商的模型，推理列表只含该模型支持的档位。更换服务商或模型时，仍然有效的子项会保留；否则选该服务商的第一个模型，推理优先 `high`，没有 `high` 时用第一个非 `off` 档位。只有没有配置连接时推理才是 `off`，此时服务商行打开设置。Agent 芯片被删除，不再替换为服务商芯片；图像模型芯片保持不变。选择写入既有的代理默认缓存和按会话保存的记录，重启后仍然在。画布上，经模型配置选择器选出的模型也写入同一记录；只要记录仍对应当前回合，它就优先于运行时基线，直到回合修订号变化。

## 决策

服务商来自选择器已经展示的模型目录（`molly-model:<connection>/<model>`，或 ACP 分组）。连接列表 API 和连接类型保持不动，以便与 #181/#190 变基。

没有「全部服务商」范围，也没有嵌套弹出层。一次服务商选择如果离开当前模型，就改选该服务商的第一个模型，再重新校验推理。没有连接 id 的扁平目录仍是一份未标注的列表。发送继续使用已解析的模型 id，其中已经包含连接。

## 验证

组件测试覆盖服务商过滤、行顺序、模型没有 `high` 的服务商、空连接时的设置入口、已删除的 Agent 芯片，以及不再出现 Agent 行。单元测试覆盖默认值、子项重新校验、按修订号保存的选择、已保存的模型和推理优先于运行时基线，以及模型选择器的修改会生成缓存补丁。Linux 桌面验收记录在拉取请求中。
