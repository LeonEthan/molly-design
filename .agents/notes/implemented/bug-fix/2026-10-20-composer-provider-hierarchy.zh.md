# 作曲器选择器是服务商，然后是模型，然后是推理

Status: implemented
Translation: current
Issue: [#192](https://github.com/LeonEthan/molly-design/issues/192)

[English](2026-10-20-composer-provider-hierarchy.md)

## 摘要

作曲器的模型选择器原先以 Agent 行开头，而那一行总是 Molly，首页作曲器还把同一信息做成 Agent 芯片。首页和画布内的选择器现在依次是服务商、模型和推理，每级仍是一个子菜单。模型列表只含所选服务商的模型，推理列表只含该模型支持的档位。更换服务商或模型时，仍然有效的子项会保留；否则选该服务商的第一个模型，推理优先 `high`，没有 `high` 时用第一个非 `off` 档位。没有配置连接时推理是 `off`，此时服务商行打开设置。已配置的模型如果只发布 `off`，推理行显示 Off，发送的也是 `off`。没有连接 id 也没有分组的模型单独成一个服务商，排在连接服务商之后。`session.cycleProvider` 在这些服务商之间循环。Agent 芯片被删除，不再替换为服务商芯片；图像模型芯片保持不变。选择写入既有的代理默认缓存和按会话保存的记录，重启后仍然在。画布上，经模型配置选择器选出的模型也写入同一记录；只要记录仍对应当前回合，它就优先于运行时基线，直到回合修订号变化。

## 决策

服务商来自选择器已经展示的模型目录（`molly-model:<connection>/<model>`，或 ACP 分组）。连接列表 API 和连接类型保持不动，以便与 #181/#190 变基。

没有「全部服务商」范围，也没有嵌套弹出层。一次服务商选择如果离开当前模型，就改选该服务商的第一个模型，再重新校验推理。没有连接 id 的扁平目录仍是一份未标注的列表。发送继续使用已解析的模型 id，其中已经包含连接。

## 验证

组件测试覆盖服务商过滤、行顺序、模型没有 `high` 的服务商、空连接时的设置入口、已删除的 Agent 芯片，以及不再出现 Agent 行。单元测试覆盖默认值、子项重新校验、按修订号保存的选择、已保存的模型和推理优先于运行时基线、模型选择器的修改会生成缓存补丁，只发布 `off` 的模型显示 Off、未分组模型不并入第一个服务商，以及服务商循环命令。Linux 桌面验收记录在拉取请求中。

## 2026-10-21 后续修复：切换服务商时的共享推理档位

PR: [#227](https://github.com/LeonEthan/molly-design/pull/227)

[#212](https://github.com/LeonEthan/molly-design/issues/212) 修复子项重新校验中的遗漏：分组的 registry/custom 目录切换服务商后，若目标模型缺少专属映射，原有共享推理档位列表会被丢弃。现在目标映射缺失时，层级解析使用调用方传入的 fallback；显式目标映射仍优先，空映射仍表示显示并发送 `off`。不再需要的原模型参数一并删除。

菜单和服务商循环命令已共用该 resolver，selector 规范化也已在模型缺少映射时保留共享选项。复用这些路径即可修复，无需在调用方分别处理或新增状态。这恢复既有的有效子项保留保证，不改变直接选择模型的行为，也不涉及 #213 的 catalog 默认模型范围。回归测试先复现失败，再在修复后通过；覆盖未提供映射表、缺失或部分映射、显式空及非空目标映射、循环选择和实际提交配置。相关层级、配置选择及选择器组件测试共 44 项通过。PR 发布前，全量 `pnpm check`、`pnpm format` 与 `pnpm run docs check` 通过。本次未运行原生桌面或真实模型验收。

## 2026-10-21 后续修复：扁平目录默认模型的提交

PR: [#228](https://github.com/LeonEthan/molly-design/pull/228)

[#213](https://github.com/LeonEthan/molly-design/issues/213) 暴露了未分组 registry/custom 模型配置选择器的显示与提交不一致：界面显示第一个可用模型，但提交会丢弃空值或无效值，或保留未选择占位值。层级解析器已经能为扁平目录推导默认模型，默认模型回填却仍嵌套在 connections 分支内。

现有回填逻辑移到 connections 分支之后，复用原有保护条件与层级解析出的模型。connections 模式的模型及推理规范化仍留在原分支。有效模型选择保持原样；完整运行时快照省略模型字段时，除非用户编辑该字段，否则继续保持省略。层级解析器已经提供界面默认值，提交过滤器仅校验候选值，因此适配回填即可修复，无需新增状态、在调用方分别设置默认值或改变过滤器职责。

八个确定性提交用例覆盖缺失、空值、占位值和无效偏好、无效运行时值、有效的第二个模型、运行时省略模型，以及覆盖该省略的用户编辑。修复前五项失败；修复后，配置选择、层级解析及选择器组件相关测试共 52 项通过。沙箱内全量检查因本地 socket 测试遇到 `listen EPERM` 而停滞，退出沙箱重跑的 `pnpm check` 通过。修改文件的格式检查及 `pnpm run docs check` 通过，保留已有文档大小警告。本次未运行原生桌面或真实模型验收。

## 2026-10-23 后续：图像模型行

所有者于 2026-10-23 审阅 Preview 版本界面后决定：首页输入框底栏因图像模型徽章、尺寸芯片与模型芯片放不下且允许换行而折成两行，该徽章并非控件且使用第三种芯片样式。现在底栏为一行不换行、样式统一的芯片（先尺寸后模型）。已配置的图像模型成为两个输入框模型菜单的最后一行，位于推理之后；选择它会打开设置中的 AI 模型。图像模型仍在设置中选择，行为不变；每次点击仍显示服务商、模型与推理。
