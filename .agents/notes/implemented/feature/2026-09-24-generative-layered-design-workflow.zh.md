## 问题与目标

负责人于 2026-09-24 定义核心流程：意图理解、灵感搜索、创意草稿与 Agent 择优、由图片模型拆解图层、YAML 重组、文字处理、整体审视、与用户素材和意图的一致性检查，以及最终打磨。目标是先跑通端到端流程，再优化回合长度、Token 和成本。

## 初始决定（负责人，2026-09-24–25）

- **规则范围。** 根 [AGENTS.md](../../../../AGENTS.md) 约束仓库开发，不禁止产品 Agent 的 Skill 推荐创作流程或重复调用图片接口。应用本身仍不强制任何创作步骤。
- **用 Skill，而非系统提示词或编排。** 一个入口 Skill（`graphic-design`）加若干专题参考；`imagegen` 仍按能力下发。修改每回合指针，要求 Agent 在设计前读取 Skill。不增加阶段控制器、第二调度器或系统提示词改动。
- **Agent 自主判断。** Skill 讲方法、收益、局限和示例，开放取舍交给 Agent。文字采用原生文本、位图或矢量形状由 Agent 决定。草稿由 Agent 择优；日后可增加 "auto" 选项区分 Agent 与用户选择。
- **生成而非裁剪图层。** 每个元素完整重新生成，包括被遮挡部分，因为裁剪会留下缺口，妨碍重新分层和手动编辑。参考图复刻采用同样方式，以参考图代替草稿探索。判断保真度时区分交付素材与设计参考；分层粒度按独立编辑价值决定。
- **模型。** 核心交付是一套可用的 Skill 方案。本轮以 OpenAI Image 2.5 为目标；Qwen Image 2.1 与 Seedream 5.0 Pro 后续接入（[#16](https://github.com/LeonEthan/molly-design/issues/16)）。不限制连接设置，撤回早先的三模型白名单设想。
- **灵感搜索**通过现有内置浏览器使用 Pinterest。
- 审视和校正暂**不限调用次数**。
- **原生工具错误。** 删除 harness 在已发出图片调用失败或 MCP 交付结果未知时终止运行的处理，两者作为工具错误返回 Agent。崩溃/重启不重放保护属于会话恢复，予以保留。
- **自动审批模式。** 代码能力是核心设计能力，因此按实际效果而非命令形式判断风险。shell 命令在接入 Molly 自有 bash 工具的 `@anthropic-ai/sandbox-runtime` 中免提示运行；越界请求（未知域名、请求离开沙箱）由 `pi-auto-approval` 分类器判断，拒绝、失败或超时时回退为提示用户。网络仅限预先放行的开发与设计域名。
- **验收。** 一次端到端可用性实验：通过 Molly 内置 Agent 从普通需求出发，得到保存、编辑、重开并导出的作品。早期"黄金复刻"实验属于上一阶段，不作为本任务验收。2026-09-25 曾决定复用分段证据而不再生成新作品，现被该验收取代。
- **单一 harness。** 新的执行使用内置 Pi harness（[Spec](../../../../specs/molly-embedded-pi-harness.zh.md)）。

## 证据

实验产物保存在仓库之外，不记录凭据或捕获的对话。调用次数：2026-09-24 共 11 次图片接口调用（8 次经第三方中转，3 次经本地反向代理），2026-09-25 1 次，均使用 `gpt-image-2.5-sunburst`；另有一次 Codex CLI 参考运行。

### 通过 Image API 获取透明度

| 接口 / 请求体                 | 透明请求方式                                  | 结果                                                    |
| ----------------------------- | --------------------------------------------- | ------------------------------------------------------- |
| generate，JSON                | 仅提示词                                      | RGBA 抠图；实心像素 alpha 为 253                        |
| edit，multipart               | 仅提示词                                      | 一次 RGBA；一次 RGB 且画出了棋盘格                      |
| edit，multipart               | `background=transparent`、`output_format=png` | 两个代理均为 RGB；其中一次报告 `"background": "opaque"` |
| generate，JSON                | 仅参数                                        | RGBA；报告 `"background": "transparent"`                |
| edit，JSON 携带 data URL 图片 | 同样参数                                      | 两次均为 RGBA；报告 `"background": "transparent"`       |

OpenAI 的 [图片编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)与[图片生成](https://developers.openai.com/api/reference/resources/images/methods/generate)接口文档说明 2.5 模型在 `png`/`webp` 输出时支持透明背景，且没有单独的去背景接口。被测代理丢失了 multipart 字段；OpenAI 官方端点是否如此未测试。JSON 编辑可避开此问题。另有三次纯绿色色键编辑在本地成功抠图（柔和蒸汽得以保留，边缘有一像素色边）；由于原生 alpha 可用，该后备方案不随产品提供。

生成的图层会偏离草稿：一只杯子返回时放大约 20% 并发生位移；Codex 参考运行（对同一海报做 8 次内置 `image_gen` 编辑，7 个透明图层均为原生 alpha）不得不重新摆放每个图层，咖啡豆大小约为原来两倍。在提示词中写明坐标并不能保持布局。

### 单独评估 `@erichll/pi-sandbox` 0.21.1

这个带 scope 的包与上表未带 scope 的 `pi-sandbox` 是不同项目；此前的否决不适用于它。发布版[包元数据](https://github.com/erichll/pi-packages/blob/f211b1233e4bc8e2109e8c105643110bc5e3f32f/packages/pi-sandbox/package.json)声明 Apache-2.0、Node `>=22.19.0`、Pi `^0.87.1`，并依赖 `@anthropic-ai/sandbox-runtime ^0.0.77` 与 `@erichll/pi-auto-review ^0.21.0`。Molly 当前锁定 Pi 0.85.1。

公开的 [`./runner`](https://github.com/erichll/pi-packages/blob/f211b1233e4bc8e2109e8c105643110bc5e3f32f/packages/pi-sandbox/src/runner.ts)可独立于完整扩展评估：调用方提供文件策略、环境、取消、输出与网络审批回调，runner 为每条命令管理 broker 进程和私有临时目录，不注册完整扩展的工具、UI 或自动审批 broker。复用仍需验证 SDK 兼容性与打包后的 broker 资源，同时保留 Molly 的 run/epoch 授权和日志边界。其[文件策略](https://github.com/erichll/pi-packages/blob/f211b1233e4bc8e2109e8c105643110bc5e3f32f/packages/pi-sandbox/README.md#security-model)仍是静态的，仅换包不能证明原生 macOS 临时目录或本地附件响应正常。

上游[变更记录](https://github.com/erichll/pi-packages/blob/f211b1233e4bc8e2109e8c105643110bc5e3f32f/packages/pi-sandbox/CHANGELOG.md)包含近期发布与加载修复：0.20.1 补齐运行时依赖，0.21.1 修复 Pi TUI alias。这说明维护活跃，不代表 Molly 集成已验收。本轮继续使用已有沙箱库，未采用这个 scoped 包；单独复用 runner 仍是可评估的选项。

## 考虑过的替代方案

- 每个阶段一个 Skill，或一个超大 SKILL.md：指针只指向一个 Skill，各阶段共享状态，大文件会在小改动时加载无关指引。
- 裁剪加干净底板的分层方式：被遮挡元素仍不完整。
- 以色键作为主要透明方案：本地可行，但依赖键色选择，且损失柔和阴影的保真度；经 JSON 请求原生 alpha 可用。
- 保留 multipart 编辑、仅增加字段：被测代理会丢弃这些字段。
- 把图层重新采样回全画布：YAML 边界即可摆放裁剪后的图层，无需重新编码。
- 图片调用失败时停止运行：负责人否决，改为沿用 Pi 原生工具错误。

## 风险与限制

- 回合长、读图多；不限调用次数，每次调用都可能计费。工具错误沿用原生行为后，结果未知的调用可能被重复发起并重复计费。
- 图层是重新绘制而非复制；被遮挡内容是推测生成的；摆放依赖 Agent 判断。
- GPT Image 输出尺寸须为 16 的倍数、长宽比不超过 3:1 且不少于 655,360 像素；极端画布需另行处理。
- 生成的实心像素 alpha 为 253–254，叠放时略微透明。
- 沙箱的放行域名和可写缓存需要调优；分类器可能受到 Agent 读取的不可信内容影响。
- Agent 的草稿择优和审视仅供参考；质量由人判断。

在真实 macOS 沙箱上的手动检查（非仓库测试）显示：

- 工作区内读写正常；
- 写入主目录和读取 `~/.ssh` 被拦截；
- 沙箱临时目录可写；
- npm 源可访问；
- `example.com` 进入审查回调，拒绝后保持拦截；
- 位于被拒私有数据目录内的工作区仍可读，同级文件被拦截。

首次检查发现 `sandbox-runtime` 用 `CLAUDE_CODE_TMPDIR` 设置沙箱内 `TMPDIR`，现已指向每个 worker 的临时目录。

Spec 范围内的实现选择：

- **模式传递。** 模式作为 ACP 模式及 Molly 的 `mode` 配置项传递，由运行配置应用器校验，会话写入运行快照，worker 配置仍按会话固定。
- **范围。** 能力按 Agent 配置发布，因此所有 Molly 会话都可选自动审批，非设计会话只是没有设计工具。
- **越界参数。** bash 新增可选的 `outside_sandbox` 参数，用于请求越界；其他模式忽略它。
- **路径形式。** 以 `~` 或 `@` 开头的文件工具路径交由审查，而不由 Molly 自行解析。
- **Linux。** Linux 需要 `bwrap`、`socat` 和 `rg`；缺失或在其他平台上时，shell 保持提示。
- **网络。** 网络决定在本次运行内复用，网络提示显示为独立的工具调用卡片。

实施中发现：

- 内置系统提示词原写有"Ask for approval before tool execution"，可能使 Agent 在自动审批下仍在对话中请求批准。负责人于 2026-09-25 同意在第 1 项运行前改为"The host handles tool approval; do not ask for it in chat."，系统提示词其余内容不变。
- 工作区外的包管理缓存（`~/.npm`、pnpm store）不可写，安装可能需要越界审批。

| 7. 审视与调整     | 通过 Bento 渲染当前版本，并实际读取返回图片；检查构图、遮挡、边缘和可读性。视觉修改后再次渲染；外部近似合成仅作辅助证据。                                            |
| 8. 检查一致性     | 核对当前结果与用户文案、素材、参考约束和意图；修正时回到受影响步骤，再取得当前版本的原生预览。                                                                       |

不增加调研台账、阶段状态、证明存储或逐阶段用户审批。现有工具结果与简短的设计依据说明即可使执行行为可检查；这不保证视觉质量。

### 验证与运行时配套前提

更强的文案无法修复被隐藏的运行时错误。现有创作检查、预览和最终收集应复用素材准入检查；对内置素材大小、素材格式、字体加载和渲染失败提供安全分类。已知大小错误应包含经过校验的相对素材路径及实际/允许大小，不透传任意外部错误文本。同样输入再调用一次不算修复。补齐完整字体注册示例，避免 Agent 为学习创作格式而搜索随包实现。

隔离可行性实验将两个完整 TTF 压缩为 WOFF：20,752,628 → 13,242,276 字节，20,856,816 → 13,678,720 字节。两者均保留全部 43,033 个字形、字形顺序、字符映射及横纵度量，并在 Electron 39.5.1 中加载成功、没有字体诊断。这支持在不提高上限或删减字形的前提下显式恢复，但不是完整 Bento 渲染验证。没有修改作品。不增加静默字体转换、自动替换或新的强制 Python 依赖。

区分三个声明：创作文件与素材检查已就绪；当前版本已经原生渲染并读图；应用已保存作品且用户已完成编辑/重开/导出验证。Agent 在运行中可确认前两项。最终收集发生在模型结束之后，因此 Skill 不能要求等待本轮保存回执才结束，也不能预先宣称提交成功。正常回合即使如实说明限制，仍可能按现有结构/素材/版本规则被收集；声明视觉检查未完成本身不会阻止保存。不能为解决这一点增加应用创作门禁或重启已结束回合。

### 实施与验证顺序

1. 修复共享素材检查与安全诊断，通过显式、保留原字体内容的恢复方式验证现有失败草稿。保留原稿与原始字体；本次诊断不需要新的图片调用。
2. 按上述结构重写主 Skill 并调整参考分工，随实现同步受影响的包规则与物化检查。整体暂存完整材料，避免已安装副本保留冲突的调研或顺序文案。
3. 使用确定性素材验证超限反馈、字体/渲染错误分类与随包 Skill 内容。它们证明能力表面，不证明真实 Agent 一定遵循文案；不为让行为测试通过而加入运行时创作强制。
4. 真实验收覆盖开放需求、指定模板且无需新灵感、已有参考但仍要求新构图，以及保持指定现稿的局部编辑。检查必要调研是否实际发生、原生预览是否对应当前版本、失败说明是否准确，以及应用保存回执；最后由人编辑、保存、重开并导出。遵守用户明确的预算与原生工具错误行为，不增加自动付费重试。

本轮规划仅更新方案和任务 Spec；本轮没有改动正式 Skill、运行时行为或用户作品，也没有新增模型或图片请求。

## 获批重写的实施与恢复（2026-09-26）

- **Skill 规则归属。** 主入口现包含九个必须执行的阶段、明确任务分支、调研豁免与完成说明。方法参考回指该规则，`imagegen` 只负责图片操作。包规则、README 和真实物化测试保持一致；完整自定义字体示例包含来源、family、weight、style 与文本使用方式。
- **共享准入。** `asset-admission.ts` 统一既有 16 MiB 上限与 MIME 嗅探，YAML 验证、预览、最终 intake 和 canonical 存储共同使用；可选 `finalize` 因而会在成功返回前发现超限字体。诊断保留来源路径、实际字节数和限额。未使用素材不作为引用素材准入；完整目录采集与 digest 的限制保持不变。不自动转换图片或字体。
- **安全错误。** 素材错误经严格的可选本地 RPC 字段和私有 MCP 元数据传递。只有内置预览工具可暴露固定类别、有界单层 `media/` 路径及验证后的大小/类型字段；producer 根据这些字段生成文案，不透传任意诊断文本。未知、外部、格式不合法及传输错误继续脱敏；字体与原生渲染错误保持既有分类。
- **复现与回归。** 修改前真实辅助脚本对合成超限字体错误地返回成功。修改后，保留的真实原稿返回两个 `MOLLY-E005`，明确指出 20,856,816 和 20,752,628 字节的字体及 16,777,216 字节上限；生产 `buildPreviewPayload` 同样拒绝该稿并返回结构化错误。另有三个回归先分别复现 harness 错误过于笼统、daemon 丢失字段及 producer 返回原始诊断，再于修改后通过。
- **显式恢复作品。** 正常退出应用后，使用完整 WOFF 副本，大小为 13,678,880 和 13,242,140 字节；解压后全部字体表与原 TTF 逐字节一致，包含每个字体全部 43,033 个字形。仅修改两个字体来源引用，14 个元素、几何、文案、原字体与其他素材均保留。经正常保存/CAS 与读回，现有设计历史将原空白正式画布保存为 v1、恢复作品保存为 v2。创建版本后使用旧修订的请求被正确拒绝，重读未变内容后使用当前基线完成保存；历史失败回合回执没有改写。
- **原生证据。** 生产 `renderSavedDesign` 将恢复载荷渲染为 1080 × 1350 的 PNG 和 JPEG，没有字体诊断，并已实际查看 PNG。生产 `buildPreviewPayload` 接受修复草稿，生成的文档/素材与保存结果完全一致；重建辅助库后，两个随包脚本入口对修复草稿均通过。这证明恢复与原生可渲染性，不代表人工视觉验收。

定向检查通过：150 项 authoring、69 项 CLI design、47 项 harness MCP、33 项 CLI render/daemon 集成、13 项物化测试，以及受影响包的类型检查。恰好等于上限仍接受，超过 1 字节会被拒绝且不改 canonical，未使用素材不参与素材准入，完整目录的大体积 digest 保持原有行为。全仓 `pnpm check`、`pnpm format` 和 `pnpm run docs check` 均通过。通过 `pnpm start:local` 重建并重启 Molly，随包的七份 Skill 文档与源文件逐字节一致。实际桌面画布已显示恢复的 v2 作品，没有字体错误横幅，导出可用且显示已自动保存。新的 Agent 运行及人工编辑/导出验收留待用户完成。本次实现与恢复没有新增模型或图片生成请求。

3. **已配置的 Pinterest 账号。** 在不暴露 Cookie 值的前提下确认来源构建/profile、导入或手工登录成功情况、重启顺序及目标页面身份。若根因为开发版重启或构建不一致，使用现有稳定签名打包流程验收账号持久化，保留开发版内存分区及加密、签名检查。若支持的签名包中仍可复现，先修证据定位的导入、Cookie 身份、有效期或目标会话缺陷。澄清现有设置展示：Cookie 数量、导入结果和网站实际登录不同；将内存模式提示与相关账号信息放在一起，不从 Cookie 数量产生持久的“已登录”判定。使用同一支持构建验证手工浏览、Agent 浏览和冷启动。
4. **可复用字体准备。** 在 Skill 增加小型可选脚本，封装经验证的 FontTools 环境；复用可用环境，缺失时在会话工作区中位于作品采集目录之外的位置，或指定临时目录显式准备锁定依赖，将缓存和字节码写入沙箱内。要求可用且兼容的解释器，不静默安装全局 Python。脚本列出 TTC 字体、提取选定字重、输出完整 WOFF，并报告大小、family/weight/style 和字形覆盖。保留源字体，验证解压字体表、字符映射与度量。优先使用 16 MiB 内的完整兼容字体；可编辑文字默认不按当前文案裁子集，显式要求子集时说明限制。转换由 Agent 主动执行，不成为 intake 自动修复。
5. **Skill 方法与交付措辞。** 保留九阶段结构，在准备步骤就近放依赖环境要求，在文字处理步骤就近放完整字体规则。调研保留来源链接与具体视觉观察；页面或引用失败后实际观察恢复，准确说明已配置账号仍登录失败。可行时改用能访问的视觉来源，只有必须使用该登录来源时才请求人工登录；区分局部观察与已核实细节。Agent 读取原生预览属于 Agent 审视，人工验收必须有真实人工观察。链接现有字段查找与辅助脚本用法，避免靠搜索随包库猜字段，也不另建一套工作流。

验收先跑确定性回归，再完成稳定签名包账号往返和生产沙箱内的真实字体脚本验证。新设计运行沿用普通 brief 与 Auto-review：预期范围内的浏览和字体准备不应人工审批，真实越界仍须明确且可诊断。检查来源、原生预览与读图，以及回合结束后的保存回执。在独立副本中添加原文没有但完整源字体覆盖的文字，修改下层元素，保存、重开并导出；核对嵌入字体，避免把系统回退误认作通过。付费验收最多五次图片调用，更多次数需负责人授权。本提案没有启动新运行或付费请求。替换沙箱库、扩大全局写权限、增加创作阶段控制器和自动修改现有作品均不在提案内。现有作品的字体恢复需另行明确执行，并走正常版本/CAS。
