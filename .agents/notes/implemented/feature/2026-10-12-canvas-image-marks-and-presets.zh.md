# 画布图片标记与快捷编辑

Status: implemented
Translation: current

[English](2026-10-12-canvas-image-marks-and-presets.md)

## 摘要

此前在画布上问 Molly 只能以整个元素为目标，而且即便工具已具备几种显而易见的编辑，每次请求也都要从空白输入开始。选中单张图片时，“标记要修改的区域”允许画最多十个带编号的框、笔画或点并描述修改；Molly 收到带标记的图片副本作为附带参考图以及元素引用，并以该图片当前素材为原图调用现有图片编辑工具。内联提问同时提供与所选元素类型相符的快捷编辑（图片：去除背景、替换物体、重新打光、让文字可编辑、拆分图层；文本：精简、改写）。这是[画布点选编辑提案](../../proposed/feature/2026-10-10-canvas-click-to-edit.zh.md)的 C、E 阶段。带标记的副本是指引而非蒙版，图像模型是否遵循取决于模型本身；付费的实际发送未运行。

## 问题与证据

在[内联提问](2026-10-10-canvas-inline-ask.zh.md)和[编号批注](2026-10-11-canvas-numbered-notes.zh.md)之后，最小目标仍是整个元素。要在人像上“去掉耳环”只能用文字描述。参考模式是 Lovart 的图内标记和 Codex 应用的区域评论。Spec 排除了蒙版编辑器，图像 MCP 只有带参考图的生成与编辑，因此带标记的参考图是现有工具唯一能承载的区域信号。另一方面，空白输入掩盖了 Agent 已能完成的编辑：带艺术字的图片可补充 `textCopy`，分层工作流可拆分平面图片。

## 决策

- **复用阶梯。** 检查过用 Bento 的裁切覆盖层和选区手柄来绘制：两者都编辑文档几何，会修改作品。检查过 B 阶段的批注图钉：它们按 id 锚定整个元素，不携带元素内部的几何。检查过自动分割模型（Lovart 的 Cmd 点击）：需要产品未附带的模型。以上均被否决；借用批注图钉的覆盖层模式，复用工具栏端点、选区 epoch、引用捕获、`selectionAction` IPC 事件、输入框的选区发送路径与 `uploadSessionReferenceImage`，以及现有图片编辑工具。
- **画布。** `packages/design-bento/src/image-marks.ts` 负责标记模式。标记是仅存在于屏幕的状态，使用图片归一化坐标，因此画布缩放、裁切与填充方式都不会使其错位。渲染器把图片绘制为裁切框内按原始尺寸、带平移/缩放变换的 `<img>`；标记模式在图片三个角放置使用相同变换的零尺寸探针，得到图片到屏幕的仿射变换，也随旋转与缩放变化。点击不拖动即放置一个点；框选与画笔决定拖动形状；最多 10 个标记（`DESIGN_MARKS_MAX`）。按 Escape、取消、请求成功、只读、选区变化或图片消失时退出标记模式。
- **合同。** 请求为 `{ type: 'marks', selectionEpoch, marksEpoch, prompt, send }`，不携带像素。主进程先捕获引用（仅限单张图片），再读取 `window.molly.marks(epoch)`；后者以长边最多 1600 px 绘制副本（PNG；超过 5 MiB 时改为白底 JPEG）。主进程转发 `{ action: 'marks', reference, prompt, send, count, image }` 前检查元素 id、PNG/JPEG 签名、不超过 5 MiB 以及每边不超过 2048 px（`decodeDesignMarkedImage` 与 `nativeImage`）。
- **发送。** 外壳把字节转为 `marked.png` 或 `marked.jpg`，在前面加上本地化的 `design.marksPrompt`，并把图片与文字作为一个普通回合发送。发送被拒或点“加入对话”时，与内联提问一样，把选区标签、图片和提示放入输入框草稿。
- **快捷编辑。** `DESIGN_ASK_PRESETS` 列出每个预设的元素类型、是否要求单个元素以及是否需要输入细节。标签位于输入框之后的“快捷编辑”组中，因此 Tab 可以到达它们，而不占用该按键。请求只携带预设 id；主进程按当前选区重新检查类型与数量，外壳把本地化指令与输入的文字拼接。图片已有 `textCopy` 时隐藏“让文字可编辑”。预设本身从不直接运行工具。
- **未做。** 不输出蒙版，不做自动物体识别，不提供图片编辑工具之外的打光或去背景工具。

## 验证

- 单元测试：预设提示规则、标记请求与带标记图片解码（`packages/shared/tests/design-selection-commands.test.ts`）；按类型的标签、隐藏文字标签、预设发送与细节门槛以及标记按钮（`design-selection-toolbar.test.ts`）；图片坐标中的框与点、请求被拒、上限与撤销、关闭、绑定 epoch 的读取与缩小，以及编号绘制顺序（`design-image-marks.test.ts`）；预设与标记转发及发送和草稿回退（`design-canvas-selection-ask.test.tsx`）。
- 真实 Electron 应用（2026-10-12，深色主题）：选中人像图片时，标记按钮出现在“问 Molly”旁。第一版构建打开标记模式后立即关闭，原因是它通过实际渲染器并未使用的 SVG `<image>` 计算映射；由此改为上述角点探针映射。修复后，拖动画出的框 1 正好覆盖耳环，点击在书堆上放置了点 2，面板自动置于图片上方，输入文字前“发送”保持禁用，Escape 退出标记模式。同一图片的提问弹窗显示了五个图片快捷编辑。
- 未运行：标记模式中的“加入对话”与实际发送（发送是付费模型回合）、浅色主题，以及应用内的文本快捷编辑。人工视觉验收待完成；Spec 修订保持 draft。
