# 画布批注第三阶段：暂存到输入框与按住对比

## 摘要

画布批注托盘的“发送”过去会立即派发一个回合，也无法查看 Molly 上次修改前的画稿。现在托盘的“发送”会把批注暂存到对话输入框——出现“N 条批注”纸片（悬停或聚焦列出编号批注），并把整稿标注快照与原有的一张区域标记图作为普通附件暂存——用户可再输入总体指示后照常发送；在批注编辑器或托盘上按 ⌘/Ctrl+Enter 仍可立即发送。另一方面，Agent 回合提交后，按住 `\` 或画布工具栏的对比按钮即可查看该回合之前的渲染，松开即返回。对比帧由 Molly 管理的 Git 历史中内容与被替换修订一致的条目渲染，只留在内存，从不写入文档、历史或触发同步。这是画布批注打磨第三阶段（[issue #185](https://github.com/LeonEthan/molly-design/issues/185) 的第 8、11 项）；暂存流程与覆盖层机制已在真实应用上验证（见关联 PR），真实已提交回合端到端喂给按住对比未执行（隔离 profile 中没有已授权的验证连接），Spec 修订仍为 draft，待人工视觉验收。

## 问题与依据

B–D 阶段之后，用编号批注审阅画稿仍是每批立即一个回合：无法补充总体指示，也无法在批注发出前检查。Codex 应用把画布批注暂存为输入框纸片。此外，回合提交后画布只会短暂勾勒改动，用户无法在“当前画稿”和“改动前”之间切换；目标反馈阶段当时推迟了按住对比，因为当时没有不改动当前稿的历史渲染方式。

## 决定

- **复用阶梯（暂存）。** 考虑过输入框的单选区纸片（`designSelectionState`）：只有一个元素引用、没有列表——否决。考虑过把批注作为内联 mention 区间放入草稿文本：十条批注会撑爆草稿，也失去单片移除手势——否决。考虑过预览视觉批注与评论引用纸片：它们作为独立的 `SessionInputBlock` 类型锚定会话实体，而非画布元素引用——否决。借用纸片样式（`DesignSelectionChip` → `DesignNotesChip`，用 Radix popover 在悬停/聚焦时列出编号批注），复用输入框的按会话草稿缓存（`sessionStagedNotesCache` 与文本/图片草稿缓存并列）、普通图片附件管线（`handleAddFiles`，含数量上限与上传失败阻塞）、`appendDesignSelectionMention` mention 流程与展开通道，因此发出的文本与直接发送完全一致：编号行，每条批注一个 `<molly-elements>` 引用。
- **整稿标注快照。** main 用现有导出渲染器（`renderSavedDesign`）离屏渲染已保存画稿，经宿主绑定的 `/ws/<id>/notes-snapshot` 路由一次性发给画布；画布（`window.molly.annotateNotesSnapshot`）把每条批注的编号画在它所在位置——图钉点与默认角锚点从屏幕几何经舞台矩形投影，区域轮廓来自图片归一化坐标——再按带标记副本的 PNG/JPEG ≤5 MiB 回退重新编码。main 用与标记副本相同的签名/尺寸/边长校验组合后的字节。托盘发送携带 `stage: true`；批注请求、epoch 防护与引用捕获不变。
- **语义保持。** 暂存从不消耗保留的未发送批注副本（只有直接发送才 `accept` 进入 flight），每次发布都携带图钉 epoch 和画布页面实例 id——画布重建时 epoch 会重置，因此来自已关闭并重开画布的暂存纸片绝不能结算掉新页面的图钉。被接受的发送——输入框暂存或托盘直接——以 `sent=true` 结算，只在图钉未再改动（epoch 与实例一致）时清空画布图钉并退役保留副本；有更新的编辑则两者都保留。移除纸片只是取消暂存，只一并移除随它暂存的图片；画布图钉保留。暂存相对输入框图片上限是全有或全无：附件放不下时完全不暂存，托盘报告失败。
- **按住对比。** 当已提交回合重载打开的画布且元素 diff 非空时，main 异步渲染 `sourceRevisionId` 与被替换画布修订一致的历史条目（`history-read` 是只读的；`sourceRevisionId` 是内容哈希，去重后的更早条目等价），经同一离屏渲染器缩小到 ≤2048 px，按作品在内存中保留一个 PNG data URL。回合开始、画布拆除或更新的准备工作都会使其失效。shell 经 `design.compare` 得知可用性；在 shell 或画布中按住 `\`——画布经工具栏端点发出 `{type:'compare'}`——或按住工具栏对比按钮，都会驱动 `window.molly.showCompare(src|null)`；该覆盖层跟随舞台矩形缩放平移，显示期间阻止舞台指针输入。否决：用 `capturePage` 截取可见画布（视口裁剪、随缩放变化，还要隐藏控件），以及隐藏的平行画布实例（静态需求用既有渲染路径即可，不值得再管一套视图生命周期）。

## 验证

- 单元：暂存标记、带 epoch 同步与对比请求的 schema 边界及整稿标注快照解码（`packages/shared/tests/design-selection-commands.test.ts`）；托盘 Send 暂存、⌘Enter 直接发送、未发送结算保留图钉（`design-note-pins.test.ts`）；图钉、角锚点与区域轮廓的快照标注几何（`design-note-pins.test.ts`）；覆盖层定位、隐藏与指针阻断（`design-compare-overlay.test.ts`）；纸片暂存、随草稿编号发送、移除而不结算（`session-chat-input-submission.test.tsx`）；暂存批注的画布事件路由（`design-canvas-selection-ask.test.tsx`）；保留副本的 epoch 与暂存结算（`design-note-retention-core.test.mjs`）；对比来源选择（`design-compare-core.test.mjs`）。
- 真实 Electron 应用（2026-10-20，深色主题，隔离 profile，未配置模型）：托盘“发送”把“2 条批注”纸片、整稿标注快照与一张区域标记图暂存进输入框附件；纸片悬停弹出层列出两条编号批注；移除纸片只移除其暂存图片，草稿文字与画布图钉保留；托盘上 ⌘↵ 立即派发且不经暂存，该回合被接受后在模型边界失败，编号批注文本留在会话记录中而图钉按“发出即清除”规则清除。用注入帧经画布桥驱动对比覆盖层：精确覆盖舞台（亚像素级）、随缩放跟随、图钉与托盘保持在上层、显示期间阻止舞台指针输入。
- 未执行：真实已提交回合端到端喂给按住对比（隔离 profile 中没有已授权的 DeepSeek Flash 连接），以及付费的暂存发送。人工视觉验收待完成；Spec 修订保持 draft。

## 限制

- 整稿标注快照取自最近一次已保存修订；按下发送时仍在保存的编辑由 epoch/修订防护拦截，与直接发送的引用一致。
- 只有在已提交回合重载了打开的画布时才会准备对比帧；画布关闭时结束的回合没有对比帧，与回合后轮廓一致。
- 未改动任何元素的回合（例如只改背景）不准备对比帧，因为触发条件是元素 diff。
- 从暂存纸片发出的回合在运行期间只显示普通工作轮廓；编号运行徽标仍只属于托盘的直接发送。
- 按住对比以整幅画稿图片为目标；它不能逐元素对比，逐元素对比已由回合后轮廓覆盖。
