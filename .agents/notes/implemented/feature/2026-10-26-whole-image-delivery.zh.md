# 整张图或可编辑图层交付

Status: implemented
Translation: current

[English](2026-10-26-whole-image-delivery.md)

## 摘要

此前每个新设计或重新设计都以图层还原收尾：用付费图片编辑抠底图和物体、重组、配字，即使用户只想要选中的那张海报。负责人在 2026-10-26 决定，在开始图层还原之前由用户选择交付形式。设计方案回复现在会和方案选择一起询问：选定方案以可编辑图层（默认）交付，还是以一整张图交付，即作为单个覆盖画布的 `image` 元素放入作品；模板、复刻和局部修改不询问。工作流 Spec 因本次修订退回 draft，新分支尚无 Agent 运行验证。

## 问题

- 本决定扩展了[用户选择设计](2026-10-09-user-chosen-designs.zh.md)的决定，其忠实还原仍是默认交付。
- 已批准的工作流 Spec 和核心 Skill 对所有新方向都承诺分层作品。唯一的用户停顿是方案选择，因此只想要原图的用户仍要为抠图付费并等待还原。
- 在分层结果出来之后再选择什么也省不了，所以问题必须在第 4 阶段之前提出。

## 决定

1. **在哪问。** 就在现有设计方案回复里，与"选 A、B 还是 C"放在一起；不增加回合，也不调用 `ask_user_question`，调研 skill 本来就禁止用它询问方案选择。需求已写明形式的不再询问；用户未回答则按可编辑图层。
2. **you-choose 路径。** 不停下；除非需求要求整张图，否则按可编辑图层。
3. **不询问的分支。** 指定模板和复刻本身就是要产出可编辑图层，局部修改保留现有结构。
4. **整张图结果。** 选定方案复制到 `media/`，作为唯一覆盖画布的 `image` 元素放入作品，跳过 `design-replication`。仍逐字核对其文案与需求，回复中说明每一处错漏的文案，并说明文字和版式不可编辑、可按需拆成图层。渲染并看图照常进行。
5. **单一归属。** 规则写在核心 `graphic-design` Skill 的 "Delivery form"；`design-research` 和汇报条目引用它。

## 备选方案

- **先交付整张图，按需拆层。** 完全不用询问，但默认交付物从可编辑变为不可编辑；意图改动更大，未采用。
- **还原前单独用 `ask_user_question` 询问。** 在方案选择之后多一次来回，未采用。

## 局限

无格式或代码改动：单个覆盖画布的 `image` 元素本来就可被准入。CLI 结构测试检查链接与标题而非措辞，不能证明 Agent 会遵循新分支；仍需一次选择整张图形式的端到端运行。
