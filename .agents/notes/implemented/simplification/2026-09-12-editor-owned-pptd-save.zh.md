# 人工编辑保存时自动更新 PPTD

Status: implemented
Translation: current

[English](2026-09-12-editor-owned-pptd-save.md)

## 摘要

在人工与 Agent 串行编辑的前提下，用户提出让人工编辑自动落到 PPTD，取消 Agent 自主触发同步的需要。用户已确认把当前稿 PPTD 的更新纳入编辑器保存能力，由 Geon 的设计适配层复用反向转换，Bento 继续只提供通用文档变更和保存接口。读取同步 hook 退出目标，但用户明确要求保留修改已有文件前先读取的提醒 hook；通过公开扩展实现，不依赖逐次模型生成证明。自动保存完整性、失败草稿保留及来源隔离仍是必要条件；Spec 和计划已调整。（事实更正：保存随后已实现为独立于 Agent 执行、在权威存储旁发布当前稿 PPTD，重开按实际文件内容核对后再复用；原文“运行时尚未实施”为确认阶段状态。）

## 原则与前序方案的关系

本建议重新讨论[非侵入 hook 方案](../../proposed/simplification/2026-09-12-noninvasive-design-hooks.zh.md)的前提。自动保存是一项由人工编辑触发的文档能力，即使没有 Agent 也应运行；它不安排 Agent 的调查、创作、读图或完成顺序。先前将“自动维护文件”一并视为应用干预 Agent 的做法过宽，应区分通用编辑器能力与设计任务编排。

[串行编辑](../architecture/2026-09-11-design-serial-editing.zh.md)继续保证人工修改与 Agent 执行错开。执行入口只排空既有保存队列、确认同版本文件就绪，不在启动 Agent 时才第一次生成 PPTD，也不将同步失败藏在提示词里。根规则和 Spec 已改为保存时更新 PPTD、hook 提醒先读；旧读取同步合同只保留为历史实施背景。

## 职责和数据流

```text
人工完成一次编辑
  → Bento 通用文档变更/保存接口
  → Geon 设计保存适配：校验、保存 BentoDoc、更新同版本 PPTD 与素材
  → Agent 使用普通文件工具读取已有文件并编辑草稿
  → 文件监听提供只读预览
  → Agent 自然结束后，既有采集与原子版本检查保存当前稿
```

- Bento 不接入 Agent 状态或五种 runtime，不在内核中增加 PPTD 文件管理。Geon 的保存适配层处理格式、磁盘及版本；这是对用户所述“Bento 自动反向同步”的职责划分。
- 保存目标覆盖已完成的文字修改、拖动、撤销/重做和属性变更。可合并连续编辑，不要求每个 pointermove 发布整个多文件工程；flush 必须等待最后一次已完成编辑的文件结果。
- 复用 exportPptd (`06aa8ba:packages/design-authoring/src/pptd-v3.ts`)、[DesignSyncService.project](../../../../apps/cli/src/design/sync-service.ts)中的转换/发布部分与[当前稿存储](../../../../apps/cli/src/design/store.ts)。当前 project 是回合服务私有方法，并依赖活动回合检查；不能仅从手工保存处调用它而保留这一依赖。
- 创建及显式导入等产生当前稿的入口也需保证可读表示就绪，避免只有手工改动后才出现 PPTD。Agent 提交刷新当前稿表示时按来源处理，不将其加载到画布的通知当成新的人工编辑。

## 可删除的设计专用机制

| 机制 | 建议 |
| --- | --- |
| 读取前 BentoDoc → PPTD hook | 删除；文件更新随人工保存完成 |
| 为同步新增的必经工具/提示词流程 | 不需要 |
| 五种 runtime 的设计读取同步适配 | 不再作为此能力的依赖；不影响原生 hooks 或其他扩展用途 |
| 修改前先读取的提醒 hook | 保留，公开 hook/extension 提醒，复用原生检查；不参与同步 |
| 专用成功读取证明、generation/attempt 审计 | 不作为新合同的统一准入条件；收敛写入和最终采集中的旧依赖，保留真实版本及来源检查 |
| 反向转换、语义往返、素材校验 | 保留，转到通用设计保存适配 |
| 草稿保留、来源区分、最终原子版本检查、实时预览 | 保留；均不要求观察模型采样边界 |

用户否定删除全部 hook。现保留“改已有文件前先读”的提醒，环境提供最新文件，Agent 负责读取与修改；提醒不是读取证明，版本检查也不证明模型理解内容。新文件例外、公开事件的真实语义与五种原生工具证据见[非侵入读取提醒](../../proposed/simplification/2026-09-12-noninvasive-design-hooks.zh.md)。不由 Geon 重造统一读取台账或用提醒冒充硬阻断。

## 保存必须具备的边界

1. **同版本可读。** BentoDoc、PPTD 页面及素材不能混用不同保存版本。转换后发布前重新核对版本，旧任务不能覆盖新保存；沿用受控快照读取和保存串行机制，不以防抖代替一致性。
2. **失败可恢复。** 两套文件不能因为分别执行 rename 就被宣称跨文件原子。若当前稿已持久化而投影发布失败，保留人工结果、明确报同步失败并阻止 Agent 读取陈旧稿进入创作；重开根据当前稿版本核对/重建投影。不能撤销已保存当前稿，也不能显示文件全部就绪。具体恢复标识优先复用版本与已有保存状态，不增加任务编排服务。
3. **未完成草稿不能丢。** 当前稿的 PPTD 表示与 Agent 失败/取消后保留的工作草稿，先沿用现有区分；自动保存只更新当前稿表示。串行执行消除了同时写入，不消除跨回合遗留修改。若进一步要求人工与 Agent 共用同一套 PPTD 工作文件，必须先确定遗留草稿的保留方式，不能直接用自动导出覆盖。
4. **来源阻止循环。** 当前稿投影不进入新产物采集；Agent 文件预览不反向保存；提交后加载画布不再次触发人工保存。复用来源、版本和内容比较，不新增第三套可提交状态。
5. **外部变化仍有边界。** 画布只读不锁住任意外部程序。正式提交继续核对真实当前稿版本、资产及文件快照，冲突保留内容，由 Agent 通过普通文件反馈处理；回合结束后发现的冲突不自动重启模型。

本建议维持 BentoDoc 为当前稿权威、PPTD 为文件表示的既有模型。进一步改为 PPTD 唯一磁盘真相、BentoDoc 仅作内存模型，是另一个存储设计决定；不从本次自动保存想法中推定授权。

2026-09-12 后续确认[Git 设计历史](../feature/2026-09-12-design-version-history.zh.md)：用户“存为版本”和恢复前保护统一使用 Git，不建设当前稿旁的第二套历史快照库。本记录中的稳定快照与发布暂存仅服务当前保存的一致性，不是持久版本后端；Git 不替代自动保存、当前稿版本检查或草稿保护。用户随后确认 Geon 独立管理本地 Git 仓库，并裁定本记录采用自动回写且保留读取提醒。

## 验证与状态

本次静态核对本地反向转换、投影发布与 canonical 保存入口，确认存在可复用实现，但没有证明其直接满足跨保存版本及崩溃恢复的新合同。本轮将已确认目标写入 Spec、根规则和计划，不修改运行时代码或发布票据，不运行测试或真实模型；文档检查单独执行。对 Cursor 的类比仅采用用户描述的体验，没有声称核实其内部存储实现。
