# 让 graphic-design Skill 聚焦设计质量

Status: implemented
Translation: current

[English](2026-10-09-graphic-design-skill-refresh.md)

## 摘要

graphic-design Skill 的大部分篇幅用于约束表述，并在多个文件中重复同样的规则，却几乎没有给 Agent 具体的版式指引；而设计评测中观察到的失败正是版式问题（主体过大、标题挤压人脸），以及版式未变却声称已重新设计。本次优化加入可打破的设计默认值并兼作审视清单，每条规则只陈述一次，纠正了禁止使用已激活的图标、表格和图表语义的指引，新增分层示例和中日韩字体指引，并以结构性测试取代逐句固定的测试。第四轮以方向词锚定工作流：结构化意图提问、以方向词为起点并对局部修改豁免的有界调研、基于原生草模的图加文草稿，以及否定方向时的处理规则。负责人已于 2026-10-09 批准 Spec 修订（回复篇幅相称及上述工作流变化）。输出质量是否提升尚未测量，需要由负责人盲评的串行设计评测运行来确认。

## 问题与依据

- graphic-design 材料约 6,200 词，"does not establish""is not proof"等否定性表述出现 16 次；预览缺失、字体加载和保存时机的规则各写了三处。
- `references/replication.md` 要求不要声称原生图标、表格或图表，`graphic-canvas-profile.md` 要求 Agent 把没有记录的组合视为不支持，却从未给出记录。冻结的能力矩阵中图标、表格与图表各行均为 `active`。
- 默认字体 Inter 不含中日韩字形。矩阵 `font.fallback` 行说明未登记字体会经宿主系统字体回退，导出确定性只对全部登记的字体栈承诺；Skill 对此未作说明。
- 已批准 Spec 第 9 步要求区分已准备文件、已审视草稿和已保存作品；短回复修复后的 Skill 要求仅在重要时提及。
- Skill 测试固定了约 20 个原句，任何改写都会在行为未变时导致测试失败。

## 决定

负责人于 2026-10-09 批准全部八项建议与三项决定：

1. `SKILL.md` 中的**设计默认值**：主体比例、文案不压人脸或产品、边距、最多三档字号、图上文字可读性、对齐与阅读顺序。Agent 可说明理由后偏离；只有真实运行中出现过的失败才成为规则。第 7 步以其为清单，第 8 步检查声称的重新设计确实改变了版式。
2. **当前可编辑能力**：删除 `graphic-canvas-profile.md`；`artwork-format.md` 按元素类型列表，以编辑器实际提供的操作为界，并标注图片裁剪受限（issue #15）。
3. **每条规则只陈述一次**；参考文件链接到归属章节而非重述。
4. **回复规则**合为一节。Spec 第 9 步改为：不得声称未执行的检查或保存，始终报告缺口，仅在重要时作三方区分。Spec 曾回到草案，负责人已于 2026-10-09 批准该修订。
5. **分层示例** `examples/layered/`（不透明背景、带阴影的透明主体、渐变遮罩、成组文字），使用合成 PNG，并由 intake 测试覆盖。
6. **中日韩字体**：登记完整且有授权的字体，压缩而不子集化，否则说明字体取决于观看者电脑。
7. **调研规则**只陈述一次并配示例表。含义不变，包括仅凭当前打开的作品不构成豁免。
8. **结构性测试**：阶段标题、所有相对链接与标题锚点可解析、每份参考均可到达、关键规则恰好出现一次、两个示例在物化目录中通过 intake。

## 后续：来自设计实践的经验

同日第二轮将默认值与一份整理自十三篇设计文本（Vignelli Canon、Bierut、Rand、Hische、Lupton、Sagmeister 等；引文未独立复核）的实践摘要对照。结果显示，第一版默认值把边距和字号处理得过于机械，并带有缺乏出处的数字（主体占短边 35–60%、5% 边距、0.5–0.65 的字号级差）。这些数字已删除，默认值明确为工作习惯而非定律：

- 边距保留不贴边的底线，其余按气质选择（窄则紧张，宽则平静）；
- 一到两个字号且对比明显（约两倍），先用字重再加第三档字号，不靠放大加粗来"喊"；
- 留白是结构；黄金分割与三分法不作为构图规则；
- 第 1 步询问作品在哪里被看到、周围是什么；
- 回复只呈现选定的一个方向，仅在用户要求或两稿确实接近时附上备选；
- `general-poster.md` 增加找出需求的特殊性、可选网格，以及有理由地、按观看距离选字；
- `browser-research.md` 要求参考多个（含历史）来源，并检查方向不是换了文案的单一来源；
- 中日韩字体部分增加标点与行首禁则检查。

书籍序列、双面印刷、字体史和设计师作者性被判定超出单张静态画布范围。这些改动同样尚未评测。

## 后续：更灵活的文字表现

应负责人要求，第 6 步不再只说普通文案一律使用原生文字，而不说明何时更适合用图片。使用标准或已登记字体的原生文字仍是正文、事实信息和可能改写的文案的默认选择，并在处理有样式的标题时优先尝试（intake 接受文字 `gradient`、`letterSpacing` 与元素 `shadow`；本次未核对其渲染效果）。字体无法表达的艺术字（手写、书法、立体或插画字、融入画面的字）可以作为由 `molly_image` 生成的 `image` 元素。由于图像模型常写错字，尤其是中日韩文字，必须逐字核对；出现错字即重新生成或改用原生文字。图片字的文案只能通过重新生成来修改，这作为可编辑性限制报告。`layered-workflow.md` 新增文字图层技法。这仍在已批准 Spec 第 6 步（"判断哪些文字采用可编辑文本，哪些适合保留为图片或矢量"）的范围内，因此 Spec 不变。

## 后续：方向优先（情绪板经验）

对照三篇情绪板文章审视工作流：优设网的情绪板教程（2022）、Made Good Designs 的情绪板指南，以及 Elizabeth Goodspeed 在 AIGA Eye on Design 发表、认为共享情绪板让广告千篇一律的文章。三者一致认为：收集前先用一句话定方向，少量参考并大胆删减，参考来自类别之外，参考传达特质而非物体，情绪板是后续判断的标尺。Skill 原先以 Pinterest 为先且没有明确方向，正是 Goodspeed 所说导致衍生作品的模式。经负责人批准：

- **第 1 步**增加作品所处类别与必须传达的一条信息，然后写一句方向描述和二到四个方向词，作为工作标尺而非用户审批步骤。新设计或重新设计存在会改变方向的缺口时，Agent 用 `ask_user_question` 一次性提问（一到四个问题，选项附推荐默认值），否则基于报告的假设继续，非交互运行不会卡住。
- **第 2 步**以方向词为起点检索，包含一个类别与当下信息流之外的来源，调研为一次有界检索。沿用现有方向的局部修改免除调研（负责人此前的待定问题，现已决定）；这改变了调研规则的意图。
- **第 3 步**保留三到六个参考，每个只贡献一种特质。草稿默认图加文：用原生元素搭建草模（形状、占位文案、提炼的配色），经 `molly_render_preview` 渲染后，连同交付素材传给 `molly_image` `edit`。负责人要求以图约束草稿，因为文字难以描述版式。找到的参考图从不作为编辑输入：以图约束会复制构图与物体，且作品属于他人。由于服务商能力不同（DashScope 最多三张输入；`USER_GUIDE.md` 将多参考合成列为未验证），纯文字生成仍是需报告的回退方案。`molly_render_preview` 不接受输入，只渲染创作目录的 `design.yaml`，因此草模临时占用该文件，已有作品先复制到别处，回合结束前替换掉草模。
- 新增设计默认值：每个标志性视觉手法都需与主题或信息相关；第 8 步对照方向词检查渲染结果；回复点明方向。
- 用户否定方向时，Agent 先对照方向词：仍成立就重新诠释，否则回到第 1 步提一个问题。

未采纳：设计前需用户批准的情绪板（Goodspeed 认为事先审批导致衍生作品，且增加阻塞步骤）、情绪板文件或图片交付物，以及由生成图组成的情绪板。

## 后续：重新设计从草稿开始

方向优先版 Skill 的首批评测（瑞幸重新设计用例，kimi-k3 · Max）运行完成，负责人认为效果一般。在保留完整证据的运行中，Agent 先在 Pinterest 调研，然后用三次 `edit` 分离代言人、咖啡和签名，用一次 `generate` 生成空背景，没有搭建草模，也没有构图草稿；版式来自重新排列抠图。分支表没有"重新设计这张海报"一行，提供原海报并要求"保持人脸、咖啡和尺寸"被理解为复刻或局部修改，而这两个分支都沿用给定构图。保持人脸一致的要求也让 Agent 回避图片模型草稿。

经负责人批准：

1. 分支表新增**重新设计**：原图提供内容、文案和交付素材，而非构图。"重新设计""优化""做得更好"即使带有保持人脸等约束，也要求新构图；局部修改是明确的局部改动。
2. **新构图必须起草**，在预算内至少两稿。重新排列抠图或现有图层不算选择构图；无法起草时需在回复中说明。
3. **草稿与最终图层分工不同。**草稿确定构图、光线与氛围，可以近似表现人脸或产品；分离出的主体放入草模，使草稿保持相似与比例。最终图层从原图分离主体以保持一致，并按选定草稿放置。`layered-workflow.md` 新增"保留主体的重新设计"做法。
4. **第 8 步**检查声称的重新设计是否遵循选定草稿；版式与任何草稿都不对应即说明跳过了第 3 步。
5. 该做法允许草稿中的展示标题改为图片字，回应负责人此前对已接受基线"系统字体显得死板"的意见。
6. 评测运行器从 Pi 会话统计过程数据（图片生成与编辑调用、渲染预览、浏览器与提问调用）写入 `run.json`，供负责人评审参考，不作为门槛。

Spec 因重新设计分支及草稿与一致性的分工回到草案。

## 备选方案

- 保留 Spec 的三方报告并撤回短回复：否决，短回复是有意的产品修复，诚实保证无需强制叙述也能保留。
- 由应用强制执行数值规则：违背 agent-naive 设计原则，否决；默认值仅作建议。
- 保留 `graphic-canvas-profile.md` 作为开发者文档：其激活纪律属于平台合同，不应在 Agent 阅读路径上。

## 局限

- 尚无 Agent 运行使用新材料。前后质量对比需要 2–3 个串行设计评测用例（含 Luckin 孪生用例），由负责人盲评，并需获批的图片预算。
- 分层示例通过 intake，但尚未经 `molly_render_preview` 渲染。
- 可编辑性表格依据冻结矩阵和编辑器面板；本次未端到端复核各类型的编辑操作。
- 重新设计起草每次运行约增加二到四次图片调用；是否改善负责人的评判只能由后续评测运行衡量。
- 安装版中的提问交互仍未验证（`USER_GUIDE.md`）。以草模约束的草稿尚未用真实图片模型测试；平面草模可能让草稿显得呆板。
