# 首页测试草稿的定向清理与恢复验证

Status: implemented
Translation: pending

## 摘要

首页启动后显示了未由使用者输入的合成测试文字。检查发现这段文字来自已保存的首页草稿，当前源码和构建产物均没有对应的默认提示。使用者选择只清理这条残留并保留正常草稿恢复，因此复用现有输入清空路径，没有增加文案过滤器或改变持久化语义。新增回归验证当前及旧命名缓存的清空结果能跨重新挂载保存，其他工作区的草稿保持原样；原始写入者仍未确定。

## 证据与决定

- [首页草稿 atom](../../../../packages/components/src/atoms/local-storage-cache.ts) 默认提示为空，通过已有产品存储按使用者与工作区恢复。
- [产品存储](../../../../packages/components/src/lib/product-storage.ts) 优先读取当前 Molly 键，仅在当前键缺失时读取对应的旧 Lody 键。正常清空写入空提示，覆盖旧值的读取优先级。
- 当前源码、启动脚本、测试脚本和构建产物中未找到该合成提示。观察到的缓存值证明恢复来源，但不能证明最初由哪个测试或进程写入。
- [标准 Electron 测试 harness](../../../../e2e/src/support/electron-harness.ts) 创建临时 profile，并核对实际 Electron 数据目录。普通本地启动复用持久 profile；这不能据以认定当前标准 harness 污染了用户数据。

复用顺序：已有输入清空及作用域草稿 setter 已能保存空值；现有产品存储已处理旧键回退，无须改造。内存 atom 会改变所有首页草稿的跨重启恢复，使用者明确选择保留该行为。按提示文字自动过滤无法区分旧测试数据与以后主动输入的相同文字，故未引入新模块、迁移标记或存储层。

Codex CLI `gpt-6-astra/high` 的只读意见建议定向一次性清理，认为当前证据不足以修改生产恢复逻辑。本次采取该建议，并保留“原始写入者未知”的限制；没有将建议当作自动修复或产品批准。

## 验证与限制

- 清空后，真实开发应用重新加载时输入为空。
- [回归测试](../../../../packages/components/tests/chat-landing-draft-persistence.test.tsx) 使用合成缓存，分别验证 Molly 与旧 Lody 命名：已有提示可以恢复，显式清空后新的 Jotai store 不再恢复该文字，其他工作区草稿仍能恢复。
- 草稿及产品存储定向测试 11 项通过；修改前组件基线 3,247 项通过。测试输出含已有历史 Claude 子模块 tsconfig 解析警告，退出状态为成功。
- 通过原生退出关闭开发应用，确认原 Electron 主进程已结束；随后执行 `pnpm start:local` 重新构建并启动。新进程的首页输入仍为空，发送按钮禁用，原会话列表仍在。
- 组件类型检查、完整本地构建、全仓 `pnpm check`、`pnpm format` 与文档检查通过。组件最终 3,249 项通过；CLI 3,073 项通过并保留既有 3 项跳过，RPC 包另保留既有 3 项跳过。
- 没有修改生产默认文案或禁用正常草稿恢复；没有清理会话历史、作品或其他草稿，也未发送模型请求。若以后再次出现，应查明新的写入来源，不能凭现有证据声称永远不会发生污染。
