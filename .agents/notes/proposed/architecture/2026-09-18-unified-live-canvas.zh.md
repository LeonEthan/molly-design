# 单一画布与 Agent 创作过程展示的可行性

Status: proposed
Translation: pending

## 摘要

右侧 Artwork / Preview 两种入口要求用户理解已保存画稿与创作草稿的内部区别。建议收敛为一个画布入口，由执行和提交状态自动选择显示内容：空闲时编辑当前稿，运行时展示最新有效 YAML 快照，提交成功后恢复当前稿编辑。现有文件监听、转换、只读渲染和最终提交链可以复用，但逐次重建原生视图、首次草稿缺失和跨回合旧草稿需要专门处理。这里的实时是跟随有效文件落盘，不保证逐 token 或逐工具调用显示；本记录仅为源码可行性分析，未实施或测量性能，也未获得具体方案批准。

## 范围与既有决策

本提案只处理右侧画布的入口及显示连续性，不改变单画布文档格式，不引入多画板、过程回放、过程版本库或新的 Agent 调度。

后续讨论已整理为[完整实施与黄金验收方案](2026-09-18-version-based-canvas-editing.zh.md)，包括历史版本直接续改，取代本文的历史只读建议及待定细则。下文保留初轮分析证据，后续设计以完整方案及 draft Spec 为准；本记录不代表已实施。

- [Spec](../../../../specs/graphic-design-platform.zh.md) 仍是现行目标；其允许手动切换当前稿和创作预览的条款在本提案获确认后再调整。
- [自动打开创作预览](../../implemented/bug-fix/2026-09-12-auto-open-agent-source-preview.md) 已实现开始执行时切换预览，并尊重用户后续选择；本提案拟取代手动来源选择部分。

## 已有实现与差量

| 已有实现 | 本次需要处理的差量 |
| --- | --- |
| `DesignCanvas` 已在 live status 开始时进入预览；监听与对账以 preview 激活为条件 | 删除来源按钮和用户选择状态，改为自动显示策略；执行生命周期不能仅凭聊天 live status 判断结束 |
| `refreshSourcePreview` 共享精确依赖监听，追踪 `design.yaml` 和引用素材 | 保留按可见消费者订阅与释放，不扩大为后台所有作品持续监听 |
| `buildPreviewPayload` 冻结并复核文件字节，经同一 intake 转为 BentoDoc；摘要去重包含素材字节 | 无须另建格式转换器；同路径图片替换也应触发显示更新 |
| `SourceObservation` 合并更新，拒绝过时代次；无效快照保留旧预览 | 保证第一份有效草稿出现前仍可见原画稿；区别临时写入状态与持续异常 |
| 每份新快照创建新的 `WebContentsView`，加载字体/图片后替换旧预览 | 测量更新延迟，保留缩放与浏览位置，避免持续变化使每次渲染都过时而长时间无更新 |
| committed receipt 经 `syncOpenDesignCanvas` 成功后返回当前稿 | 取消、失败、no_artifact 也必须有明确的自动显示归宿；加载失败与提交成功分开报告 |
| 当前编辑器隐藏后仍保留，源预览不注册保存/flush | 单一用户入口可以继续复用内部隔离；不可简单把草稿送入编辑器自动保存路径 |

现有 watcher 默认 50 ms 防抖、500 ms 最大事件等待。这仅是事件调度参数，不是端到端显示时延；读取、校验、转换、原生视图创建、图片解码和字体加载仍在其后。没有性能实测可支持具体帧率或亚秒承诺。

## 建议的用户行为

| 情况 | 同一个画布展示什么 |
| --- | --- |
| 空闲 | 已保存当前稿，可手工编辑 |
| 派发、等待首次有效改动 | 保持当前稿可见，进入只读；首次创建作品使用已有空白画布 |
| 本轮有有效 YAML 快照 | 就地显示最新有效中间稿，允许缩放和浏览 |
| 文件正在写入、结构暂不完整、素材尚未就绪 | 保持上一有效画面，不闪白、不静默补字段或丢弃元素；轻量提示等待更新，持续异常可查看原因 |
| Agent 已结束但仍在校验/提交 | 保持最后有效画面和只读状态，等待真实处理结束 |
| 提交并加载成功 | 展示新当前稿，恢复编辑；保留合理的浏览位置 |
| 取消、执行失败、无有效提交 | 处理结束后返回已保存当前稿；失败/取消说明草稿仍保留，普通无产物讨论无需额外警告 |
| 历史版本 | 保留既有显式历史查看，同一画布内只读；不要被后台更新强制抢回 |

继续复用既有执行提示，只在画布需要解释所显示内容时增加简短状态；不恢复来源路径横幅。草稿状态下禁用编辑、元素引用、存为版本和正式导出，避免画面与操作对象不一致。现有导出针对已保存当前稿，不新增中间稿导出。

取消后返回已保存稿是本提案的推荐，尚待讨论。另一种选择是停留在最后草稿，但这会要求用户额外理解如何回到可编辑当前稿；直接解锁该草稿则改变提交与数据保护合同，不属于简单的视图收敛。

## 真正的实时边界

文件监听只能观察实际写入。Agent 若一次工具调用才完整写出最终 YAML，画布只会出现一次完整变化；工具参数的流式文本不能证明文件已经落盘。有效中间状态也可能已经被下一次写入覆盖，合并调度不保证显示每一个状态。

可以在既有创作技能中建议 Agent 在自然完成的阶段保存有效草稿，例如先构图、再文字、后图片细化，但不得强制阶段、次数或暂停来制造动画。无需每次调用 `molly_render_preview`，也不因视觉进度展示而产生额外模型或付费图像请求。若要求逐 token 展示，必须另行讨论不完整语法解析、素材占位和工具参数语义；现有能力不支持作出该承诺。

## 关键技术选择

优先合并用户入口并复用既有隔离预览。每次替换只在新画面真正就绪后进行，旧画面持续可见；通用视口状态应与文档内容分开保留。先测量全量快照渲染是否满足正常写入节奏，只有确有瓶颈时才考虑同一个只读渲染实例的通用文档替换能力。现有公开桥提供 snapshot/flush/readonly/commands，尚没有可直接宣称复用的整文档热替换接口；增加它会扩大桥接与撤销、资源生命周期的验证范围。

每次预览均提交为当前稿不建议采用：它改变失败/取消保留原稿、正式版本校验和自动保存的语义，并可能反向覆盖 Agent 工作文件。唯一可编辑真相继续是已保存 BentoDoc；临时 BentoDoc 仅为派生显示数据。

草稿目录跨回合保留，准备阶段不覆写草稿。因此新回合开始不能直接把磁盘旧文件或缓存画面当作本轮进展。需要关联作品、会话、当前执行和源摘要，优先复用既有派发事实；注意 `artifactAtSend` 的产物摘要与只读取引用素材的预览摘要不必同域，不能未经核对直接比较。若需要预览范围的起始摘要，它应是临时观察状态，不是新的持久读取证明。中途打开/重连需重新取得正在执行回合的来源和已有快照，不可一律等下一次文件变化。最终提交、下一回合开始和跨作品切换都应使旧显示任务失效。

本提案默认空闲时显示当前稿，不让外部修改或上轮遗留草稿自动取代可编辑画稿。现行 Spec 还支持空闲时查看外部编辑器写入的预览；删除独立入口会收缩这个入口，确认方案时应明确接受，或另行定义其呈现方式，不能默认为外部文件自动提交。

## 实施边界与验证

删除切换入口的工作量较小；包括连续显示、视口保持、执行结束衔接和旧草稿隔离的完整改动预计为中等范围，非单纯删除两个按钮，也无需重建渲染系统。落地时更新 Spec、会话范围规则/README 和实际变更的服务合同；讨论阶段不改写已确认目标。

验收应以真实 Electron 中的可观察画面和保存结果为准：首次无文件、有旧草稿的新回合、有效→无效→有效 YAML、图片后到及同路径替换、连续快速写入、写入期间缩放、提交成功、取消/失败/no_artifact、重连及跨作品切换。使用确定性信号验证中间稿可见且当前稿版本不变，提交后才恢复编辑；再用真实 Agent 确认实际写入粒度和端到端延迟。性能目标需在固定文档/素材规模下商定和测量，本次没有承诺时延。
