# 单一实时画布、版本编辑与黄金验收方案

Status: proposed
Translation: pending

## 摘要

本方案将 Artwork / Preview 收敛为唯一画布，把右上角改为独立“保存版本”按钮和历史入口；选择历史版本即以该内容为起点继续编辑。一个作品只有一个活动工作稿，人和 Agent 串行修改，Agent 写出有效 YAML 时原位展示，正式提交后恢复编辑；已保存版本不可变，切换前保护未存版本的修改。实现复用 BentoDoc、受限文件观察、独立 Git 历史和保存门禁，补充必要的版本来源及活动编辑上下文。用户随后明确要求开始实施；代码、回归、最终构建及原生版本流程已完成。最终构建的真实 golden 与同案续改经保留失败后的驱动恢复通过技术检查，捕获三份不同构建画面并验证版本来源、保护及导出一致性；人工视觉及交互体验验收仍待完成，本方案保留待验收状态，Spec 仍为 draft。

## 1. 范围与决策状态

用户要求取消双视图、展示 Agent 构建过程、直接从所选版本继续人机编辑，并要求以 golden case 最终验证。用户先授权完善方案，随后以“start implementing”授权实施及方案内验证；不包含提交或发布。未额外提出偏好时采用下文明确默认值；这些细则不伪称为逐项人工批准。

本方案承接[初轮分析](2026-09-18-unified-live-canvas.zh.md)，取代其中历史只读查看的建议，并拟替代[旧版本交互](../../implemented/feature/2026-09-12-design-version-history.zh.md)的“查看 → 从此编辑”两步。目标进入 [Spec](../../../../specs/graphic-design-platform.zh.md) 的 draft 修订；实现文档和范围规则在对应代码切片落地时更新，不能提前宣称新行为已存在。

本期只有一个活动工作稿和可回溯的版本来源。不增加命名分支、每分支独立未完成稿、合并、过程回放、多画板、版本缩略图、自动模型重启或第二套历史存储。空闲时外部编辑器或遗留 Agent 草稿不再有独立预览入口，也不自动替换当前稿；文件仍保留可读。

## 2. 用户模型与右上角

| 对象       | 定义与展示                                                                     |
| ---------- | ------------------------------------------------------------------------------ |
| 已保存版本 | 不可变的文档和确切素材快照，V1、V2 等编号按创建顺序稳定展示                    |
| 当前基准   | 工作稿源自哪个版本；未偏离时显示“V1”，偏离时显示“基于 V1 · 有新修改”           |
| 活动工作稿 | 唯一可编辑 BentoDoc；人工修改和 Agent 正式提交仍自动保存，不要求先创建版本     |
| 运行中画面 | 此工作稿所属回合的最新有效 YAML 派生渲染；只读且未提交，不成为另一份可编辑真相 |

右上角为轻量版本状态、独立“保存版本”按钮和现有历史按钮。历史保持平面列表，列出编号、时间、当前基准标记，以及有依据时的“基于 V1”或“切换前保留”；首期不要求命名，不画分支树。首次未存版本显示“当前稿”。

保存版本先 flush 已完成编辑，成功写入 Git 且绑定当前基准后显示新编号。相对所选基准没有内容变化时不创建节点；当前已有基准时按钮禁用，尚无版本的工作稿允许首次保存。不同来源但内容恰好相同不自动合并版本身份；自动保存状态与“有新修改”分别表示落盘和是否已存为版本。

## 3. 唯一画布的状态

| 阶段                     | 显示与操作                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| 空闲且就绪               | 显示活动工作稿，可编辑、引用、导出、保存版本和切换版本                                   |
| 准备派发                 | 阻止新人工修改并 flush；失败保留输入/编辑，确认未执行后恢复                              |
| 执行中，尚无本轮有效草稿 | 保持本轮开始前当前稿可见；首次创作为已有空白画布，不闪白、不显示旧草稿冒充进展           |
| 执行中，有有效草稿       | 原位显示最新有效画面；可缩放和平移，禁用编辑、引用、导出、存版本和切版本                 |
| 暂时半写或缺素材         | 保持上一有效画面；简短提示等待有效内容，诊断可查看，不逐事件刷红色错误或静默修复         |
| Agent 已结束、产物处理中 | 保持画面和只读，等待正式处理结果                                                         |
| 提交并加载成功           | 显示新工作稿，恢复操作；不自动创建历史版本                                               |
| 取消、失败或未提交       | 处理结束后显示最新确认保存的当前稿，保留草稿；普通 no_artifact 不制造失败提示            |
| 提交成功但画布加载失败   | 如实说明已保存但画布未加载；不得把旧预览解锁为新稿，重新加载走已有恢复路径而非重跑 Agent |
| 执行状态未知或重连中     | 保留最近可靠画面、暂只读；核对作品和回合后恢复，不能因 UI 断开而解锁                     |

执行中可以打开历史列表，但历史项不可切换；版本保护和禁用须由实际变更入口再次检查。停止后要等执行及产物处理结束才能切换。不将观看目标和编辑目标分开。多窗口共享同作品活动上下文；切换影响全部实例，有未保存/输入法组合内容的实例先共同 flush，失败不强制覆盖。

不恢复刷新按钮、导入按钮、来源路径横幅或结果卡。沿用既有执行状态，画布仅显示解释当前画面所需的简短状态。

## 4. 选择版本就是切换编辑起点

顺序固定为：冻结变更及派发 → flush 所有实例 → 校验目标及预期当前稿 → 在同一 Git 历史保护未存版本修改 → 原子更新当前文档和基准身份 → 发布对应 YAML → 加载全部实例 → 恢复操作。

- 点当前基准且有修改时，也意味着恢复该版本原内容；先保护修改。内容与基准均未变时为 no-op。
- 保护复用既有“切换前”节点；文档/素材已经有可达历史快照时不重复创建。保护节点可从同一列表选回；它不是每分支的独立未完成稿。
- 保护或目标校验失败：不切换。保护已成功但保存失败：保留保护节点，报告切换失败，不删除保护内容来隐藏失败。
- 文档已保存但投影或加载失败：如实显示实际基准，保持未就绪，阻止用旧文件派发；重开可恢复，不回退覆盖已落盘结果。
- 清除旧选区及引用，按新稿重建撤销/重做；普通作品标签切换继续保留编辑状态。撤销不跨越历史版本切换。
- 只切换画稿和 Agent 可读当前投影，聊天记录不回滚；旧 Agent 草稿、回执和无关文件保留。下一回合先读最新工作稿；旧草稿不因切换而被重置提交基线。

例如 V1 → V2 → V3 后选 V1，再编辑保存 V4，V4 的设计来源为 V1，V2/V3 仍可选回。运行中取消/失败默认显示本轮开始前已确认保存的工作稿，包含人工在所选版本上做的修改；异常外部保存时以实际 canonical 和冲突诊断为准，不强制写回旧基线。

## 5. 数据与持久化决定

继续使用 Molly 管理的每作品独立 `history.git`，隔离用户 Git。采用**线性 Git 保存顺序 + 显式设计来源**：保留全部版本可达和稳定编号，在新版本 Git 元数据中记录基准版本与保存种类，不把 Git 最新 parent 冒称为设计来源。旧版本没有来源信息时显示未知，不追溯猜测。

活动基准身份随现有 canonical 持久化封套保存，和文档原子更新；不进入 BentoDoc 元素或 Agent YAML，不创建平行工作稿/历史索引文件。普通人工与 Agent 保存保留当前基准，版本切换/保存节点绑定才改变基准。比较是否有新修改只比较文档及素材。没有身份元数据的旧当前稿先显示“当前稿”；旧版本、内容及编号仍可读，不凭相同内容猜测旧选择。

并发检查覆盖编辑上下文，不能仅凭相同画面内容让旧选择请求通过；实施时扩展现有 revision/变更合同，防止 V1→V2→V1 后迟到请求误绑定。Git 历史锁、作品锁及所有实例的 flush 使用明确一致的顺序，不能在持锁路径重入现有锁。

Git 发布与基准绑定是两个持久步骤：先使完整历史节点可达，再以预期当前上下文绑定。Git 元数据记录操作身份和捕获基线，同一次请求重试定位既有节点而非重复创建。中断后允许“版本已保存、基准尚未更新”，但不能出现基准指向未发布对象；仅在预期上下文仍匹配时补绑定，否则保留版本、报告未切换，不覆盖后续编辑。不新增通用事务台账。

不直接把 `history.ts` 的 parent 改为所选版本：现有列表和可达性采用 `--first-parent`，直接修改会使其他方向不可见。设计来源和创建顺序明确分开，真正多分支引用另行设计。

## 6. 实时展示实现与边界

复用 `design/source-path`、精确文件监听、`collectAuthoring` / `intakeAuthoring`、`SourceObservation`、隔离渲染和最终提交回执。界面只有一个画布，内部可保留当前稿编辑器与只读渲染面的隔离；预览不得进入 autosave/flush，不推进 canonical 或 Git，不触发 YAML 回写循环。

实时粒度是已落盘的有效快照，不是模型 token、工具参数或全部文件事件。合并事件优先追上最新状态；无效中间态不能清空画布、补齐结构或跳过不合法元素。素材身份包含确切字节，同路径替换也更新。技能只可建议自然阶段保存，不强制工具次数、固定顺序或为展示制造等待。

显示任务绑定作品、编辑上下文、回合、来源和观察代次。复用派发时文件事实隔离旧草稿；正式产物摘要与引用素材预览摘要不同域时不能直接比较。必要的预览起始摘要只用于显示来源，不成为读取证明或提交授权。无消费者时不持续渲染；中途打开及重连须从活动回合事实重建，不能把当时磁盘文件一律当作起始基线或一直等待下一次写入。

替换等待新画面及素材就绪，旧画面保持可见。保留缩放倍率与画布坐标中心，尺寸变化只做必要边界修正；新作品首次进入才 fit，不每次更新 fit。先复用完整快照重绘；实测不足再评估通用只读文档替换，不新增 Agent 专属 Bento 生命周期。

记录“完整有效文件及素材就绪 → 实际新画面可见”的延迟及合并数量。首期目标是在固定 golden 文档/素材规模和记录的 macOS arm64 环境下，停止写入后 2 秒内显示最新有效状态；这是待验证目标，不是现有性能事实。首次冷加载单独记录；连续写入不得无限使渲染作废。目标未达须在验收中列明并处理，不能只测 watcher 防抖时间。

## 8. Golden case：初次复刻与同案版本续改

沿用[冻结合同](../../../../e2e/KIMI-REPLICATION-ACCEPTANCE.md)：285×2000 的 MagSafe 支架参考图，SHA-256 `3f155040ce8152cd3e5808d000cbedb482307c1c1c1f4df68b6f50ae82baaa89`，初始提示词准确为 `复刻这个设计`，真实 Kimi Code CLI / K3 / Thinking High。不增加坐标、提取文案或修复提示，不种入解法；参考图和证据留在忽略目录。环境不可用时如实阻塞，不替换模型/供应商。

使用最终构建的真实 macOS arm64 OSS Electron 和隔离数据、工作区、端点；核验主进程/渲染器/CLI/Bento、模型和工具身份。复用已有 runner，新增 `unified-canvas` 阶段与下述证据；旧 `baseline|single-file` 驱动不能冒充支持本验收。旧 golden 仅作参考，不默认增加付费改前基线；改后必须有全新独立轮次。

### A. 固定复刻轮

1. 从新作品，通过正常附件/输入路径提交图片与准确提示词；分别记录附件送达和实际读图证据。
2. 从派发起观察唯一画布，记录有效源身份、显示身份、回合状态、canonical revision 和真实画面。至少捕获两份不同的非空有效构建画面，至少一份在 Agent 结束前可见；最终画面可作为后一份。不允许驱动改文件、扣住工具结果、加等待提示或重放预制步骤制造实时成功。
3. 模型只写一次且没有足够构建画面时，视觉/提交可分别判定，实时 golden 为未证实，整体不能 passed。合成测试不能补签真实过程；不自动重跑或覆盖本轮。
4. 自然完成，正式校验/回执后才恢复编辑；导出 PNG/JPEG、关闭重开再导出并核对文档/素材和同环境结果。原始复刻存为 V1，保留未编辑导出及哈希供视觉审核。

### B. 同案版本与人机续改

5. 原生控件修改可见标题、移动文字和调整图片裁切，自动保存并重开核对，再保存版本得到 V2。保留原始 V1；不能以图片铺底或隐藏文字通过可编辑性检查。
6. 历史点击 V1，一步回到其内容并可编辑，V2 仍完整可选。手工把所选可编辑标题改为 `GOLDEN-HUMAN`，等自动保存，用正常元素引用发送固定后续提示：`仅在我引用的标题现有文字末尾追加「 · Agent」，保留其他内容。` 这是同案扩展，不修改 A 轮固定提示或视觉结论。
7. Agent 应获得包含人工改动的最新工作稿，最终标题为 `GOLDEN-HUMAN · Agent`，其他文档内容和素材保持不变；执行时不能切换/存版本，实时画布继续工作。保存 V3，其设计来源为 V1，V2 保留；以实际 commit 身份断言，V1/V2/V3 是场景逻辑标记。
8. 再做未存版本的人工修改后切换 V2，验证自动保护、V2 原内容及保护节点可选回；重启核对基准、工作稿、来源和全部历史。最后切回 V1 导出，确认原始 golden 不变。

### C. 人审与交付

交付参考/原始导出完整长图、固定分区对比、可编辑复刻、实时录屏或连续画面、版本切换/保护证据及机器报告。报告分别列技术、实时、版本、人机续改、视觉、清理状态；全部通过且用户确认视觉高一致性及构建/切换体验可接受，整体才能通过。视觉只评价 A 轮未修改输出；自动指标或 Agent 自评不代替人审。

同案预计包含初始复刻和一次真实续改两次显式派发，不自动循环修复/重试。图像 generate/edit 总计遵循本任务五次预算，无配置不补默认模型。保留失败、取消、配置变化及所有模型/图像调用事实，付费 live lane 不加入无网络确定性回归。原始会话和秘密不得提交仓库。

## 9. 负路径、检查与完成条件

确定性测试覆盖：半写 YAML、缺失/替换素材、旧任务迟到、首次缺稿及旧草稿、快速更新合并、取消/失败/no_artifact、结束后处理、重连/中途打开、跨作品及多窗口、保护/保存/投影/加载失败、Git 发布后中断、重试幂等和旧存储兼容。使用显式信号、注入时钟和确定性夹具，不用真实睡眠、调度运气或网络。原生 E2E 验证实际画面、视口和变更门禁，包括运行与产物处理阶段的按钮禁用。

实施提交前运行对应测试、`pnpm check`、`pnpm format`、`pnpm run docs check`；E2E 驱动/元数据变化运行 `pnpm e2e:check`，harness/活动 P0 变化运行构建及 smoke；包边界或平台组合变化运行 `pnpm check:public-boundary`。冻结最终构建后执行 golden；随后影响输出、交互或链路的修改不能沿用旧构建通过结论。

## 10. 实施发现与当前验证记录
