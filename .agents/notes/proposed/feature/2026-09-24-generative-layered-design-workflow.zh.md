Status: proposed

## 摘要

Molly 的设计 Agent 能够编写可编辑的 `design.yaml` 作品，但缺少从需求到经过审视的分层设计的默认流程。已批准的[任务 Spec](../../../../specs/generative-layered-design-workflow.zh.md)把这套流程（需求整理、Pinterest 调研、草稿、依据选定草稿重新生成完整透明图层、重组与审视）写入 Skill，并配套带透明度选项的 JSON 图片编辑、沿用 Pi 原生的工具错误处理、沙箱加分类器的自动审批模式，以及可选的 Node alpha 辅助脚本。分段实验表明，透明参数真正到达服务端时 OpenAI Image 2.5 会返回原生 alpha，并在保留或合成素材上验证了导入、编辑、裁剪、保存/重开/导出以及内置 Agent 的校正；尚未跑过一次从需求到保存作品的完整流程，因此它是主要验收。本记录保留决定、证据和理由；Spec 是当前生效的方案。

## 问题与目标

负责人于 2026-09-24 定义核心流程：意图理解、灵感搜索、创意草稿与 Agent 择优、由图片模型拆解图层、YAML 重组、文字处理、整体审视、与用户素材和意图的一致性检查，以及最终打磨。目标是先跑通端到端流程，再优化回合长度、Token 和成本。

## 决定（负责人，2026-09-24–25）

- **规则范围。** 根 [AGENTS.md](../../../../AGENTS.md) 约束仓库开发，不禁止产品 Agent 的 Skill 推荐创作流程或重复调用图片接口。应用本身仍不强制任何创作步骤。
- **用 Skill，而非系统提示词或编排。** 一个入口 Skill（`graphic-design`）加若干专题参考；`imagegen` 仍按能力下发。修改每回合指针，要求 Agent 在设计前读取 Skill。不增加阶段控制器、第二调度器或系统提示词改动。
- **Agent 自主判断。** Skill 讲方法、收益、局限和示例，开放取舍交给 Agent。文字采用原生文本、位图或矢量形状由 Agent 决定。草稿由 Agent 择优；日后可增加 "auto" 选项区分 Agent 与用户选择。
- **生成而非裁剪图层。** 每个元素完整重新生成，包括被遮挡部分，因为裁剪会留下缺口，妨碍重新分层和手动编辑。参考图复刻采用同样方式，以参考图代替草稿探索。判断保真度时区分交付素材与设计参考；分层粒度按独立编辑价值决定。
- **模型。** 核心交付是一套可用的 Skill 方案。本轮以 OpenAI Image 2.5 为目标；Qwen Image 2.1 与 Seedream 5.0 Pro 后续接入（[#16](https://github.com/LeonEthan/molly-design/issues/16)）。不限制连接设置，撤回早先的三模型白名单设想。
- **灵感搜索**通过现有内置浏览器使用 Pinterest。
- 审视和校正暂**不限调用次数**。
- **原生工具错误。** 删除 harness 在已发出图片调用失败或 MCP 交付结果未知时终止运行的处理，两者作为工具错误返回 Agent。崩溃/重启不重放保护属于会话恢复，予以保留。
- **自动审批模式。** 代码能力是核心设计能力，因此按实际效果而非命令形式判断风险。shell 命令在接入 Molly 自有 bash 工具的 `@anthropic-ai/sandbox-runtime` 中免提示运行；越界请求（未知域名、请求离开沙箱）由 `pi-auto-approval` 分类器判断，拒绝、失败或超时时回退为提示用户。网络仅限预先放行的开发与设计域名。
- **验收。** 一次端到端可用性实验：通过 Molly 内置 Agent 从普通需求出发，得到保存、编辑、重开并导出的作品。早期"黄金复刻"实验属于上一阶段，不作为本任务验收。2026-09-25 曾决定复用分段证据而不再生成新作品，现被该验收取代。
- **单一 harness。** 新的执行使用内置 Pi harness（[Spec](../../../../specs/molly-embedded-pi-harness.zh.md)）。

## 证据

实验产物保存在仓库之外，不记录凭据或捕获的对话。调用次数：2026-09-24 共 11 次图片接口调用（8 次经第三方中转，3 次经本地反向代理），2026-09-25 1 次，均使用 `gpt-image-2.5-sunburst`；另有一次 Codex CLI 参考运行。

### 通过 Image API 获取透明度

| 接口 / 请求体                 | 透明请求方式                                  | 结果                                                    |
| ----------------------------- | --------------------------------------------- | ------------------------------------------------------- |
| generate，JSON                | 仅提示词                                      | RGBA 抠图；实心像素 alpha 为 253                        |
| edit，multipart               | 仅提示词                                      | 一次 RGBA；一次 RGB 且画出了棋盘格                      |
| edit，multipart               | `background=transparent`、`output_format=png` | 两个代理均为 RGB；其中一次报告 `"background": "opaque"` |
| generate，JSON                | 仅参数                                        | RGBA；报告 `"background": "transparent"`                |
| edit，JSON 携带 data URL 图片 | 同样参数                                      | 两次均为 RGBA；报告 `"background": "transparent"`       |

OpenAI 的 [图片编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)与[图片生成](https://developers.openai.com/api/reference/resources/images/methods/generate)接口文档说明 2.5 模型在 `png`/`webp` 输出时支持透明背景，且没有单独的去背景接口。被测代理丢失了 multipart 字段；OpenAI 官方端点是否如此未测试。JSON 编辑可避开此问题。另有三次纯绿色色键编辑在本地成功抠图（柔和蒸汽得以保留，边缘有一像素色边）；由于原生 alpha 可用，该后备方案不随产品提供。

生成的图层会偏离草稿：一只杯子返回时放大约 20% 并发生位移；Codex 参考运行（对同一海报做 8 次内置 `image_gen` 编辑，7 个透明图层均为原生 alpha）不得不重新摆放每个图层，咖啡豆大小约为原来两倍。在提示词中写明坐标并不能保持布局。

### 代码核查（2026-09-25）

- 已发出的图片调用失败或工具报错时，harness 会终止运行（[acp-adapter.ts](../../../../packages/harness-pi/src/acp-adapter.ts)）；MCP 交付结果未知时同样终止（[tool-operation-journal.ts](../../../../packages/harness-pi/src/tool-operation-journal.ts)）。
- 设计运行中，除已授权站点上的浏览器调用外，每次工具调用都会提示（[worker-main.ts](../../../../packages/harness-pi/src/worker-main.ts)）；Molly 用宿主审批包装自有工具（[approved-tools.ts](../../../../packages/harness-pi/src/approved-tools.ts)）。
- 锁定的 Pi SDK 0.85.1 在 `createBashToolDefinition` 上提供 `BashOperations`，正是 Pi 官方[沙箱示例](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/sandbox/index.ts)使用的钩子。
- 导入只收录被引用的图片、图片填充和字体素材（[intake.ts](../../../../packages/design-authoring/src/intake.ts)），因此 `media/` 中未使用的草稿不会进入提交的作品，但仍留在磁盘上。
- 每回合指针把 Skill 称为"可选辅助"（[skills.ts](../../../../apps/cli/src/design/skills.ts)）。

## 考虑过的替代方案

- 每个阶段一个 Skill，或一个超大 SKILL.md：指针只指向一个 Skill，各阶段共享状态，大文件会在小改动时加载无关指引。
- 裁剪加干净底板的分层方式：被遮挡元素仍不完整。
- 以色键作为主要透明方案：本地可行，但依赖键色选择，且损失柔和阴影的保真度；经 JSON 请求原生 alpha 可用。
- 保留 multipart 编辑、仅增加字段：被测代理会丢弃这些字段。
- 把图层重新采样回全画布：YAML 边界即可摆放裁剪后的图层，无需重新编码。
- 图片调用失败时停止运行：负责人否决，改为沿用 Pi 原生工具错误。

## 风险与限制

- 回合长、读图多；不限调用次数，每次调用都可能计费。工具错误沿用原生行为后，结果未知的调用可能被重复发起并重复计费。
- 图层是重新绘制而非复制；被遮挡内容是推测生成的；摆放依赖 Agent 判断。
- GPT Image 输出尺寸须为 16 的倍数、长宽比不超过 3:1 且不少于 655,360 像素；极端画布需另行处理。
- 生成的实心像素 alpha 为 253–254，叠放时略微透明。
- 沙箱的放行域名和可写缓存需要调优；分类器可能受到 Agent 读取的不可信内容影响。
- Agent 的草稿择优和审视仅供参考；质量由人判断。

## 验证限制

现有证据覆盖基于保留、合成或单个新生成素材的分段环节，使用的是代理而非 OpenAI 官方端点，每个合成评审用例只运行一次。本任务尚未修改 Molly 运行时代码。尚未进行从需求到保存作品的完整运行，也未调用 Qwen、Seedream 或 OpenAI 官方端点。本地实验文件不在仓库内，无法据仓库复核。
