# 画布点选编辑：调研与分阶段提案

Status: proposed
Translation: current

[English](2026-10-10-canvas-click-to-edit.md)

## 摘要

Molly 画布能精确引用选中元素，但每个 AI 请求都要在对话面板中完成，只能以整个元素为目标，一次只能处理一个目标，且目标处没有反馈。Lovart、Higgsfield 与 Codex 应用都把请求和结果留在被点击的对象处。本记录保存该调研和五阶段提案；所有者于 2026-10-10 批准第一阶段（A），已在[画布内联提问](../../implemented/feature/2026-10-10-canvas-inline-ask.zh.md)中实现。B–E 阶段仍为提案，调研来自公开文档，未经实际上手使用。

## 调研（公开来源，2026-10-10）

| 产品 | 目标 | 提示输入位置 | 返回结果 |
| --- | --- | --- | --- |
| Lovart | Mark（M 或 Cmd/Ctrl 点击）无需蒙版识别图片内物体，每次提示最多 10 个标记；Edit Elements 把平面图拆成可移动图层；Edit Text 改写图片内文字 | 标记出现在输入框；Tab 打开 Quick Edit 预设或自定义提示 | 原位、局部修改目标；撤销与编辑历史 |
| Higgsfield | Draw-to-Edit 在图上粗略涂抹/草绘；Layers（分层、改字、区域编辑、重打光、去背景） | 提示加显式模型选择 | 仅重绘涂抹区域 |
| Codex 应用 | 批注模式：点击元素或拖选区域 | 在目标处写评论并保存为编号标记；Adjust 实时预览字体/颜色/间距 | 在对话中统一处理评论，按编号引用 |

来源：Lovart 高级 AI 编辑文档与更新日志（Touch Edit、Edit Element、Edit Text、Chat with Canvas）、Lovart 博客 “iteration loop ai design touch edit”、Higgsfield Layers 与 Nano Banana Pro Inpaint 页面、Codex 内置浏览器文档与发布说明。Higgsfield 的区域工作流以及 Codex 发给 Agent 的数据内容没有公开文档。

## Molly 的差距（2026-10-10）

1. 请求要离开点击处去完成。
2. 无法以小于元素的范围为目标。
3. 一次请求一个目标；没有成批的编号批注。
4. 运行期间整块画布只读，没有针对目标的进度；完成后看不出哪些元素变了，也看不出选区外元素是否被改动。
5. 所有元素类型的 AI 动作都相同。

## 阶段

- **A. 内联提问**——已实现（见上方链接）。
- **B. 编号图钉，一次批量回合。** Cmd/Ctrl 点击放置带各自说明的编号图钉；“发送 N 条批注”以一个回合携带 N 个引用，只产生一个“Molly 修改前”恢复点。复用多引用解析。符合现有 Spec 意图。
- **C. 图片内标记。** 在选中图片上点、框或涂抹，标记绘制到副本上作为参考图附带（“只修改标记处”），经现有图像编辑工具执行。只新增带标注的参考图，从而不违反 Spec 的“无蒙版编辑器”。自动物体识别（Lovart Cmd 点击）不在范围内：需要分割模型。改变 Spec 意图。
- **D. 目标处反馈。** 运行时在被引用元素上显示工作中轮廓；完成后显示逐渐淡出的“已修改”轮廓、按住对比“Molly 修改前”，以及基于元素 ID 的提示性差异，报告选区外的改动，不阻断也不修复。改变 Spec 意图。
- **E. 按元素类型的动作。** 按类型提供预设（去背景、替换物体、重打光；“让文字可编辑”以补充 `textCopy`；经分层工作流“拆成图层”），并在内联提问中提供 Tab 预设。只提供工具真实具备的能力。符合现有 Spec 意图。

刻意排除：变体/候选网格（候选工作流已退役）、运行时仅锁定选中元素（Spec 要求同一作品串行编辑）、静默把过期引用迁移到新修订（Spec 要求明确提示选区过期）。

建议顺序：A → D → B → C → E。建议指标：从选中到发送的时间、从画布发起的 AI 编辑占比，以及选区外差异提示在设计质量评测用例上的触发频率。
