选服务商后只填 Key：AI 模型与图像模型连接

方案 v3 + 高保真原型 · 2026-10-28 · 代码基线 main 7a6794a4（feat(harness-pi): add Kimi K3.1 Pro on Pi 1.4.0）· 只读调研：没有改源码，没有提交、推送，也没有操作 GitHub。标 【未验证】 的内容还没在代码或真实服务上核实过。

结论速览
  • AI 模型表单已经基本做到"只填 Key"。对 9 个 API Key 服务商，当前代码在选中服务商时就预填官方 URL（applyProviderChoice → PROVIDER_PRESET_DEFAULT_BASE_URLS），URL 收在「Advanced」里；模型默认是「All N」；名称默认取服务商名；保存只要求 Key。唯一明显的缺口在 Kimi Code：设置页有登录入口时，Kimi Code 的 Key 入口只能从「Sign in with a plan › Kimi Code › Use an API key instead」进去，要多走两步。
  • 真正的缺口在图像表单。新建时 URL 是空的（createImageConnectionFormDraft），一填 Key 就报 "Enter a base URL."；Model 必须手动输入。
  • 和规范有一处冲突。Spec（specs/graphic-design-platform.zh.md「内置图像工具」）和根 AGENTS.md 都要求图像模型"由用户必填、产品不设默认模型"。所以本方案推荐一键选择的候选模型 chip，不预选任何一个：用户点一下就行，不用打字，也不算产品默认值。如果要预选默认模型，就得先改 Spec 和 AGENTS.md，见 D4。
  • 不改共享层、main 进程、存储、运行时，也不新增 IPC。AI 表单改 1 个组件文件，图像表单改 1 个组件文件再加 2 个 locale 文件。

1. 问题与边界

要解决的问题

用户使用官方账号时，在 AI 模型连接和图像模型连接两个表单里点选服务商（例如 Kimi Code、OpenAI、阿里云百炼）后，唯一需要输入的是 API Key。Base URL 预填为官方地址，收在默认折叠的「Advanced」里，需要时可以改成自定义地址。模型由我们给出候选，或者在校验 Key 时自动列出，用户不需要手动输入 URL 或模型名。

做

  • AI 表单：在设置页里，Kimi Code 的 Key 入口直接放进 API key 组。折叠的「Advanced」旁边显示一行摘要（地址 · 模型范围），让预填的值看得见。
  • 图像表单：新建时按协议预填官方 URL，切换协议时跟着切换（前提是用户没改过 URL）。主区域的 Model 文本框换成候选 chip，点一下就选中；手动输入模型名的文本框移进「Advanced」。
  • 引导流程的 providers 步骤复用同一组件（providers-screen.tsx L483/L490，variant="panel"），所以自动获得同样的行为。

不做

  • 不按 Key 前缀推断服务商，不新增服务商，不改 OAuth（ChatGPT 和 Kimi Code 的登录流程原样保留）。
  • 不改运行时、凭据存储、IPC，不改 connection-check.ts、model-discovery.ts、embedded-harness.ts、image-connection.ts。
  • 已保存的连接不迁移、不改写：只有 stored === undefined 时才预填。
  • 不改会话里的模型选择器；openai-compatible（Custom）的流程不变。

2. 方案

复用阶梯（按 AGENTS.md 要求列出）：① 直接复用：PROVIDER_PRESET_DEFAULT_BASE_URLS、applyProviderChoice、PROTOCOL_COPY.defaultBaseUrl、ModelSuggestions、ModelChecklist、ConnectionCheckError/Badge、useConnectionCheck、现有 locale 文案。② 改造后复用：在 PROTOCOL_COPY 里加候选模型；ModelSuggestions 的 chip 样式复用为候选 chip；Advanced 触发按钮加摘要。③ 借鉴模式：「Use the default endpoint」按钮照搬 AI 表单的做法。④ 新建：不需要。
没有采用的做法：v2 提出的共享层 IMAGE_PROVIDER_PRESETS / RECOMMENDED_MODELS。前者目前除了这个组件没有别的使用方，按 AGENTS.md "先复用模块再加协议/存储" 的要求不该进共享层；后者和现有的「All 模型」默认值、"不从校验列表预选" 的注释（L583–586）以及 Spec 都冲突。另外，用服务商磁贴替换图像表单的 SegmentedControl 没有收益：只有两个协议，而且分段控件已经对应到服务商了。

2.1 AI 模型表单

改动文件：packages/components/src/components/settings/model-connection-setting.tsx、packages/components/tests/model-connection-setting.test.tsx、packages/components/src/stories/ModelConnectionSetting.stories.tsx。locale 不改，复用 settings.models.summary.* 和 endpointLabel。

  1. Kimi Code 的 Key 入口始终放在 API key 组。ProviderPicker 里的 keyProviders 改成总是包含 'kimi-coding'，显示为 "Kimi Code (membership API key)"。这和 OpenAI 的做法一致：ChatGPT（登录）和 OpenAI（Key）本来就各有一个磁贴。登录磁贴原样保留，「Use an API key instead」也保留。
  2. Advanced 折叠时显示摘要。触发按钮后面追加一行弱化文字：{endpointLabel(endpoint)} · {summary}，例如 api.kimi.com/coding/v1 · All models。summary 直接沿用 ModelConnectionRow 已有的表达方式（All models / N of M models）。
  3. 其余不变。URL 已经预填，模型默认 All，名称默认取服务商名，保存只要 Key。模型清单本来就在 Advanced 里（D3）。

2.2 图像模型表单

改动文件：packages/components/src/components/settings/image-connection-setting.tsx、packages/components/tests/image-connection-setting.test.tsx、packages/components/src/stories/ImageConnectionSetting.stories.tsx、locales/en.json、locales/zh_CN.json，以及 specs/graphic-design-platform.zh.md/.md 的措辞（见 D4）。

  1. 新建时预填 URL。createImageConnectionFormDraft(undefined) 返回 baseUrl = PROTOCOL_COPY['openai-images'].defaultBaseUrl。有 stored 时行为不变。
  2. 切换协议时跟着换 URL。扩展 applyImageProtocolChoice：当前 URL 为空或等于旧协议的默认地址时，换成新协议的默认地址；用户自定义的地址保留不动。现有的清空 Key 行为保留，model 也一并清空（候选模型因协议而异）。
  3. 候选模型 chip。给 PROTOCOL_COPY 加上 candidateModels。主区域的 Model 字段改为一组单选 chip（role="radio"），默认不选中任何一个。如果校验返回了列表，不在列表里的候选打上 settings.models.picker.notListed 标签（复用现有文案）。
    • OpenAI Images：gpt-image-2、gpt-image-1。仓库测试里用得最多的是 gpt-image-2（29 处）；这是否就是 OpenAI 当前官方的模型名 【未验证】。
    • DashScope：qwen-image-2.1、qwen-image-2.0（出现在 design-image-tool.test.ts 和 model-connection-store.test.mjs 里）【未验证】。
  4. Advanced 收纳 URL 和自定义模型。折叠时只显示摘要 {host}{path} · {model || "—"}；展开后是 Service address（加「Use the default endpoint」按钮）和「Other model ID」文本框，ModelSuggestions 跟着移进来。URL 不合法、或已选模型不在服务列表里时，自动展开 Advanced（沿用现在 open 的判断方式）。
  5. 保存条件不变（imageConnectionCanSave），仍要求 model 非空。没选模型时，主区域显示 "Choose a model."。
  6. 新增 locale 键（中英各一份）：settings.imageConnection.chooseModel = "Choose a model."；settings.imageConnection.otherModel = "Other model ID"；settings.imageConnection.modelCandidates = "Model"。其余文案全部复用。

2.3 共用部分

  • 校验逻辑原样保留：Key 只在 main 进程里使用，不进渲染进程以外的地方，不需要新 IPC。
  • 存储格式、revision 规则、harness 都不改。只有新建草稿会预填；编辑已有连接时，显示的就是已保存的值。

3. 原型

原型按真实组件的 Tailwind 类和亮色主题 token 复刻：卡片 rounded-2xl border-border/40 bg-card，输入框 32 px、bg-input-field，主按钮用 soft-lime 的 primary 填充配深色文字。界面文案用 en.json 里的现有字符串，新增的用 斜体 标在注释里。蓝色虚线框和编号是报告自己的标注，不属于 UI。

#问题建议备选与影响
D1每个 AI 服务商的默认模型不设默认模型，保持 All。会话里由用户自己选模型（现有设计）；连接表单不需要预选，所以也不需要 v2 的 RECOMMENDED_MODELS。如果确实想让选择器先显示一个推荐模型，那是会话选择器的需求，不属于这次。参考 pi-ai 1.4.0 的目录：kimi-coding 有 k3 k3-256k kimi-for-coding kimi-for-coding-highspeed，overlay 再加上 k3.1-pro；moonshotai 有 kimi-k2.6 kimi-k2.7-code kimi-k2.7-code-highspeed kimi-k3。打包进应用的 model-catalog.json 是构建时生成的、不在仓库里，与这份列表是否完全一致 【未验证】。
D2首批图像服务商只做 OpenAI 和阿里云百炼。它们对应现有的两个协议；其他兼容服务走 OpenAI Images 协议加 Advanced 自定义地址。加 Kimi 或其他服务商就是新增服务商或协议，不在本次范围内。候选模型名（gpt-image-2/1、qwen-image-2.1/2.0）需要你确认 【未验证】。

D4图像表单：候选 chip 不预选（B），还是预选默认模型（A）B。符合 Spec "产品不设默认模型" 和 AGENTS.md "user-required model and no product default"，用户点一下就行。Spec 里"用户配置 URL"的措辞需要改成"官方 URL 预填、可在 Advanced 中修改"；Spec 本来就是 draft 状态。A 少点一下，但要先修改 Spec 和根 AGENTS.md 的约束，并获得你书面批准；另外默认模型过期时，会造成"静默错误"的风险。
