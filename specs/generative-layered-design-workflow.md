## Goal

Given a brief or reference image, Molly's embedded Agent completes the design process from intent understanding to final polish, delivering a layered artwork that users can edit, save, reopen and export. The image model creates the design; the user chooses among three complete design options, and the Agent reproduces the chosen one as faithfully as possible in editable form. When choosing, the user may instead ask for the chosen option as one whole image, which is saved and exported like any artwork but whose copy and layout are not editable. The user may instead ask for the layout first: the Agent draws an editable layout on the canvas and, once the user has adjusted and confirmed it, generates one design from that layout and reproduces it in editable layers. **Make the end-to-end path work first; optimize turn length, tokens and cost afterwards.** The core deliverable is a complete, usable skill solution. This round targets OpenAI Image 2.5 through the user's configured connection and explicit model; compatibility with other image models follows later without restricting the connection settings now.

This revision requires the Agent to follow the Skill workflow, using the user's design thinking and references first. Inspiration research sets a direction, so it is exempt only when no new direction is set: the user prescribes a concrete template or reference target to follow without new inspiration and the inspected target supports the requested work, or a bounded edit keeps the existing direction. Implementation and acceptance evidence are summarized in the final Evidence section; earlier failed runs remain recorded without being relabelled as passes.

## Core workflow

1. **Intent understanding:** understand the design purpose and the user's design thinking, including the category the work competes in and the one message it must send; organize content, copy, materials and supplied references. The canvas size comes from the brief: a stated size or format, the artwork the request refers to, or where the work will be seen; an empty placeholder canvas carries no size intent, and an unsettled size that changes the composition is asked. When a new design or redesign leaves gaps that would change the direction, ask once through the structured question tool when it is available, with options and a recommended default; otherwise proceed on reported assumptions. Write a direction sentence and two to four direction words as the working yardstick for later stages; they are not a user approval step.
2. **Inspiration and research:** prioritize and inspect the user's inspiration and references. Research visual content through one design site such as Pinterest, with at least one search aimed outside the category and current design feeds, in one bounded pass searched from the direction words (at most three searches, scrolling two to four screens each, and a search may extend along a promising thread) before composition selection or creation: survey the result grid to pick, then save at most three picks and view each one, without opening detail pages for rejected candidates; save the few inspiration images the design options may use. Skip it only when the user explicitly prescribes a concrete template or reference target to follow without additional inspiration and the inspected target supports the requested visual decisions, or a bounded edit keeps the existing direction, and no additional research is requested. A topic, broad style words, supplied assets or the Agent's own concept do not establish this exception. Follow explicit user restrictions on networking and report resulting limitations; unavailable tools do not constitute a reference-based exception. Necessary factual verification remains separate.
3. **Design options and user choice:** keep a few references, each contributing one quality rather than its objects or layout. Generate three complete design options with the image model, each a finished poster including its headline and key copy, differing in concept or composition. Options are created from images and text, not text alone: the source image when there is one (supplied delivery assets or the artwork being redesigned), plus one or two inspiration images the Agent chooses from its research, with the prompt naming the quality each lends and forbidding its objects, text and logos; a rendered native blockout may steer layout. An option that is recognizably one reference with new copy fails. The Agent shows the options with a recommendation and, in the same reply, asks whether to deliver the chosen one as editable layers (the default) or as one whole image, unless the brief already names the form; it then ends the turn for the user's choice without changing the artwork and continues in the turn where the user chooses. If the user asks the Agent to decide, it generates only one recommended option and continues delivering it in the same turn, as editable layers unless the brief asks for a whole image. A whole-image delivery places the chosen option as a single image element covering the canvas, skips stages 4–6 except checking its copy letter by letter against the brief, reports every wrong or missing line and that the wording is not editable, and continues with stages 7–9.
4. **Layer decomposition:** reproduce the chosen design rather than reinterpret it: a background plate edited from the design with foreground objects and text removed, and complete foreground objects isolated from the design, including occluded portions. A supplied face, product or logo the user requires to stay exact is isolated from the source when the design altered it.
5. **YAML recomposition:** write `design.yaml` to assemble the layers into an editable artwork at the positions and sizes measured from the chosen design.
6. **Text handling check:** take every line of wording from the brief or source, never from the design image, including fine print the design dropped, and match how the chosen design sets it. Copy that native text reproduces faithfully stays editable text; lettering it cannot reproduce (drawn letterforms, texture, outlines, letters fused with a badge) becomes an image isolated from the design at any size, its characters checked against the source.
7. **Holistic review and adjustment:** render the current artwork through Bento, actually inspect the returned image and compare it with the chosen design, then regenerate or edit layers that need adjustment. Visual changes require another native preview; external approximations are supplementary evidence.
8. **Consistency check:** compare against supplied materials, copy line by line, intent, the chosen design and, for a new direction, the direction words; correct deviations with the image model or artwork edits.
9. **Final review and polish:** refine the result and report in proportion to the request. Never claim a check, render or save that did not happen. Always report unmet requirements, blocked steps and remaining deviations; distinguish prepared authoring files, a natively reviewed current draft and an application-confirmed save only when that difference matters to the user.

Open briefs follow all nine stages. A redesign of a supplied or open artwork is a new design: the source supplies content, copy and delivery assets, not the composition. For a user-prescribed template or reconstruction, the inspected reference serves as the chosen design; bounded edits, limited to named local changes, use the prescribed existing artwork as the design and layer baseline. These are explicit branch actions, not blanket stage exemptions. Templates, reconstructions and bounded edits always work in editable layers; only new designs and redesigns offer the whole-image form. Each branch uses the same research rule, preserves unaffected work and returns to native review after changes.

**Layout-first path:** when the brief asks for the layout first or to generate only after the layout is confirmed (including the wording the home page's "Layout first" starter fills in), a new design follows this path instead of three options. Stages 1–2 run as usual, with the Agent first asking about style direction and then researching. The Agent then draws the layout on the canvas in native elements: each image region is a translucent box with a content label, and the headline and key copy are written as final text. It ends the turn without calling the image model. The user moves, resizes, adds, deletes or relabels regions and asks for generation in a later turn. The Agent reads the user-edited artwork, passes the rendered layout as the first input image with each region's content and position in the prompt, and generates one design from images and text, without offering options. It delivers editable layers unless the brief asks for a whole image. Reproduction takes position and size from the layout and appearance from the generated design: layout text stays as final text, extracted objects return to their region boxes, and the boxes and labels are deleted before delivery. The reply reports where the result departs from the layout. The confirmed layout stays in the design history, so the user can restore it and generate again. Layout conventions align with MOSS-Image layout input: region boxes are not rotated, one label summarizes the scene and style, and image regions and copy map to object and text items. At generation a bundled helper derives MOSS layout JSON from the current artwork (pixel coordinates in yxyx order with the canvas center as origin, size scaled to multiples of 16) and puts it in the prompt with the rendered layout. The JSON is a derived view and is not stored.

## Design approach and responsibilities

- Put the required workflow, branch conditions and completion criteria in the existing design Skill entry; place techniques in focused references linked at their point of use. The Agent follows workflow dependencies and explicit repair loops, choosing methods and useful iterations within user constraints. Remove blanket permission to omit or freely reorder stages. The application adds no stage controller or mandatory creative checkpoints.
- Ground factual copy in user-supplied or verified information. The [harness environment context](molly-embedded-pi-harness.md#responsibilities-and-state-authority) supplies the current clock; file modification times do not establish today's date. Add an unspecified event's calendar date only after establishing the intended year and verifying the date; otherwise retain accurate coarser wording or omit it.
- Reference reconstruction also produces complete layers; the supplied image replaces the design options. Local edits remain focused on the user's request.
- Authoring checks, native preview and final collection must agree on supported asset admission. Known built-in asset-size, format, font-load and rendering failures provide safe, actionable diagnostics; a generic external error must not be treated as proof of a desktop connection failure. Check custom fonts on the first renderable draft before detailed typography. No silent font conversion or substitution is added.
- Native review and final saving are different observations. Collection follows the Agent's natural end, so the Agent reports what it has verified without waiting for or anticipating that turn's later save receipt. A partial result may still be collected under existing schema, asset and version rules; a visual limitation is not an application save gate. Never relabel a failed native review as successful because an external composition looks acceptable.
- Distinguish delivery assets from design references and choose layer granularity by independent editing value. Leave fidelity, completion, shadow/steam grouping and other open choices to the Agent, without exhaustive case rules or an asset-redraw approval process. The Skill may recommend breakable design defaults drawn from observed failures (focal scale, margins, type scale, copy placement and legibility over images) and use them as the review checklist, including that every signature motif connects to the subject or message; the Agent may depart from them with a reason, and the application enforces none.
- When the user rejects a direction in a later turn, the Agent first checks the rejection against the direction words: if they still hold, it reinterprets them visually and says what changed; if not, it returns to intent understanding and asks one question about what dissatisfies the user.
- Teach side-by-side, overlay, local-difference and light/dark-background comparisons that are executable with shipped tools: native render plus image reading, and the Node helper below. Guidance must not depend on Python or other runtimes absent from a user's machine. Human judgment establishes visual quality; pixel scores do not replace it.
- **Tool errors follow Pi's native behavior.** A failed or uncertain image call returns to the Agent as an ordinary tool error, and the Agent decides what to do next. The application adds no run stop, retry fence or retry of its own for tool errors. Restoring a crashed or restarted run still never replays an already-dispatched call; that is session recovery, not tool-error handling.
- **No permission prompts.** Code execution is a core design capability. Since 2026-10-01 built-in Molly runs use Pi's default of no permission checks, with the deterministic `cc-safety-net` floor that blocks known destructive commands without prompting ([harness Spec](molly-embedded-pi-harness.md#models-credentials-and-permissions)). Designers do not choose a permission mode; the per-call Ask mode stays retired ([#10](https://github.com/LeonEthan/molly-design/issues/10)). The earlier auto-review mode is superseded.
- Reuse the embedded Agent, image tools, native rendering and save path. BentoDoc remains the single editable truth, with YAML for Agent authoring. Preserve the read-only, commit and version boundaries.

## Acceptance

1. **End-to-end usability run (primary):** after implementation, start one new design through Molly's native interface with the embedded Pi Agent, the configured OpenAI Image 2.5 connection and no permission prompts, giving only a plain brief without stage instructions. The Agent should read the Skill, use supplied design thinking and references first, actually research design-site visuals when the explicit exception does not apply, show three design options and stop for the user's choice, then after the choice generate transparent layers from the chosen design, recompose them in `design.yaml` and inspect current native renders. Verify the application's subsequent save receipt. The user then independently edits a lower layer, saves, reopens and exports. Record the reference exception, if applicable, the observations informing design decisions, image calls, tool errors and how the Agent handled them, remaining permission prompts, elapsed time and visible deviations. Human judgment decides visual acceptance; a failed run is kept and reported, not relabelled.
2. **Interfaces and assets:** extend the existing MCP→request→asset-import tests with synthetic responses for parameters, source/mask data URLs, alpha and published assets; a synthetic provider error reaches the Agent as a tool error without ending the run. Script tests cover retained pixels, offsets, optional trims, comparison sheets and source preservation. Test observable behavior only.
3. **Workflow and failure branches:** check a prescribed template without new inspiration, a reference that still requests a new composition, a bounded edit preserving the prescribed artwork and its direction without inspiration research, and a new design whose user picks the whole-image form, which must ask for the form in the options reply, deliver a single covering image without layer reproduction and report the uneditable copy, and the layout-first path, which must ask about style, end the turn after drawing the layout, generate exactly one design after confirmation, keep text and object position and size from the user-adjusted layout, prompt with the helper's MOSS layout JSON, and delete the layout boxes. The same research predicate governs each branch. Deterministic tests cover asset-limit diagnostics and consistent admission, font/render failure categories and packaged Skill material; actual Agent runs establish whether it follows the workflow. Distinguish a stale preview after an edit, failed native rendering, and a failed application save rather than claiming any of them completed.
4. **Evidence limits:** the earlier segmented MVP results support the plan but do not replace end-to-end acceptance. Do not claim general visual reliability from one run. Golden-replica experiments from the earlier phase are not acceptance for this task.

## Out of scope

Turn-length, token and cost optimization; automatic denoising or placement; dedicated comparison UI; permission prompts or review of Agent actions; new orchestration or storage; a layout-mode switch, slash commands or a separately stored layout data format; a MOSS-Image image connection; WebP and general codec expansion. Bento's fractional-scale crop rendering issue is tracked in [#15](https://github.com/LeonEthan/molly-design/issues/15), and Qwen/Seedream integration in [#16](https://github.com/LeonEthan/molly-design/issues/16); both remain separate follow-ups.

## Open questions

- The tested journey no longer presents the initial temporary-path and attachment-prompt blockers. Record any new domain or cache failures separately; this does not establish compatibility with arbitrary commands or destinations.
- Without permission checks, untrusted content the Agent reads (web pages, briefs) can steer any command the user could run; `cc-safety-net` blocks only known destructive patterns. The accepted run predates this change and used auto-review.
- With native tool errors, an uncertain image call may be repeated by the Agent and billed twice. Preserve unknown outcomes and record any subsequent Agent calls; the application adds no automatic paid retry.
