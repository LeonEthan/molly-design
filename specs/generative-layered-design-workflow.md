## Goal

Given a brief or reference image, Molly's embedded Agent completes the design process from intent understanding to final polish, delivering a layered artwork that users can edit, save, reopen and export. **Make the end-to-end path work first; optimize turn length, tokens and cost afterwards.** The core deliverable is a complete, usable skill solution. This round targets OpenAI Image 2.5 through the user's configured connection and explicit model; compatibility with other image models follows later without restricting the connection settings now.

This approved revision requires the Agent to follow the Skill workflow, using the user's design thinking and references first. Additional inspiration research is exempt only when the user prescribes a concrete template or reference target to follow without new inspiration, and the inspected target supports the requested work. Implementation and acceptance evidence are summarized in the final Evidence section; earlier failed runs remain recorded without being relabelled as passes.

## Core workflow

1. **Intent understanding:** understand the design purpose and the user's design thinking; organize content, copy, materials and supplied references.
2. **Inspiration and research:** prioritize and inspect the user's inspiration and references. Research design-site visuals such as Pinterest before composition selection or creation unless the user explicitly prescribes a concrete template or reference target to follow without additional inspiration, the inspected target supports the requested visual decisions, and no additional research is requested. A topic, broad style words, supplied assets or the Agent's own concept do not establish this exception. Follow explicit user restrictions on networking and report resulting limitations; unavailable tools do not constitute a reference-based exception. Necessary factual verification remains separate.
3. **Creative generation:** write prompts, generate several full-image composition drafts, and let the Agent select the best.
4. **Layer decomposition:** use the selected draft as a reference to regenerate complete elements individually with the image model, including occluded portions.
5. **YAML recomposition:** write `design.yaml` to assemble the layers into an editable artwork.
6. **Text handling check:** decide which text becomes editable text and which is better represented as an image or vector.
7. **Holistic review and adjustment:** render the current composition through Bento and actually inspect the returned image, then regenerate or edit layers that need adjustment. Visual changes require another native preview; external approximations are supplementary evidence.
8. **Consistency check:** compare against supplied materials, copy and intent; correct deviations with the image model or artwork edits.
9. **Final review and polish:** refine the result and accurately report completed checks and remaining deviations. Distinguish prepared authoring files, a natively reviewed current draft, and an artwork whose save is confirmed by the application.

Open briefs follow all nine stages. For a user-prescribed template or reconstruction, the inspected reference serves as the selected composition; bounded edits use the prescribed existing artwork as the composition and layer baseline. These are explicit branch actions, not blanket stage exemptions. Each branch uses the same research rule, preserves unaffected work and returns to native review after changes.

## Design approach and responsibilities

- Put the required workflow, branch conditions and completion criteria in the existing design Skill entry; place techniques in focused references linked at their point of use. The Agent follows workflow dependencies and explicit repair loops, choosing methods and useful iterations within user constraints. Remove blanket permission to omit or freely reorder stages. The application adds no stage controller or mandatory creative checkpoints.
- Ground factual copy in user-supplied or verified information. The [harness environment context](molly-embedded-pi-harness.md#responsibilities-and-state-authority) supplies the current clock; file modification times do not establish today's date. Add an unspecified event's calendar date only after establishing the intended year and verifying the date; otherwise retain accurate coarser wording or omit it.
- Reference reconstruction also regenerates complete layers; the supplied image can replace draft exploration. Local edits remain focused on the user's request.
- Authoring checks, native preview and final collection must agree on supported asset admission. Known built-in asset-size, format, font-load and rendering failures provide safe, actionable diagnostics; a generic external error must not be treated as proof of a desktop connection failure. Check custom fonts on the first renderable draft before detailed typography. No silent font conversion or substitution is added.
- Native review and final saving are different observations. Collection follows the Agent's natural end, so the Agent reports what it has verified without waiting for or anticipating that turn's later save receipt. A partial result may still be collected under existing schema, asset and version rules; a visual limitation is not an application save gate. Never relabel a failed native review as successful because an external composition looks acceptable.
- Distinguish delivery assets from design references and choose layer granularity by independent editing value. Leave fidelity, completion, shadow/steam grouping and other open choices to the Agent, without exhaustive case rules or an asset-redraw approval process.
- Teach side-by-side, overlay, local-difference and light/dark-background comparisons that are executable with shipped tools: native render plus image reading, and the Node helper below. Guidance must not depend on Python or other runtimes absent from a user's machine. Human judgment establishes visual quality; pixel scores do not replace it.
- **Tool errors follow Pi's native behavior.** A failed or uncertain image call returns to the Agent as an ordinary tool error, and the Agent decides what to do next. The application adds no run stop, retry fence or retry of its own for tool errors. Restoring a crashed or restarted run still never replays an already-dispatched call; that is session recovery, not tool-error handling.
- **Auto-review permission mode.** Code execution is a core design capability. Pi design sessions offer an auto-review mode that judges risk by effect rather than command form: ordinary shell commands run freely inside an OS sandbox, actions that leave its boundary are judged by a classifier, and only its denials or failures prompt. The default mode keeps today's prompts. Community permission packages were evaluated (see the note).
- Reuse the embedded Agent, image tools, native rendering and save path. BentoDoc remains the single editable truth, with YAML for Agent authoring. Preserve the read-only, commit and version boundaries.

## Acceptance

1. **End-to-end usability run (primary):** after implementation, start one new design through Molly's native interface with the embedded Pi Agent, the configured OpenAI Image 2.5 connection and auto-review mode, giving only a plain brief without stage instructions. The Agent should read the Skill, use supplied design thinking and references first, actually research design-site visuals when the explicit exception does not apply, generate and select a draft, generate transparent layers, recompose them in `design.yaml` and inspect current native renders. Verify the application's subsequent save receipt. The user then independently edits a lower layer, saves, reopens and exports. Record the reference exception, if applicable, the observations informing design decisions, image calls, tool errors and how the Agent handled them, remaining permission prompts, elapsed time and visible deviations. Human judgment decides visual acceptance; a failed run is kept and reported, not relabelled.
2. **Interfaces and assets:** extend the existing MCP→request→asset-import tests with synthetic responses for parameters, source/mask data URLs, alpha and published assets; a synthetic provider error reaches the Agent as a tool error without ending the run. Script tests cover retained pixels, offsets, optional trims, comparison sheets and source preservation. Permission tests cover auto-approved and still-prompted calls. Test observable behavior only.
3. **Workflow and failure branches:** check a prescribed template without new inspiration, a reference that still requests a new composition, and a bounded edit preserving the prescribed artwork. The same research predicate governs each branch. Deterministic tests cover asset-limit diagnostics and consistent admission, font/render failure categories and packaged Skill material; actual Agent runs establish whether it follows the workflow. Distinguish a stale preview after an edit, failed native rendering, and a failed application save rather than claiming any of them completed.
4. **Evidence limits:** the earlier segmented MVP results support the plan but do not replace end-to-end acceptance. Do not claim general visual reliability from one run. Golden-replica experiments from the earlier phase are not acceptance for this task.

## Out of scope

Turn-length, token and cost optimization; automatic denoising or placement; dedicated comparison UI; classifier review of in-sandbox actions; other third-party permission extensions; new orchestration or storage; WebP and general codec expansion. Bento's fractional-scale crop rendering issue is tracked in [#15](https://github.com/LeonEthan/molly-design/issues/15), and Qwen/Seedream integration in [#16](https://github.com/LeonEthan/molly-design/issues/16); both remain separate follow-ups.

## Open questions

- The tested journey no longer presents the initial temporary-path and attachment-prompt blockers. Record any new domain or cache failures separately; this does not establish compatibility with arbitrary commands or destinations.
- `@anthropic-ai/sandbox-runtime` is a beta research preview and `pi-auto-approval` is an early single-author release (0.1.1); both are pinned, and upgrades need review.
- A classifier can be influenced by untrusted content the Agent reads (web pages, briefs); classifier approvals are limited to escalations. Preserve its verdicts in run evidence; the accepted run had no human prompts, without establishing classifier correctness for arbitrary content.
- With native tool errors, an uncertain image call may be repeated by the Agent and billed twice. Preserve unknown outcomes and record any subsequent Agent calls; the application adds no automatic paid retry.
