## 目标

用户输入设计需求或参考图后，Molly 内置 Agent 完成从意图理解到最终打磨的设计流程，交付可继续编辑、保存、重开和导出的分层作品。**先跑通端到端流程，再优化回合长度、Token 和成本。** 本任务的核心交付是一套完整可用的 Skill 方案。本轮以 OpenAI Image 2.5 为目标，使用用户配置的连接和明确指定的模型；其他图片模型的兼容后续再做，当前不限制连接设置。

本次获批修订要求 Agent 遵循 Skill 工作流，并优先采用用户的设计思考与参考。只有用户指定了具体模板或参考目标、要求沿用且无需新灵感，并且实际查看后的目标足以支撑本次工作时，才免除额外灵感调研。实现与验收状态见文末依据；早期失败运行仍保留在记录中，不改写为通过。

## 核心流程

1. **意图理解**：理解设计目的与用户的设计思考，组织内容、文案、素材及用户提供的参考。
2. **灵感与调研**：优先采用并查看用户的灵感与参考。进入构图选择或创作前，必须通过 Pinterest 等设计网站查看视觉内容；只有用户明确指定了具体模板或参考目标、要求沿用且无需额外灵感，实际查看后的目标足以支撑本次视觉决策，并且用户没有要求额外调研时，才适用豁免。题材、宽泛风格词、所给素材或 Agent 自己的构想不能单独构成豁免。遵守用户明确的联网限制并说明由此产生的局限；工具不可用不属于参考豁免。必要的事实核实另行处理。
3. **创意生成**：编写提示词，生成多份整图构图草稿，由 Agent 择优。
4. **图层拆解**：以选定草稿为参考，通过图片模型逐个重新生成完整元素，包括被遮挡部分。
5. **YAML 重组**：编写 `design.yaml`，将图层组合成可编辑作品。
6. **文字处理检查**：判断哪些文字采用可编辑文本，哪些适合保留为图片或矢量。
7. **整体审视与调整**：通过 Bento 渲染当前构图并实际读取返回图片，重新生成或编辑需要调整的图层。视觉修改后须再次原生预览；外部近似合成仅作辅助证据。
8. **一致性检查**：核对用户素材、文案和设计意图，使用图片模型或画稿编辑修正偏差。
9. **最终检查与打磨**：完善整体效果，如实说明已完成检查和剩余偏差，区分已准备的创作文件、已原生审视的当前草稿，以及由应用确认保存的作品。

开放需求执行全部九个阶段。用户指定模板或复刻时，已查看的参考承担选定构图的作用；局部修改以用户指定的现稿作为构图与图层基线。这些是明确的分支动作，不是宽泛的阶段豁免。各分支使用相同调研规则，保留未受影响的工作，并在修改后回到原生审视。

## 设计方式与职责

- 在现有设计 Skill 主入口写明必须遵循的工作流、分支条件与完成标准；专题参考在使用处提供具体方法。Agent 遵循步骤依赖与明确修复循环，在用户约束内选择方法和有用的迭代次数。删除任意省略或自由调整阶段顺序的宽泛许可；应用不增加阶段控制器或固定创作检查点。
- 事实文案依据用户提供或已核实的信息。[harness 环境上下文](molly-embedded-pi-harness.zh.md#职责与状态权威)提供当前时钟；文件修改时间不代表今天。用户未指定的活动公历日期，应明确目标年份并核实后添加，否则保留准确的概括表达或省略。
- 参考图复刻同样采用完整图层再生成，可直接以参考图代替草稿探索；局部修改围绕用户要求展开。
- 创作检查、原生预览与最终收集应对受支持素材采用一致的准入判断。对已知的内置素材大小、格式、字体加载和渲染错误提供安全且可指导修复的诊断；通用外部错误不能被当作桌面连接失败的证据。在精细排版前，利用首个可渲染草稿检查自定义字体。不增加静默字体转换或替换。
- 原生审视和最终保存是不同的观察。收集发生在 Agent 自然结束之后，因此 Agent 如实说明已经验证的事项，不等待或预先断言本轮稍后产生的保存回执。部分结果仍可按现有结构、素材与版本规则被收集；视觉限制不是应用保存门禁。不能因外部合成图看起来可接受就把原生审视失败改称成功。
- 区分交付素材与参考图，按独立编辑价值决定分层粒度。保真、补全、阴影与蒸汽如何分层等开放问题由 Agent 判断，不穷举固定规则，也不增加重绘素材申请流程。
- 提供并排、叠层、局部差异和明暗底色等对比经验，且须能用随包工具执行：原生渲染加读图，以及下文的 Node 辅助脚本。指引不得依赖 Python 等用户机器上可能缺失的运行时。视觉质量由人判断，不以像素分数替代。
- **工具错误沿用 Pi 原生行为。** 图片调用失败或结果未知时，作为普通工具错误返回 Agent，由 Agent 决定下一步。应用不为工具错误额外增加停止运行、重试栅栏或自行重试。崩溃或重启后恢复运行时仍不重放已发出的调用；这属于会话恢复，而非工具错误处理。
- **自动审批权限模式。** 代码能力是核心设计能力。Pi 设计会话提供自动审批模式，按实际效果而非命令形式判断风险：普通 shell 命令在操作系统沙箱内自由运行，越出沙箱边界的操作由分类器判断，只有其拒绝或失败时才提示。默认模式保持现有提示。社区权限扩展已评估（见记录）。
- 复用内置 Agent、图片工具、原生渲染和保存链路；BentoDoc 保持唯一可编辑真源，YAML 用于 Agent 创作。沿用现有只读、提交和版本边界。

## 实施任务

下表保留已完成的实施范围。获批的工作流 Skill 重写涵盖共享素材检查与安全诊断、入口及参考分工重写、随包材料验证及行为与人工验收。方案借鉴用户提供的邻仓演示文稿 Skill 的定义、分支、验证和交付组织方式，不引入其产品依赖。

## 验收

1. **端到端可用性实验（主要验收）**：实施后通过 Molly 原生界面新建设计，使用内置 Pi Agent、已配置的 OpenAI Image 2.5 连接和自动审批模式，只提供普通需求描述，不给分步指令。Agent 应读取 Skill，优先采用用户提供的设计思考与参考，不符合明确豁免时实际通过设计网站查看视觉内容，生成并选择草稿、生成透明图层、在 `design.yaml` 中重组并查看当前版本的原生渲染。核验应用随后产生的保存回执。之后由用户独立修改一个下层元素，保存、重开并导出。记录是否符合参考豁免、哪些观察支撑设计决策，以及图片调用次数、工具错误及 Agent 的处理方式、剩余权限提示、耗时和可见偏差。视觉验收由人判断；失败的运行保留并如实报告，不改标签。
2. **接口与素材**：扩展现有 MCP→请求→素材导入测试，用合成响应验证参数、原图/mask data URL、透明度和素材落盘；合成的服务端错误作为工具错误交给 Agent 且不终止运行。脚本测试覆盖保留像素、偏移、可选裁剪、对比图和源文件保留。权限测试覆盖自动批准与仍需提示的调用。只测试可观察行为。
3. **工作流与失败分支**：核验指定模板且无需新灵感、已有参考但要求新构图，以及保持指定现稿的局部编辑；各分支使用同一调研判据。确定性测试覆盖素材超限诊断与一致准入、字体/渲染失败分类及随包 Skill 内容；真实 Agent 运行用于确认是否遵循工作流。修改后过期的预览、原生渲染失败和应用保存失败应分别如实说明，不能宣称已完成。
4. **证据边界**：此前的分段 MVP 结果支持本方案，但不能替代端到端验收。不以一次运行宣称通用视觉可靠性。早期阶段的"黄金复刻"实验不作为本任务的验收。

## 暂不包含

回合长度、Token 与成本优化；自动去噪和自动定位；专用比较 UI；对沙箱内操作做分类器审批；其他第三方权限扩展；新的编排或存储系统；WebP 与通用图像编解码扩展。Bento 非整数缩放裁剪渲染问题见 [#15](https://github.com/LeonEthan/molly-design/issues/15)，Qwen/Seedream 接入见 [#16](https://github.com/LeonEthan/molly-design/issues/16)，均为独立后续工作。

## 待定问题

- 已测链路不再出现早期临时目录与附件审批阻断。之后发现的域名或缓存问题单独记录，不据此承诺任意命令或目标地址均可用。
- `@anthropic-ai/sandbox-runtime` 为 beta 研究预览版，`pi-auto-approval` 为早期单作者版本（0.1.1）；两者均锁定版本，升级需评审。
- 分类器可能受到 Agent 读取的不可信内容（网页、需求）影响；分类器批准仅限越界请求。运行证据保留其判断；本次通过运行没有人工提示，但不证明分类器能正确处理任意不可信内容。
- 工具错误沿用原生行为后，结果未知的图片调用可能被 Agent 重复发起并重复计费。保留未知结果并记录之后的 Agent 调用；应用不做自动付费重试。
