## 目标

用户输入设计需求或参考图后，Molly 内置 Agent 完成从意图理解到最终打磨的设计流程，交付可继续编辑、保存、重开和导出的分层作品。**先跑通端到端流程，再优化回合长度、Token 和成本。** 本任务的核心交付是一套完整可用的 Skill 方案。本轮以 OpenAI Image 2.5 为目标，使用用户配置的连接和明确指定的模型；其他图片模型的兼容后续再做，当前不限制连接设置。

本次获批修订要求 Agent 遵循 Skill 工作流，并优先采用用户的设计思考与参考。灵感调研用于确立方向，因此只有不确立新方向时才免除：用户指定了具体模板或参考目标、要求沿用且无需新灵感，并且实际查看后的目标足以支撑本次工作；或局部修改沿用现有方向。实现与验收状态见文末依据；早期失败运行仍保留在记录中，不改写为通过。

## 核心流程

1. **意图理解**：理解设计目的与用户的设计思考，包括作品所处的类别与必须传达的一条信息；组织内容、文案、素材及用户提供的参考。新设计或重新设计存在会改变方向的缺口时，若结构化提问工具可用，就一次性提问，并给出选项与推荐默认值；否则基于报告的假设继续。写下一句方向描述和二到四个方向词，作为后续阶段的工作标尺；它们不是用户审批步骤。
2. **灵感与调研**：优先采用并查看用户的灵感与参考。进入构图选择或创作前，必须以方向词为起点，通过 Pinterest 等设计网站并至少一个类别和当下设计信息流之外的来源查看视觉内容，调研为一次有界的检索。只有用户明确指定了具体模板或参考目标、要求沿用且无需额外灵感，实际查看后的目标足以支撑本次视觉决策，或局部修改沿用现有方向，并且用户没有要求额外调研时，才适用豁免。题材、宽泛风格词、所给素材或 Agent 自己的构想不能单独构成豁免。遵守用户明确的联网限制并说明由此产生的局限；工具不可用不属于参考豁免。必要的事实核实另行处理。
3. **创意生成**：保留少量参考，每份只贡献一种特质，而非其物体或版式；生成多份整图构图草稿，由 Agent 择优。草稿默认采用图加文：将原生元素搭建的构图草模渲染图及用户提供的交付素材作为编辑输入，并以提炼出的决定编写提示词。找到的参考图从不作为编辑输入。模型无法编辑时，草稿由文字生成，Agent 需说明。
4. **图层拆解**：以选定草稿为参考，通过图片模型逐个重新生成完整元素，包括被遮挡部分。
5. **YAML 重组**：编写 `design.yaml`，将图层组合成可编辑作品。
6. **文字处理检查**：判断哪些文字采用可编辑文本，哪些适合保留为图片或矢量。
7. **整体审视与调整**：通过 Bento 渲染当前构图并实际读取返回图片，重新生成或编辑需要调整的图层。视觉修改后须再次原生预览；外部近似合成仅作辅助证据。
8. **一致性检查**：核对用户素材、文案、设计意图，以及新方向下的方向词，使用图片模型或画稿编辑修正偏差。
9. **最终检查与打磨**：完善整体效果，回复篇幅与需求相称。不得声称未发生的检查、渲染或保存。始终说明未满足的要求、受阻步骤和剩余偏差；仅当差异对用户重要时，才区分已准备的创作文件、已原生审视的当前草稿和由应用确认保存的作品。

开放需求执行全部九个阶段。用户指定模板或复刻时，已查看的参考承担选定构图的作用；局部修改以用户指定的现稿作为构图与图层基线。这些是明确的分支动作，不是宽泛的阶段豁免。各分支使用相同调研规则，保留未受影响的工作，并在修改后回到原生审视。

## 设计方式与职责

- 在现有设计 Skill 主入口写明必须遵循的工作流、分支条件与完成标准；专题参考在使用处提供具体方法。Agent 遵循步骤依赖与明确修复循环，在用户约束内选择方法和有用的迭代次数。删除任意省略或自由调整阶段顺序的宽泛许可；应用不增加阶段控制器或固定创作检查点。
- 事实文案依据用户提供或已核实的信息。[harness 环境上下文](molly-embedded-pi-harness.zh.md#职责与状态权威)提供当前时钟；文件修改时间不代表今天。用户未指定的活动公历日期，应明确目标年份并核实后添加，否则保留准确的概括表达或省略。
- 参考图复刻同样采用完整图层再生成，可直接以参考图代替草稿探索；局部修改围绕用户要求展开。
- 创作检查、原生预览与最终收集应对受支持素材采用一致的准入判断。对已知的内置素材大小、格式、字体加载和渲染错误提供安全且可指导修复的诊断；通用外部错误不能被当作桌面连接失败的证据。在精细排版前，利用首个可渲染草稿检查自定义字体。不增加静默字体转换或替换。
- 原生审视和最终保存是不同的观察。收集发生在 Agent 自然结束之后，因此 Agent 如实说明已经验证的事项，不等待或预先断言本轮稍后产生的保存回执。部分结果仍可按现有结构、素材与版本规则被收集；视觉限制不是应用保存门禁。不能因外部合成图看起来可接受就把原生审视失败改称成功。
- 区分交付素材与参考图，按独立编辑价值决定分层粒度。保真、补全、阴影与蒸汽如何分层等开放问题由 Agent 判断，不穷举固定规则，也不增加重绘素材申请流程。Skill 可以推荐源自实际失败的可打破设计默认值（主体比例、边距、字号层级、文案位置及图上文字可读性），并将其作为审视清单，包括每个标志性视觉手法都与主题或信息相关；Agent 可以说明理由后偏离，应用不强制执行任何一项。
- 用户在后续回合否定方向时，Agent 先对照方向词判断：方向词仍成立，就重新诠释其视觉表达并说明改变了什么；不再成立，就回到意图理解，用一个问题询问用户不满意之处。
- 提供并排、叠层、局部差异和明暗底色等对比经验，且须能用随包工具执行：原生渲染加读图，以及下文的 Node 辅助脚本。指引不得依赖 Python 等用户机器上可能缺失的运行时。视觉质量由人判断，不以像素分数替代。
- **工具错误沿用 Pi 原生行为。** 图片调用失败或结果未知时，作为普通工具错误返回 Agent，由 Agent 决定下一步。应用不为工具错误额外增加停止运行、重试栅栏或自行重试。崩溃或重启后恢复运行时仍不重放已发出的调用；这属于会话恢复，而非工具错误处理。
- **不弹出权限提示。** 代码能力是核心设计能力。自 2026-10-01 起，内置 Molly 运行沿用 Pi 不做权限检查的默认行为，并以确定性的 `cc-safety-net` 底线不弹提示地拦截已知破坏性命令（[harness Spec](molly-embedded-pi-harness.zh.md)）。设计师无需选择权限模式；逐次询问模式保持退役（[#10](https://github.com/LeonEthan/molly-design/issues/10)）。先前的自动审批模式已被取代。
- 复用内置 Agent、图片工具、原生渲染和保存链路；BentoDoc 保持唯一可编辑真源，YAML 用于 Agent 创作。沿用现有只读、提交和版本边界。

## 验收

1. **端到端可用性实验（主要验收）**：实施后通过 Molly 原生界面新建设计，使用内置 Pi Agent、已配置的 OpenAI Image 2.5 连接且不弹出权限提示，只提供普通需求描述，不给分步指令。Agent 应读取 Skill，优先采用用户提供的设计思考与参考，不符合明确豁免时实际通过设计网站查看视觉内容，生成并选择草稿、生成透明图层、在 `design.yaml` 中重组并查看当前版本的原生渲染。核验应用随后产生的保存回执。之后由用户独立修改一个下层元素，保存、重开并导出。记录是否符合参考豁免、哪些观察支撑设计决策，以及图片调用次数、工具错误及 Agent 的处理方式、剩余权限提示、耗时和可见偏差。视觉验收由人判断；失败的运行保留并如实报告，不改标签。
2. **接口与素材**：扩展现有 MCP→请求→素材导入测试，用合成响应验证参数、原图/mask data URL、透明度和素材落盘；合成的服务端错误作为工具错误交给 Agent 且不终止运行。脚本测试覆盖保留像素、偏移、可选裁剪、对比图和源文件保留。只测试可观察行为。
3. **工作流与失败分支**：核验指定模板且无需新灵感、已有参考但要求新构图，以及保持指定现稿及其方向、无需灵感调研的局部编辑；各分支使用同一调研判据。确定性测试覆盖素材超限诊断与一致准入、字体/渲染失败分类及随包 Skill 内容；真实 Agent 运行用于确认是否遵循工作流。修改后过期的预览、原生渲染失败和应用保存失败应分别如实说明，不能宣称已完成。
4. **证据边界**：此前的分段 MVP 结果支持本方案，但不能替代端到端验收。不以一次运行宣称通用视觉可靠性。早期阶段的"黄金复刻"实验不作为本任务的验收。

## 暂不包含

回合长度、Token 与成本优化；自动去噪和自动定位；专用比较 UI；权限提示或对 Agent 操作的审查；新的编排或存储系统；WebP 与通用图像编解码扩展。Bento 非整数缩放裁剪渲染问题见 [#15](https://github.com/LeonEthan/molly-design/issues/15)，Qwen/Seedream 接入见 [#16](https://github.com/LeonEthan/molly-design/issues/16)，均为独立后续工作。

## 待定问题

- 已测链路不再出现早期临时目录与附件审批阻断。之后发现的域名或缓存问题单独记录，不据此承诺任意命令或目标地址均可用。
- 不做权限检查时，Agent 读取的不可信内容（网页、需求）可能引导其运行用户能运行的任何命令；`cc-safety-net` 只拦截已知破坏性模式。已通过的验收运行早于此变更，使用的是自动审批。
- 工具错误沿用原生行为后，结果未知的图片调用可能被 Agent 重复发起并重复计费。保留未知结果并记录之后的 Agent 调用；应用不做自动付费重试。
