## 使用场景

用户发起设计会话，输入需求并添加参考图，使用本机 Agent 生成可编辑的平面设计；随后通过选中元素对话或手工修改，保存、重开并导出图片。用户通过会话历史查找历史产出，不管理独立作品目录。正常创作不要求 Git 仓库、分支、终端命令或代码审查知识。

核心目标是将成熟的 Lody coding-agent 工作台经验与 Bento 可编辑设计能力结合，形成 Agent 自主使用的设计环境（agent-naive），复用现有工作范式。Agent 读写 YAML 画稿投影，不使用 PPTD。

静态单画布的编辑与渲染以已迁入并验证的 Bento 范围为上限，只做删减；必要的 Lody 接入适配和已经明确确认的自动回写、先读文件提醒 hook、文件实时预览按各自边界实施，不据此扩充产品。Agent 创作面是 Molly 自有的 YAML 投影，不以 PPTD 或外部 PPT 技能为现行格式合同，不提供 PPTD 互通。适用的第一性原理、复用与 Agent 自主性规则见根 [AGENTS.md](../AGENTS.md#design-principles-and-migration-scope)。

本文纳入 2026-09-11 已确认的范围收敛：Agent 自行处理文件冲突，删除候选工作流，图像工具同时支持生成与编辑且模型由用户必填。实施细节及真实接入仍待验证。已实现 P0 固定样稿、P1 手工编辑及 P2 Agent 设计闭环；阶段证据见文末，不表示新目标已实现或产品已获发布验收。

## 产品范围

- 本地单人桌面工作台；每个作品一个静态画布，项目可组织多个作品。
- 覆盖海报、封面、社交配图、横幅、信息图、长图和通用电商图片；场景知识放在技能和参考材料中。
- 保留 Molly 现有桌面架构、UI 设计语言、Agent 接入及本地会话能力；迁入 Bento 的文档、编辑和渲染能力。
- 整个迁移计划不包含独立素材库、跨作品素材浏览或复用，也不将其顺延至后续迁移阶段。保留当前画布的图片插入、替换、选中图片重新生成及文档所需素材持久化；回合参考图附件是独立需求。
- 首期交付 PNG/JPEG。多画板、演示文稿、视频、模板市场、云协作及其他专业格式不属于本草案。Agent 创作入口为单个 `design.yaml` 与本地 `media/`；尺寸、背景、字体和元素集中在该 YAML，不使用页面清单或独立页面文件。第一步保留 Bento 的 `id`/`kind` 及结构化 text/table/chart；不使用 `.pptd`，不发明 DSG 或其它新图形模型。
- 不提供通用逐轮结果卡、逐轮历史缩略图、侧栏作品缩略图或独立候选创建/采用/拒绝流程。普通回合状态、文件诊断和当前画稿入口复用会话能力；冲突保留草稿供 Agent 继续处理。Agent 的渲染预览与图片读取能力保留。
- 附件选择、粘贴/拖放、通用图片/文件预览、搜索/置顶/重命名、命令/快捷键和会话恢复复用 Lody 现有能力，不重复建设。参考图接入只补 Molly 本地组合与设计输入的差异；通用附件呈现不属于待删除的设计结果卡链路。

首页保留原有顶部与对话输入结构，尺寸选择位于输入框左下方、附件入口旁，不提供独立的新建设计按钮或名称输入。尺寸默认 Auto，不要求预填宽高；点击展开常用尺寸及具体像素宽高，最下方为自定义尺寸。自定义宽高在弹层内填写并校验，应用后一起生效，关闭弹层不改变已选尺寸。预设复用固定宽高语义；创建画布与首次持久任务输入使用同一次提交的尺寸，明确要求 Agent 按此宽高设计。Auto 不追加固定尺寸要求；后续用户仍可明确要求调整尺寸。输入内容并按回车时复用现有 Session 提交及自动命名流程，同时初始化空白单画布作品；Auto 在 P1 使用默认初始画布，后续可经 Agent 创作路径调整，尚不承诺 Agent 根据内容自动计算尺寸。创建失败保留输入草稿。提交沿用现有 Agent 配置要求，作品打开后的手工编辑不依赖 Agent 执行。

## 职责和持久化

第一阶段单文件字段合同为：`format: molly-canvas/1`、必填 `size`/`elements`、可选 `background`/`customFonts`/`diagnostics`/`title`。元素保留现有 `id`/`kind`/`bounds`，不采用类型区块。入口默认值、文件元数据与 canonical 的边界、显式旧 YAML 转换和测试门槛见第一阶段审核方案。该具体方案已通过本轮审核。

当前稿维护最新工作状态，设计会话记录讨论和执行过程，首期默认一个作品对应一个主会话。用户通过“存为版本”保留历史节点，Git 是唯一历史存储，不另建文件快照库或权威版本索引；自动保存及普通 Agent 回合不逐次创建历史版本。会话归档和删除沿用原项目语义，不新增删除普通 workspace 文件或设计历史的行为；删除会话记录不等于删除设计文件。既有 Git worktree 清理规则不因此获得删除版本存储的授权。

现有 CLI 后台继续负责 Agent 生命周期、权限回应、会话与回合。设计服务负责格式转换、结构校验、素材登记、版本校验及当前画稿保存；冲突时保留创作文件并返回可处理诊断。Electron 负责桌面资源、可信编辑器桥接、渲染进程与原生文件交互。设计服务不另建一套 Agent 调度、差异合并或聊天存储。

BentoDoc 是当前画稿的唯一权威状态（canonical）。画稿投影是从当前稿按需生成的 YAML 文件表示（单个 `design.yaml` 与本地 `media/`），供 Agent 读取；Agent 创作草稿是 Agent 正在修改的同一布局文件，经校验再提交为 BentoDoc。画稿投影与 Agent 创作草稿具有不同用途，不构成两个可独立提交的权威当前稿。不把 `design.json` 或 PPTD 当作 Agent 创作入口。预览图和导出图是派生产物。现有 Loro/Flock 保存会话及作品关联，本地 workspace 保存当前画稿与素材，不把两者变成可分别修改的重复画稿。

会话及产物身份是关联依据；当前稿并发保存的基线标识用于检测状态变化，与 Git 历史提交 ID 分开。会话元数据的写入或通知失败不得撤销已持久化的作品；重开时能根据已持久化的关联恢复，具体提交与修复机制在技术切片中确定。用户不应因通知迟到而重复生成同一作品。

## 编辑和 Agent 回合

P1 支持宽高各 1–4096 像素的单画布。任何调整画布尺寸的实现都必须保持元素位置和大小；若调整后有元素超出画布，拒绝该调整并说明阻塞元素，不自动缩放或裁切。2026-09-16 起，编辑器内手工调整画布尺寸的入口（页面设置面板）随画布 UI Lovart 化退役，画布尺寸经 Agent 创作路径创建与调整，见画布 Lovart UI 记录。

1. 同一作品采用串行编辑：派发前先阻止新增手工修改，完成通用 flush 和待完成保存，成功后固定当前稿基线、选区、参考材料与技能，再启动 Agent。保存或启动失败时保留输入/编辑内容，确认没有执行中的回合后恢复编辑。
2. 模型、权限和工具能力由当前 Agent 的真实能力决定；不伪造支持状态，不静默切换 Agent，也不代替用户回答权限请求。
3. Agent 自然完成后收集并校验产物；文件出现不代表完成，Agent 回合成功也不等于有效画稿已经提交。成功回合中可证明未改变、也没有本轮有效主动重提交事实的旧创作文件记录 no_artifact，不因它与当前画布不同而自动提升或提交。入口须为 `design.yaml`；遗留 `.pptd` 不是有效产物。保留文件与历史回执；明确重提交的边界见下节。
4. Agent 运行及其产物采集/提交处理期间，所属作品所有 Bento 实例禁止人工修改；其他作品不受影响。应用利用既有执行状态控制通用只读能力，并在人工变更/保存入口执行同一检查，不能只禁用按钮。最终提交仍原子核对基线，异常外部变化或陈旧请求报错并保留草稿，不覆盖新稿。
5. 普通修改与重新生成使用同一提交流程：产物有效且版本检查通过即保存当前稿，不根据提示词分类，也不额外等待采用。冲突交由 Agent 通过重读、比较和修改文件处理，应用不提供专用候选审批或设计语义合并。
6. 失败、取消、校验失败及未能提交如实反馈，执行状态复用既有会话显示；普通讨论或未产出设计不要求额外结果提示。终止后保留工作文件和原稿，用户显式继续时由 Agent 读取最新稿并处理草稿；重启或提交失败不自动发起模型调用。持久提交回执与历史事实不因 UI 退役而删除；已有候选内容保持可读，可作为普通文件供 Agent 处理，不新增候选工作流。
7. 元素引用携带作品、当前稿基线及稳定元素 ID；选区失效时明确提示，不猜测另一元素作为目标。首期在回合完成后引用当前稿继续修改，不扩展运行中引用临时预览的交互。
8. 只读覆盖等待工具/权限、取消处理中和结束后的采集/提交；正常完成、失败、取消均待执行与结果处理确认结束后恢复编辑。无有效产物则保留原稿。关闭标签或断开 UI 不解锁；重开先核对真实执行状态，状态未知时暂只读并显示恢复状态。延迟的结束事件不能解锁后续回合，同一作品的重叠派发沿用既有排队/拒绝机制。

2026-09-12 用户确认 Grok 的“停止”采用完整关闭语义：终止当前会话执行及其后台任务和子任务，保留会话记录、当前稿和工作文件。应用通过公开会话关闭能力确认执行已结束，并等待产物处理完成后才恢复画布编辑；关闭失败不得当作已停止。仅在用户发送下一条消息时沿既有恢复路径继续会话，不自动重启或重发被停止的回合。该语义修复已实现并经验证（见「依据与验证状态」节），不将原生 cancel 回执当作底层请求已关闭的证据。

## 当前画稿读取与文件一致性（P3 目标）

2026-09-12 修订目标为自动回写与读取提醒；既有读取同步/generation 证明实现需后续收敛，不能把旧验收当作本修订已实现。

- Bento 保持独立编辑/渲染，提供通用变更、snapshot/flush 和只读能力。人工编辑经 Molly 设计保存适配自动更新 BentoDoc、同版本 YAML 画稿投影与素材；不感知 Agent 生命周期，也不等待 Agent 主动同步。
- 复用已有自动保存、反向转换和投影发布。连续编辑可合并，flush 等待最后一次已完成编辑的文件结果；启动 Agent 只等待已有保存队列与文件就绪，不首次触发设计同步。创建和恢复等当前稿入口保持同一就绪条件。
- 当前稿已保存但画稿投影发布失败时保留人工结果，明确反馈并阻止使用陈旧投影开始创作；重开按当前稿版本核对/重建。逐个 rename 或防抖不代表跨文件原子性，旧任务不能覆盖新版本。
- BentoDoc → YAML 画稿投影 → BentoDoc 保持首期开放的编辑语义、稳定元素 ID、层级、样式和素材引用。单文件化首先保留 `id`/`kind` 及 Bento 结构化 text/table/chart；进一步类型区块重组须先通过完整往返与 Agent 可操作性验证，并明确批准其具体字段合同。不使用 PPTD 的 `elementId`/`elementType`、HTML 富文本、主题 `$ref` 或 `seriesDefaults`。对分组、多层阴影等做最小格式及双向适配；不静默丢弃或栅格化。不要求还原 YAML 排版、注释或别名。
- 保留通过公开 hook/extension 加载的先读提醒：修改已有文件前先读取当前内容；整文件覆盖前读完整内容；变化/冲突后重读调整；新文件不要求读取不存在的目标。续改作品还应读取最新当前稿，不能只依据历史记忆修改遗留草稿。复用原生文件工具的已有保护，不修改 runtime。
- 提醒是行为要求，不是执行证明。仅补上下文的 PreToolUse 不保证本次已生成写参数会等待 Read；记录实际事件、上下文送达和原生拒绝语义，不冒称五种 Agent 全路径强制先读。静态 skill 不能冒充已接通 hook。不新增统一读取台账或逐次模型生成证明。
- 当前稿投影与 Agent 草稿分离；自动保存、读取和恢复不覆盖未完成草稿，也不静默换其提交基线。应用投影不作为新产物采集，预览不反向保存，防止循环。
- 版本冲突通过普通工具反馈由 Agent 重读、比较和调整；明确重提交仍关联确切草稿与预期当前稿版本。仅重读或旧文件存在不自动升级为本轮产物。结束后才发现冲突则保留草稿/诊断，待显式继续，不自动重启。
- 正式提交独立校验结构、素材、来源与当前稿版本，保护未保存修改。移除旧 generation 读取证明依赖时同时调整最终采集；缺少提醒事件不直接否定有效产物，提醒送达不等于提交授权。按实际版本、启动方式和工具路径验证五种接入，不承诺 Shell/MCP 全局拦截。

设计建议和可选辅助工具放在 skill；应用只做结构校验和可观测结果分类，不强制工具调用次数、视觉自检轮数或固定完成流程。工具缺席不推断 Agent 自带能力缺席。正式导出继续采用固定 Bento 渲染路径。

[生成式分层设计任务](generative-layered-design-workflow.zh.md) 定义已批准的九步创作流程及其支撑改动，具体方法与创作取舍由 Agent 负责。

Agent 可调用已有 `molly_render_preview` 渲染 YAML 画稿投影，再用实际可用的图片读取工具查看并继续修改。应用不要求通过结果卡取图，也不把渲染成功等同模型已读取图片；预览工具缺席时，仅说明该能力不可用，不替 Agent 判定全部视觉 review 失败。可选 finalize 脚本不构成必经写入顺序或文件发布事务。

## 内置图像工具

Molly 内置 MCP 提供 generate 和 edit 两种能力，复用既有图像连接、会话权限、传输与 workspace 素材保存。用户配置 URL、Key 和必填 model；产品不设默认模型、不猜测模型别名或静默切换。已有用户配置保留其明确保存的值，空 model 不再自动补默认值。

- Generate 接收提示词生成图片；edit 接收提示词与一张或多张原图/参考图，可选 mask。默认接入协议为 OpenAI Images-compatible 的 generations/edits，不要求每个供应商都支持全部参数；实际不支持时如实报错，不自动改走文生图或重复付费调用。
- 工具结果保存为工作区素材，由 Agent 决定如何用于画稿投影；调用生图/编辑接口本身不提交或替换当前画稿。复用 Bento 已有裁切、替换及普通选区动作，不增加独立图像作业系统或 mask 编辑器。
- 附件输入、Agent 看图及 Bento 手工图片操作独立于图像服务，不因未配置 image MCP 而被禁用。五种 Agent 是否能取得实际图片输入分别验证。

## 唯一画布与实时构建

右侧只提供一个画布，不提供 Artwork / Preview 来源切换。空闲时显示并编辑所选版本衍生的活动工作稿；Agent 运行期间在原位置显示本轮最新有效的只读创作状态。实际文件变化触发受限快照采集、结构校验与 YAML → BentoDoc 转换；工具事件只作补充，不为五种 Agent 分别建立预览机制。该链路不参与 Agent 调度或完成判断。空闲时外部文件或遗留草稿不自动替换工作稿，也不保留独立预览入口。

- 仅为实际可见且需要实时构建的画布建立订阅，同一 workspace/入口的消费者共享监听与转换；最后一个消费者离开或断开后释放。无消费者的历史 workspace 不监听、不持续转换；后台回合仍沿用正式产物采集。
- 监听 `design.yaml` 和必要素材目录；为发现首次创建、rename 替换及缺失依赖，可非递归监听最近合法父目录并过滤。依赖改变时调整目标，不递归监听整个 workspace。建立订阅后核对初始文件，重开、恢复连接及有消费者的回合结束主动核对，补偿遗漏通知。遗留 `.pptd` 不是创作入口。
- 合并连续事件，按依赖集合与文件字节跳过重复转换；设置有限的等待和重采策略，避免持续写入造成无期限等待或忙重试。固定同次观测的文档与素材字节并复核稳定性后转换，不把防抖、逐文件读取或结构有效当成作者已完成多文件事务。有效的中间稿可以预览，不能据此认定产物完成。
- 转换/渲染按项目合并调度，结果绑定源摘要、作品和订阅代次；旧任务不得覆盖较新结果或更新已切换的视图。无效中间状态、暂缺素材和读取不稳定时保留上一份有效预览并如实报错，不能清空可编辑当前稿或把回合判失败。监听失败报告自动预览更新不可用，正式采集不受影响。
- 派发及首次有效改动前保持当前稿可见，首次作品保留空白画布；不能把上轮草稿当作本轮进展。显示任务绑定作品、编辑上下文、回合和源身份，重连/中途打开重新核对；旧任务不得覆盖新目标。运行及处理期间可观看、缩放和平移，禁止编辑、元素引用、导出、保存版本和切换版本。历史列表可打开但不可改变编辑目标。
- 更新待新画面、素材及实际容器布局就绪后，自动缩放并居中完整画布，再原位替换。首次加载、有效实时刷新、完成后重载和版本切换均适配窗口；容器尺寸变化重新适配。同一画面仅隐藏后重开保留手动缩放；选区改变、普通手工编辑及无效中间草稿不触发重置。有效文件落盘是实时粒度，不承诺逐 token 或展示每次写入。半写、缺素材等状态保留上一有效画面并提供简短等待状态及可查看诊断，不清空画布或静默修复。
- 回合完成后独立采集、校验和提交，成功且画布加载就绪后恢复编辑，无需采用确认。失败/取消/无提交时显示最新确认保存的当前稿并保留工作文件，普通 no_artifact 不作失败提示；不因曾预览成功而自动提交。已保存但投影/画布未就绪须单独报告并阻止陈旧编辑/派发，不自动重跑 Agent。
- 预览不推进当前稿版本、不改变 Agent 草稿基线、不触发保存或完成。应用产生的画稿投影、正式存储、预览缓存和导出文件不作为创作入口监听或 Agent 新产物收集，避免同步循环；不使用“忽略下一次事件”推断来源。预览只读并自动更新，不提供手动刷新或导入为当前稿入口；不新增作品目录导入产品，不提供遗留 `.pptd` 导入。

## 保存、恢复和导出

- 自动保存、切换作品、关闭标签和退出应用共享保存确认语义。失败必须可见，不能声称已保存；运行时与画稿保存采用各自真实状态。
- 切换作品、关闭标签或退出时保存失败，阻止该动作并保留未保存修改；用户可重试或明确放弃修改，不能静默丢稿。
- 手工保存仍核对版本，异常多窗口/外部修改导致基线过期时拒绝覆盖并保留本地内容。串行编辑取消正常人机并发场景，不以此证明所有冲突消失；Agent 文件冲突沿工具反馈和会话继续处理。
- 已实现的冲突另存暂保留为异常情况下的保稿手段，不再作为日常人机协同功能扩展。彻底移除前须明确非 Agent 并发修改的保稿出口；不能用只读按钮替代这一检查。另存仍只复制画稿和必需素材，不复制会话记录；失败保留修改。
- 意外崩溃或断电后恢复最后成功保存的画稿及素材；仍处于待保存或保存中状态的修改可能丢失。P1 不承诺崩溃恢复未确认保存的草稿，正常离开动作仍执行保存保护。
- 历史版本采用下节的 Git 存储；不迁入相邻项目完整修订库，也不自建平行快照后端。编辑器撤销/重做与人工保存的历史节点分开。
- 作品标签仍打开时，普通作品/面板切换保留编辑器撤销/重做状态；历史版本切换重建撤销和选区，不跨版本撤销。关闭标签或重启后不保留撤销历史，已保存当前画稿不受影响。
- 正式导出基于已保存的当前画稿，使用固定编辑器渲染路径、字体和素材。导出前处理当前未保存修改，不能悄悄导出旧稿。
- PNG 保留透明度；JPEG 透明区域填白。像素尺寸按画布实际尺寸输出；缩放仅影响界面显示。
- 无效文档、缺失素材、字体或渲染失败须报错，不用占位图或窗口截图冒充成功导出。
- 首期不提供作品目录管理或相邻项目作品目录导入功能；旧程序数据保持原状。

## 设计版本

- 画布右上角提供独立“保存版本”按钮及历史按钮。自动保存维护一个活动工作稿；保存版本先等待已完成编辑落盘，捕获一致文档和确切素材/字体，成功保存并绑定后显示新基准。按稳定 V1、V2 等编号及时间展示，不强制命名；已有基准且无内容变化时不重复创建节点。独立“另存作品”仍创建新作品。
- 历史项直接切换编辑起点，无只读查看/“从此编辑”中间步骤。切换前先 flush 所有实例，当前内容尚无历史快照时在同一 Git 后端保留可选回的“切换前”版本；保护失败不切换。选回当前基准也恢复该版本原内容并保护修改；同内容且同基准则不操作。
- 已保存版本不可变，工作稿可持续编辑；未修改显示 V1，偏离后显示“基于 V1 · 有新修改”，首次无基准显示“当前稿”。人和 Agent 串行修改同一工作稿，派发读取包含最新人工修改的内容，而非仅取基准快照。从 V1 续改存为 V4 记录来源 V1，V2/V3 保留；不引入命名分支、各分支独立工作稿、合并或专用缩略图。
- Git 追加顺序与设计来源分开，版本列表和来源从同一 Git 后端读取，不另存权威历史索引；旧版本来源未知时不猜测。活动基准随当前稿持久化封套原子保存，不进入 BentoDoc/YAML，重启恢复选择及工作稿。历史发布先于基准绑定，部分成功如实报告，重试不重复建节点或覆盖后续编辑。
- 切换经结构/素材校验及覆盖编辑上下文的原子版本检查，只影响所属作品；更新 Agent 可读当前投影，保留草稿、回执、聊天及无关文件，不自动重置旧草稿提交基线。所有实例同步新上下文、撤销和选区；加载/投影失败与落盘成功分开报告，未就绪时不得用陈旧内容编辑或派发。
- 执行、准备及产物处理期间禁止保存和切换版本；可打开历史列表但不另切观看目标。停止也需等待实际执行与处理结束。跨窗口和迟到请求沿用作品变更检查，不能仅禁用按钮；切换不自动停止、重启或调用 Agent。
- Git 只承担历史内容存储；当前稿自动保存、画稿投影转换、完整文件发布、冲突检查和草稿保护继续由设计服务负责。Git commit 不能证明多文件输入来自同一编辑版本。必要临时文件不作为第二个持久历史库。
- Git 历史为本地能力，不要求 GitHub、远程仓库、push 或额外 Agent 回合。由 Molly 管理独立本地 Git 仓库，支持普通非 Git 项目创作并隔离用户分支、暂存区和无关内容，不能直接用项目级 reset/checkout 实现画稿恢复。

## 工作台与边界

保留侧栏、标签页和对话输入结构；默认对话与较大画布并排，提供专注画布模式。图层和属性按需展开，图片操作随当前画布选区呈现，窄窗口切换视图时保留编辑状态。去掉幻灯片、演示及其他不支持的编辑器入口。

选中元素后，属性栏在选区附近悬浮，保留现有类型控件及引用/图片/样式动作；按钮大小不随画稿缩放，工具栏和弹层避让可视边界。拖动时隐藏、结束后重新定位；无选区、只读及运行中派生画面不显示可编辑栏。从历史版本切换得到的就绪工作稿正常支持编辑栏。此项不改变单画布文档范围。验收必须包含真实 Electron 窗口中七类元素的浅色/深色选中截图及逐图视觉评估，视觉判断独立于自动化功能通过。

单选带矩形选框的可编辑元素（图片、文本、形状、图标、表格和图表）时，选框底部显示元素框的实际宽 × 高；拖拽调整期间实时更新，以画布像素计，不随视图缩放改变读数。尺寸标注不拦截操作，使用端点编辑的线条及多选不显示该标注。选框四角保留圆点，四边中点使用沿边方向的细长胶囊，保持既有拖拽命中范围。

布局、设置、命令与 onboarding 沿用现有框架；P1 已有专注画布入口，后续验证其与预览/只读的衔接，不重做；Lody 当前 Zen 隐藏右侧面板，不能直接作为替代。复用现有 Agent 引导与本地能力裁剪，仅将代码任务示例改成设计，不增加必经配置页面。图像连接已经在 P2 接入，后续整理入口；没有具体需求时不新增保存设置。

Git 分支操作、PR/CI 等开发功能退出设计主流程，并停止其不再需要的后台工作；设计版本历史是 Git 的新消费者，保留其必要基础能力，不复用自动提示 Agent commit/push 的流程。共享基础设施只在确认没有消费者后删除。终端、参考网页浏览、会话分叉按实际消费者逐项决定；通用文件、进程、工具、诊断、权限和恢复能力继续复用。新应用身份与数据目录须与现有 Lody 和相邻程序隔离。

### 内置网页调研与素材

首期交付让设计会话的 Agent 在用户可见的 Molly 内置浏览器中使用 Pinterest 账号搜索素材、浏览详情并保存选定图片；设置只提供 Pinterest 的 Chrome 账号导入。Amazon 搜索、商品详情与网页问答转为后续范围，不作为首期完成条件。浏览工具只操作当前会话获准的内置页面；来源 Chrome 仅在用户主动选择时向 Molly 导入指定网站的登录状态，不作为 Agent 的浏览目标。Molly 独立持有网站 profile；导入成功以网站在内置页实际识别账号为准，Cookie 写入或用户在内置页手工登录均不证明 Chrome 账号已复用。

首次需要网站账号时，浏览器侧栏可按站点引导至 Molly 的网站账号设置，或由用户在 Molly 页面登录；无需预先完成必经设置。用户在 Molly 内选择来源 Chrome 用户配置和支持的网站并发起导入，必要时处理 macOS 的系统授权，不要求进入 Chrome 开发者模式、手工安装扩展或复制配对码。设置中管理导入与清理，导入期间明确提示系统授权与等待；读取超时后由用户处理系统弹框并手动重试，不自动重试，读取失败保留 Molly 原有 Cookie。Cookie 数量只说明本机数据状态，不代表网站已登录。未支持导入的站点仍可由用户在内置页登录；这不扩展 Agent 可操作的浏览器范围。

用户授权按当前任务的站点和工具范围生效，完成、取消、页面关闭或人工接管后撤销。跨出获准顶层站点先暂停并请求扩大范围；同一页面不向第二个 Agent 任务开放实时观察。人工接管及登录/MFA 期间停止 Agent 读取和操作；恢复须重新观察，不能重放此前未知结果的动作。浏览授权不自动包含账号导入、发布、购买或修改账户的意图；普通点击和输入不被标为天然只读。现有 Agent 执行和产物处理期间的画布只读规则继续适用。

Agent 选定的网页图片经持有网站 session 的受控字节获取和现有设计资产路径进入作品；首期仅接纳通过解码验证的 PNG/JPEG/GIF 输入，其他格式明确报告不支持，页面只提供下载的流程不支持。素材结果记录来源并不自动提交画布。网站登录限制、反自动化和目标地区功能可用性按实际验证披露，不承诺任意 Chrome profile、网站或账号可无条件迁移；浏览器、登录与素材网络路径均须限制 Agent 可读取的本机及私网目标。完整技术取舍和分步验收见浏览器方案。

遵循 [平台边界](../packages/platform/AGENTS.md) 和 [共享协议合同](../packages/shared/AGENTS.md)：不引入认证产品云请求或遥测。用户选择的 Agent 及图像服务仍可能访问外部模型，本地优先不等于离线生成；凭据不进入画稿、Role 或日志。没有 Agent 或图像服务时，已有作品仍可编辑、保存和导出。
