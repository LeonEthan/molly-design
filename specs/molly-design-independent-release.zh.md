## 2026-09-17 命名统一修订提案（待审核）

目标拼写已确认为 `Molly` / `molly`。已实施的命名统一决定建议将当前产品展示名收敛为 Molly，并将自有包、代码标识、环境变量及新写入格式/路径统一为 molly 命名。若采用本修订，下文“内部名称逐项裁定”按该提案细化，“不全面重命名内部包”的排除项调整为：自有内部包纳入，外部协议和来源不纳入。

旧作品、附件、草稿、设置和会话须保留兼容读取；新写入使用新名称。真实上游署名、第三方 ACP 协议与历史证据保留原名；已有 Molly 安装标识、数据位置、仓库和更新频道不因缩短展示名再次更换。具体读回、冲突处理、切片和验收见提案。

此节为待审核修订，下面正文保留此前首发范围供对照，不将旧承诺静默改写。现行设计规格的 `geon-canvas/1` 合同尚未变更；采用新格式前须修订受影响的中英文规格并重新批准。本轮只提出方案，没有实施、公开发布或整份规格批准。

## Problem Statement

用户希望将 Molly 作为独立的平面设计桌面应用发布。现有版本已具有独立的主要安装身份和数据目录，但图标、首次引导演出、部分文案、后台运行痕迹及发布配置仍保留明显的 Lody 产品身份。用户也不需要独立 CLI 产品，不能为了使用设计工作台而安装或操作命令行工具。

仅替换首页名称无法完成独立化：首次体验、错误提示、公共运行时下载、应用更新和发布页同样会影响用户对产品归属的判断。粗暴替换所有 Lody 字符又可能破坏已有 Molly 数据、依赖协议及准确的开源署名。

## Solution

Molly 以自己的品牌、支持入口、资源分发及应用内自动更新能力独立发行。首发沿用 macOS arm64 支持范围；品牌、引导、对外接口、分发与支持入口独立化均为首发前置条件。

重新制作 Logo、图标、首次引导动画、音乐与操作音效，统一采用“纸张与版式：克制、精致的设计工作台”方向。首次开场自动播放音乐，提供静音和跳过，之后启动不自动重播。用户通过桌面应用完成配置、创作和更新；不提供独立 CLI 产品。

Molly 与 Lody 独立安装，不读取或迁移 Lody 数据，同时保护已有 Molly 数据。内部兼容名称逐项裁定，保留准确的许可证、作者和上游来源；README 可以集中说明开源来源。

## User Stories

1. 作为新用户，我希望安装包和应用均明确名为 Molly，以便确认安装的是独立产品。
2. 作为用户，我希望 Dock、窗口、安装器及应用内使用一致的新图标，以便辨认 Molly。
3. 作为用户，我希望 Logo 在小尺寸、深色和浅色背景下清晰，以便日常使用时快速识别。
4. 作为新用户，我希望开场围绕纸张、版式和设计创作展开，以便理解产品用途。
5. 作为新用户，我希望看到为 Molly 制作的动画和设计作品，以便获得独立的品牌体验。四幕分别展示海报、编辑出版、品牌视觉和电商商品详情页（如亚马逊 A+ 图），每幕使用不同图片与呼应的文字。作品具有多样的配色、字体、图像与构图，通过统一的开场框架，形成从单幅表达、内容编排、视觉系统到商业产品叙事的递进。
6. 作为新用户，我希望首次开场自动播放 Molly 音乐，以便完整体验动画与配乐。
7. 作为用户，我希望随时静音，以便在不适合播放声音的环境中使用。
8. 作为用户，我希望立即跳过开场，以便直接进入必要配置和创作。
9. 作为偏好减少动态效果的用户，我希望仍能顺利进入应用，以便无需观看完整动画。
10. 作为回访用户，我希望开场不自动重播，以便快速恢复工作。
11. 作为用户，我希望离开引导后音乐停止，以便不受残留声音干扰。
12. 作为新用户，我希望引导示例是设计作品而非代码任务，以便开始第一个作品。
13. 作为用户，我希望继续使用现有 Agent 配置与作品创建流程，以便品牌更换不增加必经步骤。
14. 作为用户，我希望菜单、设置、通知和加载状态统一使用 Molly，以便产品身份保持一致。
15. 作为遇到问题的用户，我希望崩溃、恢复和安装等待报告也明确属于 Molly，以便正确寻求支持。
16. 作为中文或英文用户，我希望两个语言版本中的产品名称和说明一致，以便不遇到旧品牌误导。
17. 作为使用辅助技术的用户，我希望图标标签和引导控制准确可操作，以便独立使用应用。
18. 作为用户，我希望帮助、反馈和更新说明指向 Molly，以便找到对应产品的信息。
19. 作为用户，我希望可达的分享产物和二维码不宣传 Lody，以便分享内容与当前产品一致。
20. 作为设计者，我希望普通设计导出不新增品牌水印，以便保留作品内容。
21. 作为桌面用户，我希望无需安装或操作独立 CLI，以便全部日常操作在 Molly 中完成。
22. 作为桌面用户，我希望内部 Agent 执行能力继续正常工作，以便删除 CLI 产品入口不影响创作。
23. 作为同时安装 Molly 和 Lody 的用户，我希望两者不争抢协议、进程状态或数据，以便独立使用。
24. 作为已有 Molly 用户，我希望更新后仍可读取作品、附件、草稿、设置和设计会话，以便继续工作。
25. 作为用户，我希望 Molly 不读取或迁移 Lody 数据，以便产品数据边界明确。
26. 作为新用户，我希望 Agent 安装资源来自 Molly 控制的分发地址，以便安装服务归属与产品一致。
27. 作为用户，我希望资源下载失败或校验不通过时获得准确反馈，以便恢复安装而非使用损坏资源。
28. 作为用户，我希望在 Molly 内获得并安装新版本，以便不用手动寻找替代安装包。
29. 作为用户，我希望更新只接受适用于 Molly 和当前平台的可信制品，以便不会安装其他产品或损坏版本。
30. 作为正在创作的用户，我希望更新不丢失编辑或打断执行中的 Agent，以便保留工作成果。
31. 作为更新失败的用户，我希望已有应用和数据保持可用，以便稍后重新尝试。
32. 作为下载者，我希望发布页、安装包和校验文件统一属于 Molly，以便核对版本和来源。
33. 作为开源用户，我希望能查阅准确的上游来源和素材归属，以便理解产品的开源基础。
34. 作为维护者，我希望内部保留的兼容名称有明确理由，以便后续修改不破坏协议和旧数据。

## Implementation Decisions

- **品牌边界**：用户可见产品身份全面使用 Molly；内部包名、协议和历史记录不采用全局字符串替换。正常、失败及恢复入口均纳入范围。
- **视觉与声音**：制作 Molly 自身的 Logo、字标及平台图标，覆盖实际打包和应用内消费者。重做引导分镜、插画、音乐与操作音；当前配乐为代码合成，不能将工作误解为仅替换音频文件。具体图形、旋律和时长由后续素材设计确定。
- **引导集成**：复用现有首次引导状态、Agent 配置和首个作品创建能力，不新增必经配置页。保留跳过、静音和减少动态效果；首次自动播放，退出停止，后续启动不自动重播。平台阻止自动播放时提供明确的开启入口，不阻塞使用。
- **CLI 删减**：取消独立 CLI 发行、安装说明和用户产品入口，不另行建立 Molly CLI。保留桌面依赖的 Agent 执行、本地服务和内部启动机制；不把目录名为 CLI 等同于可直接删除全部实现。
- **身份与数据**：沿用已经独立的应用身份、协议和主要数据根。排查硬编码旧路径、附件目录、自动启动参数及新写入身份。对已由 Molly 产生但沿用旧名称的数据，依据真实归属保留兼容读回或安全迁移；不能扫描、导入或覆盖 Lody 用户数据。
- **资源分发**：Agent 公共运行时由 Molly 控制地址和发布，沿用版本化资源与完整性校验。允许继续复用真实上游适配器，不复制或擅改其版本协议。具体托管供应商和域名不在本规格中指定。
- **自动更新**：首版提供应用内自动更新，复用现有桌面更新服务和平台桥接，建立 Molly 的更新元数据、制品验证及发布链路。当前本地版禁用更新的策略需要显式修订，不能只更换 feed 地址或无条件打开继承渠道。
- **更新保护**：更新必须核对产品、版本、平台和制品完整性/可信身份；错误来源或无效制品不可安装。安装或重启前确保人工编辑已保存且 Agent 执行与产物处理结束；未满足时延后安装。失败应保留原有可用应用和用户数据，避免静默重启或破坏已有工作。
- **公开入口与发布**：整理 Release 标题、artifact 名称、安装器元数据、维护者信息、帮助、反馈和产品文档；去除遗留 Lody 产品更新源。明确区分当前 workflow 的实际发布仓库与基础配置残留。
- **范围清理**：分享卡、云端页面及遗留引导组件先核对本地可达性；无消费者的旧品牌资源可移除，不为不存在的入口另造功能。
- **来源归属**：保留准确的 LICENSE、适用署名、依赖来源和历史作者；记录新素材来源。产品发布者信息使用实际 Molly 发布身份，不能借品牌改名改写历史作者。
- **合同同步**：实施时更新受影响的 CLI 产品定位、平台下载/更新及公开边界规则。自动更新和公共资源下载不授权产品云登录、遥测或其他托管业务。任何受影响的已批准 Spec 行为修订须回到 draft，保留此前批准范围和历史事实。

## Testing Decisions

- **主要验收边界**：以最终 macOS arm64 安装包和用户操作为主，复用现有 Electron harness、首次引导页面驱动、隔离用户配置及设计旅程。沿同一安装包边界覆盖全新启动、开场、Agent 设置、首个作品、人工编辑、保存、重开和导出；不为品牌修改新增平行测试框架。
- **升级场景**：以两个可区分的 Molly 版本，经应用内更新完成一次真实安装和重开，验证作品、素材、附件、设置和设计会话保留。使用隔离且受控的测试更新源，不发布测试版本给普通用户。
- **异常更新**：复用现有 Sparkle 策略、事件和打包校验测试边界，使用确定性的事件和本地合成制品验证不可用更新、下载失败、校验失败、错误产品/平台、执行中延后安装及失败后数据保留。只有安装包旅程难以可靠制造的失败才下沉至这些既有边界。
- **隔离与兼容**：测试 Molly 与 Lody 并存不抢占协议和存储；使用合成旧 Molly 数据验证沿用旧命名路径的附件和草稿可读。用明确标记的另一产品数据证明不会被扫描或迁移。
- **声音与无障碍**：验证首次自动播放、静音、跳过、退出后停止、再次启动不重播以及自动播放被拒绝时的入口；检查键盘与减少动态效果。听感和动画质量由人工判断，DOM 或静态资源存在不代表体验通过。
- **品牌验收**：人工核验系统图标、安装器、引导、深浅主题、小尺寸、中文和英文以及失败弹窗；静态扫描只用于发现遗漏，不以全库零 Lody 命中为通过条件。可达分享和帮助入口按实际消费者检查。
- **分发验收**：受控资源服务覆盖成功、网络失败和完整性失败；最终另核验 Molly 公共资源发布链路的实际可用性。自动化单元测试不依赖公网、真实等待或调度运气，使用注入时钟、合成素材和显式状态。
- **测试质量**：断言用户可观察结果、数据读回和明确失败，不断言 mock 调用次数或简单复述实现。既有自动保存、串行编辑、提交、导出及恢复旅程作为回归依据；品牌与新更新验收不能用旧包结果替代。
- **交付检查**：完成变更对应的类型、静态、测试、格式、文档与公开边界检查；记录测试制品身份和证据限制。自动化结果不替代视觉/听觉判断，也不代表取得发布授权。

## Out of Scope

- 独立 CLI 产品，以及将整个后台执行模块删除或重写。
- Lody 用户数据导入或自动迁移；改写上游 Git 历史、作者、许可和第三方协议。
- 全面重命名所有内部包、外部协议或源码中每个 Lody 字符。
- 重新设计 Agent 生命周期、Bento 编辑器、设计持久化和已验收的创作合同。
- 新增产品云、账号、计费、遥测、移动端或 Web 产品。
- 将 Windows/Linux 或 macOS Intel 扩入首发实机支持范围。
- 新建完整营销网站、购买域名、开通付费托管、购买发布证书或公开发布应用；这些动作没有由本次规格发布请求授权。

## Further Notes

本规格综合已经确定的产品选择，并授权将规格发布到 Issue tracker；不构成运行时实施完成、整份本地 Spec 获批或应用公开发布授权。Issue 使用 `ready-for-agent`，本地文档保持 draft，后续实施记录保持与实际证据一致。

Developer ID 签名和 macOS 公证仍是建议的发布准备，未被本轮单独确认为已具备或已完成；实施者须列明所需发布者身份、证书和账号。更新制品可信验证是本规格要求，不能用校验文件存在替代可信发布者验证。最终视觉素材、托管位置和发布凭据未被虚构为已确定方案。

本规格在 T26 品牌与帮助范围、T23 首次设计引导范围及 T29 验收记录之外增加独立品牌和自动更新要求；旧验收不自动覆盖新增范围。既有主数据隔离已经实现，但少数旧路径仍须核查；继承更新地址存在不证明当前本地应用发生跨产品更新。

设计行为沿用[设计平台规格](graphic-design-platform.zh.md)。源码依据、旧决定关系和本轮进展由独立发布提案记录。关联 Issue：[T26](https://github.com/LeonEthan/molly-design/issues/28)、[T29](https://github.com/LeonEthan/molly-design/issues/31)。本轮仅完成文档与 tracker 操作，未运行新安装包验收。

## 2026-09-20 仓库收敛实施

首发继续限定 macOS arm64；正式发布工作流已收敛为该目标，其他平台保留本地实验构建，
不作为正式支持承诺。默认工作区只初始化 ACP core、DSH 能力合同与 Bento；DSH 仍有
共享层消费者，暂不删除。旧适配器与 Lody 网站保留来源记录，但退出默认依赖安装和检查。
独立贡献入口、来源授权与维护边界见实施记录。

这些仓库修改不构成公开发布、签名、公证、真实升级验收或本 Spec 的整份批准。
